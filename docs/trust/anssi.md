# ANSSI's recommendations for generative AI

How Jean answers each of the 35 recommendations in ANSSI's *Recommandations de sécurité pour un système d'IA générative* (ANSSI-PA-102, version 1.0 of 29 April 2024, under the Licence Ouverte 2.0, [ANSSI's page](https://messervices.cyber.gouv.fr/guides/recommandations-de-securite-pour-un-systeme-dia-generative)), for a security team that checks AI systems against it. Checked against the code on 19 October 2026.

The guide follows an AI system through three phases: training a model, deploying it, running it. An organisation deploying Jean trains no model: it serves Jean, picks a brain (its own servers, a provider behind its gateway, or the brain on the device) and decides what is connected. So each row says:

- **For a deployment:** whether the recommendation falls on an organisation deploying Jean: *Yes*, *Partly*, or *No*, with whom it falls on instead.
- **Jean:** what the code does, with the file or decision that does it. **Organisation:** what is left to whoever deploys it. **Not yet:** what Jean doesn't do, said plainly.

The [threat model](threat-model.md) has the detail behind each answer.

## General

| # | Recommendation | For a deployment | What answers it |
|---|---|---|---|
| R1 | Build security into every phase of an AI system's life cycle<br>*Intégrer la sécurité dans toutes les phases du cycle de vie d’un système d’IA* | Yes, without the training phase | **Jean:** the threat model names each boundary and what holds it, and changes with it; every change runs the pipeline in [README.md](README.md#checked-by-every-pipeline). **Organisation:** its own measures for hosting and running Jean, with ANSSI's hygiene guide as their base; training is the brain's provider's. |
| R2 | Analyse an AI system's risks before training it<br>*Mener une analyse de risque sur les systèmes d’IA avant la phase d’entraînement* | Yes, before deploying | **Jean:** the [threat model](threat-model.md) and the [DPIA template](dpia.md) give an analysis such as EBIOS RM its inputs: what Jean protects, which parts hold the organisation's data (the tab, the brain, the gateway, connected services, the share host), who answers for each, and what is left. **Organisation:** the analysis, with its brain and its connections. |
| R3 | Assess how far to trust the external libraries and modules the system uses<br>*Évaluer le niveau de confiance des bibliothèques et modules externes utilisés dans le système d’IA* | Yes | **Jean:** three libraries load upfront, the rest inside the capability that needs them, each added with a decision; versions pinned by `package-lock.json` and served from `app/vendor/`, never a CDN; each pipeline runs `npm audit signatures` and `npm audit --audit-level=high` and keeps a CycloneDX bill of materials, as each release does ([releases.md](releases.md)). Extensions run in frames of their own, and `capabilities.deny` turns them off (D296). **Organisation:** reading the bill of materials. |
| R4 | Assess how far to trust the external data sources the system uses<br>*Évaluer le niveau de confiance des sources de données externes utilisées dans le système d’IA* | Yes | **Jean:** whatever a page, a file, a mail, a skill or a shared task says, the same rules hold what Jean does next (R9, R27); a skill keeps its source and digest (`core/skills.js`, D121). Policy keeps skills to the organisation's sources (`skills.sources`, `skills.only`) and names the services people may connect (`connections`, `directory`). **Organisation:** which sources and services to allow. |
| R5 | Apply DevSecOps principles in every phase of the project<br>*Appliquer les principes de DevSecOps sur l’ensemble des phases du projet* | Yes, for Warehouse SAS | **Jean:** each change runs strict types (`tsc --noEmit`), the unit tests, a smoke test of every capability in Chromium and WebKit, every page's policy by the browsers' own reports (D326) and the packages' audit (`.gitlab-ci.yml`, `.github/workflows/ci.yml`); a deploy or release is built from a commit, never a working tree (D320); releases and version tags are signed, the key kept outside the repository (D419). **Not yet:** no static or dynamic security analysis tool (SAST, DAST) in the pipeline. |
| R6 | Use secure formats for AI models<br>*Utiliser des formats de modèles d’IA sécurisés* | Yes, for models on the device | **Jean:** models on the device are ONNX graphs and their weights, run by ONNX Runtime in a worker (`caps/brain-local/`, `caps/reflexes/`, `caps/pictures/`), or weights read by dictation's WebAssembly engine (`caps/voice/whistle.js`); none in a format that runs code as it loads, such as pickle. **Organisation:** the formats of the brain its servers or provider run. |
| R7 | Consider data confidentiality from the system's design<br>*Prendre en compte les enjeux de confidentialité des données dès la conception du système d’IA* | Yes | **Jean:** what people write, give and make stays on their device, each file sealed with AES-256-GCM (D371, [encryption.md](../encryption.md)); it leaves only for the brain that answers, the services connected, the sites opened and a share host that can't read its copies ([Where your files go](../../app/files.html)); a project set to Keep on this device uses only brains on the device or a server on this computer (`ui/send.js`, D269). Nothing people do trains a model: what Jean remembers is lines in a file the person reads and edits (`core/memory.js`). **Organisation:** the [DPIA](dpia.md); its brain's contract (no training, retention, region). |
| R8 | Consider need-to-know from the system's design<br>*Prendre en compte la problématique de besoin d’en connaître dès la conception du système d’IA* | Yes | **Jean:** there is no shared corpus or index: each person's Jean holds what they gave it, on their device, and reaches a connected service with their own sign-in, so it sees there what they may see (D89, D194); profiles share nothing (D228). **Organisation:** the rights its services grant each person; what the brain was trained on is its provider's. |
| R9 | Never let an AI system carry out critical actions on the information system automatically<br>*Proscrire l’usage automatisé de systèmes d’IA pour des actions critiques sur le SI* | Yes | **Jean:** by default Jean only reads and writes its own files, searches (its files, the person's folders, the sources built in such as Wikipedia) and runs code in its sandbox; sending, sharing, deleting, reading a page, any connected service's call and anything else external ask first, before each call, a script's nested calls included (`core/rules.js`, `core/loop.js`, D48); passwords and payments are Never, and nothing loosens them (D293). On the person's computer, each command is asked first unless they always allowed that folder (`caps/machine/machine.js`), and a change in their folder is asked with its diff (D141). **Organisation:** locking rules (`rules`), guards that make chosen calls ask first or never (`guards`, D295), `capabilities.deny`. A person may choose Always allow for a kind of action policy hasn't locked. |
| R10 | Control and secure developers' and administrators' privileged access<br>*Maîtriser et sécuriser les accès à privilèges des développeurs et des administrateurs sur le système d’IA* | Yes | **Jean:** there is no administration console or server: what an administrator sets is the site's files, its `policy.json` and its headers; `policy.html` at the site's address shows what its policy holds (D415). **Organisation:** who may change the site, its policy, the gateway and the identity provider, from dedicated accounts and workstations. |
| R11 | Host the system in trusted environments that match its security needs<br>*Héberger le système d’IA dans des environnements de confiance cohérents avec les besoins de sécurité* | Yes | **Jean:** static files with nothing running on the server, served from any host, on premises too, from a signed release ([releases.md](releases.md)); people's data stays on their devices. **Organisation:** where Jean is served, and above all where the brain runs, which sees what people send it: its own servers, a provider it trusts behind its gateway, or the brain on the device. |
| R12 | Keep each phase of the system in an environment of its own<br>*Cloisonner chaque phase du système d’IA dans un environnement dédié* | Partly: no training phase | **Jean:** the browser keeps each origin's storage apart, so a test copy on a host name of its own shares no files, keys or sign-ins with the production copy; an `ee/` key works only at the addresses it names (`ee/key.js`). **Organisation:** separate hosts, gateways, sign-in apps and secrets for testing and production. |
| R13 | Put a secure internet gateway in front of a system exposed to the internet<br>*Implémenter une passerelle Internet sécurisée dans le cas d’un système d’IA exposé sur Internet* | Yes, when Jean's address is on the internet | **Jean:** files only, each page with its own `Content-Security-Policy`, sent with one header set (`Strict-Transport-Security`, `X-Content-Type-Options`, `frame-ancestors`) that `policy.html` checks ([deploy/](../../deploy/README.md), `caps/policy/checks.js`); people sign in at the organisation's identity provider with OpenID Connect and PKCE, and Jean never reads a directory itself (D385). **Organisation:** the reverse proxy and filtering in front of the host and the AI gateway. |
| R14 | Prefer SecNumCloud hosting for a system deployed in a public cloud<br>*Privilégier un hébergement SecNumCloud dans le cas d’un déploiement d’un système d’IA dans un Cloud public* | Yes, in a public cloud | **Jean:** needs no particular cloud, and nothing passes through Warehouse SAS's servers when the organisation serves its own copy with its own gateway and no share host of Warehouse SAS's. **Organisation:** a SecNumCloud-qualified host where its security needs call for one, above all for the brain and the gateway; policy pins brains to them (`brains`). |
| R15 | Plan a degraded mode of business services without the AI system<br>*Prévoir un mode dégradé des services métier sans système d’IA* | Yes | **Jean:** what people made with Jean stays theirs without it: a backup is every file in one zip, readable anywhere (`caps/backup/`), and Sync keeps a copy in a folder (D157); offline, a brain on the device answers when there is one (D269). **Organisation:** how the work gets done without Jean. |
| R16 | Dedicate GPUs to the AI system<br>*Dédier les composants GPU au système d’IA* | No: the brain's servers | **Jean:** runs no GPU server. The brain on the device uses the person's own GPU through WebGPU, as any page may. **Organisation:** its inference servers, or its provider's. |
| R17 | Consider side-channel attacks on the system<br>*Prendre en compte les attaques par canaux auxiliaires sur le système d’IA* | Partly | **Jean:** adds nothing: answers stream over HTTPS as the brain's provider sends them. **Organisation:** padding against the token-length side channel the guide cites is the provider's or the gateway's to do. |

## Training

| # | Recommendation | For a deployment | What answers it |
|---|---|---|---|
| R18 | Train a model only on data its users may legitimately access<br>*Entraîner un modèle d’IA uniquement avec des données légitimement accessibles par les utilisateurs* | No: whoever trains the brain | **Jean:** trains nothing. Its reflexes' small model, Kev, was fine-tuned by Warehouse SAS on requests written for it to a specification, no one's real data, and is published with its data and recipe (`jean-is/kev-0.6b-reflexes-ONNX`, D328). |
| R19 | Protect the integrity of the model's training data<br>*Protéger en intégrité les données d’entraînement du modèle d’IA* | No: whoever trains the brain | **Jean:** Kev's training data is public beside its weights (D328), so anyone can read what it learned from. |
| R20 | Protect the integrity of the system's files<br>*Protéger en intégrité les fichiers du système d’IA* | Yes | **Jean:** a release's sums are signed (D419); the service worker checks each file it keeps against the SHA-256 in `capabilities.json` (`sw.js`), which catches a damaged file, not a hostile server: the signed release does that. Dictation's, the picture check's and the picture makers' weights are pinned by revision and SHA-256 and checked before use (`ui/weights.js`, `caps/voice/whistle.js`, `caps/pictures/`). **Not yet:** the device brain's and Kev's weights are the weights host's current files, unpinned (`caps/brain-local/brain-worker.js`, `caps/reflexes/`). **Organisation:** a mirror of the weights it checked (`urls.modelWeights`). |
| R21 | Never retrain the model in production<br>*Proscrire le ré-entraînement du modèle d’IA en production* | No: nothing is retrained | **Jean:** no model learns from use; what Jean remembers is lines in a file the person reads, changes and deletes (`core/memory.js`). |

## Deployment

| # | Recommendation | For a deployment | What answers it |
|---|---|---|---|
| R22 | Secure the chain that deploys AI systems to production<br>*Sécuriser la chaîne de déploiement en production des systèmes d’IA* | Yes | **Jean:** a release is built from a commit as git has it, never a working tree, its sums signed and the signature checked before it is said to be made (`scripts/release.js`, D419); the organisation checks it with OpenSSH before deploying ([releases.md](releases.md)). **Organisation:** deploying from its administration network and workstations. |
| R23 | Plan security audits before deploying to production<br>*Prévoir des audits de sécurité des systèmes d’IA avant déploiement en production* | Yes | **Not yet:** no outside penetration test; [pentest.md](pentest.md) is its brief, and its summary joins this pack once the high and critical findings are fixed and retested. **Jean:** every change checks the pages' policies in each engine (D326) and that no frame of Jean's own gets `allow-same-origin` (`test/html.test.js`). **Organisation:** its own audit, by a PASSI-qualified provider as the guide suggests, with pentest.md as a starting brief. |
| R24 | Plan business functional tests before deploying to production<br>*Prévoir des tests fonctionnels métier des systèmes d’IA avant déploiement en production* | Yes | **Jean:** a smoke test of every capability in Chromium and WebKit on each change (`npm run e2e`), and test sets in many languages that measure the reflexes, what brains offer, the tutor, answers from documents and long tasks (`npm run reflexes`, `offers`, `tutor`, `documents`, `longtasks`), most of them against a brain one names. **Organisation:** testing its own uses with its own brain before opening Jean to its people. |

## Production

| # | Recommendation | For a deployment | What answers it |
|---|---|---|---|
| R25 | Protect the system by filtering users' inputs and outputs<br>*Protéger le système d’IA en filtrant les entrées et les sorties des utilisateurs* | Yes | **Not yet:** Jean doesn't filter what people ask or what brains answer, for sensitive data or for requests the organisation wouldn't allow, and sets no length on answers beyond the brain's own. **Jean:** with Auto, a message the reflexes read as personal or confidential goes to the brain on the device when there is one (`ui/auto.js`, D269); a policy guard holds a call when a yes-or-no question about it is yes ("Does it hold a client's personal data?"), answered by Kev or the brain, a judgement rather than a filter (D295); a picture made on the device is checked there for nudity, hate, violence and self-harm before it shows (`caps/pictures/check.js`, D280). **Organisation:** a filter of requests and answers at its gateway. |
| R26 | Control and secure the system's interactions with other business applications<br>*Maîtriser et sécuriser les interactions du système d’IA avec d’autres applications métier* | Yes | **Jean:** [Where your files go](../../app/files.html) names every address Jean contacts; policy names the services people may connect; their tools ask first by default, read-only ones too (`caps/connections/connections.js`); sign-ins use OAuth or OpenID Connect with PKCE, their tokens sealed in `.secrets/`; HTTPS everywhere but this computer (D260); each call keeps whose rule decided it (D299, D308). **Organisation:** the header's `connect-src`, which narrows Jean to the gateway and the services allowed; network filtering; the rights each service grants. |
| R27 | Limit automatic actions from a system that processes uncontrolled inputs<br>*Limiter les actions automatiques depuis un système d’IA traitant des entrées non-maîtrisées* | Yes | **Jean:** the rules of R9 hold whatever Jean read, in a routine's run too, whose approvals wait in the inbox (`caps/routines/routines.js`); in a task shared from someone else's Jean, every call to a connected service asks first whatever the rules, and the task is marked as someone else's, to read as data (`caps/share/share.js`, D361); code reaches the internet only through Jean, asking once a run for each new site (D162); a picture loads only from an address a source gave, never one the brain wrote (D35, D336). **Organisation:** locked rules, as R9. |
| R28 | Isolate the system in one or more dedicated technical environments<br>*Cloisonner le système d’IA dans un ou plusieurs environnements techniques dédiés* | Yes | **Jean:** code a brain writes runs only in a worker started by `sandbox.html`, in a frame with `sandbox="allow-scripts"` alone, of an opaque origin, `connect-src 'none'` (`ui/sandbox.js`, D13); pages in answers and Office files in `preview.html`'s opaque frame (D126, D267); extensions in frames of their own (D296); other sites in the browser pane, never at Jean's origin (D140). **Organisation:** serving Jean from a host name of its own, which no other application shares, since the browser walls each origin's storage. |
| R29 | Log everything the system processes<br>*Journaliser l’ensemble des traitements réalisés au sein du système d’IA* | Yes | **Jean:** each task's file keeps every step on the device: the request, each call with its arguments, result and whose rule decided it, and the answer (D299, D308). With `ee/`'s `audit`, each turn goes to the organisation's OpenTelemetry collector as a trace: the request, each request to a brain (provider, model, tokens, why it stopped), each call and its decision, the answer, and what was added or removed, the words only with `"content": true`, the person named by their account or, with `"person": "pseudonym"`, by a pseudonym (`ee/otlp.js`, `ee/person.js`, D386, D421, D427); `retention` keeps what leaves a task its period (D412). **Not yet:** the trace doesn't hold the whole of what each brain was sent (its instructions, the parts of files given): the gateway's log does. **Organisation:** the collector, the gateway's log, and how long each keeps what, as the CNIL asks. |

## Code written by AI

| # | Recommendation | For a deployment | What answers it |
|---|---|---|---|
| R30 | Always check source code AI generates<br>*Contrôler systématiquement le code source généré par IA* | Yes, for code a brain writes | **Jean:** a brain's code runs without asking (`execute` is Do it by default), but only in the sandbox (R28); on the person's computer each command is asked first unless they always allowed that folder, and a change in their folder is asked with its diff (D141); Jean commits nothing itself, and a commit there is a command like any other; packages a script installs come from the registries policy names (`computer.registries`). **Not yet:** no analysis of the code a brain writes. **Organisation:** `"rules": { "execute": "ask" }` to have every script asked; its developers' review and analysis tools. |
| R31 | Limit AI-generated code in applications' critical modules<br>*Limiter la génération de code source par IA pour des modules critiques d’applications* | No: the organisation's developers | **Organisation:** what its developers may write with Jean or any assistant. **Jean:** its own sealing, lock, shares and certificates call the browser's Web Crypto and WebAuthn, and implement no cryptographic primitive of their own (`ui/seal.js`, `caps/lock/`, `caps/share/seal.js`, `caps/receipt/`). |
| R32 | Make developers aware of the risks of AI-generated code<br>*Sensibiliser les développeurs sur les risques liés au code source généré par IA* | No: the organisation's developers | **Organisation:** its developers' training. |

## Services open to the public

| # | Recommendation | For a deployment | What answers it |
|---|---|---|---|
| R33 | Harden security for AI services open to the public on the internet<br>*Durcir les mesures de sécurité pour des services d’IA grand public exposés sur Internet* | Only for a copy open to the public, such as jean.is | **Jean:** no server holds anyone's requests or answers: they stay on the device, sealed (R7); one header set the site's `policy.html` checks (R13). jean.is signs no one in: each person brings their brain's key or sign-in; an organisation's copy signs its people in (`signIn`, D385). **Not yet:** requests and answers aren't analysed or checked before they reach people (R25). **Organisation:** protection from denial of service, at its host. |

## Generative AI from others

| # | Recommendation | For a deployment | What answers it |
|---|---|---|---|
| R34 | Never use generative AI tools on the internet for work involving sensitive data<br>*Proscrire l’utilisation d’outils d’IA générative sur Internet pour un usage professionnel impliquant des données sensibles* | Yes | **Jean:** policy replaces people's brains with the organisation's and locks them (`brains`, `core/settings.js`), behind its sign-in (`auth: "oidc"`, D385); a project can keep to brains on this computer (D269); each answer says where it was done (D252). Without a policy, a person may pick any brain, consumer plans included (D235, D262). **Organisation:** `brains` in policy, the header's `connect-src`, and its rule for sensitive data. |
| R35 | Review regularly the rights generative AI tools have on business applications<br>*Effectuer une revue régulière de la configuration des droits des outils d’IA générative sur les applications métier* | Yes | **Jean:** Settings › Approvals shows each kind of action's rule and every guard, the organisation's marked as locked; a connection's rights are what its sign-in was granted, in the service itself; with `ee/`, each call, its decision, and each connection added or removed reach the collector (D386, D421). **Organisation:** the review itself, of what its identity provider and services grant, and of its policy, after each version of Jean it deploys. |

## Not yet

What the IT page and anyone quoting this file says Jean doesn't do:

- No outside security audit (R23): [pentest.md](pentest.md) is its brief.
- No filter of requests and answers for sensitive data, and no limit on an answer's length (R25, R33).
- No static or dynamic security analysis in the pipeline (R5), and none of the code a brain writes (R30).
- The device brain's and Kev's weights aren't pinned by hash (R20).
- The audit trace doesn't hold the whole of what each brain was sent (R29).
