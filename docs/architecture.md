# Architecture

How Jean is built, as it is now. Why each choice was made, and what was rejected, is in [decisions.md](decisions.md), cited here as `Dnnn`.

## Principles as rules

| Principle | Rule that can be enforced |
|---|---|
| KISS | Hard limits in [budgets.json](../budgets.json), checked in CI. Going over means deleting something first. |
| Portable | All data is plain files: Markdown, JSONL, `SKILL.md` folders, sealed at rest on the device (D371). Export is a zip; import is dropping a folder. |
| Universal | Standards, not adapters: OpenAI-compatible and Anthropic Messages, MCP, Agent Skills, ACP events, the Jev-style Decisions API. |
| Browser-ready | Static files, offline after the first load, opened from a link. |
| System-agnostic | `core/` uses only standard web APIs and runs unchanged in a browser, a worker, Node, Deno or Bun; its tests run under `node --test`. |
| Incremental | Capabilities are discovered as situations call for them, offered by Jean, granted by the user, and only then loaded. |

## Stack

**No build step** (D9). Plain ES modules and an import map; types in JSDoc, checked by `tsc --noEmit`. Development serves `app/` as written (D243), and view-source is the source; a web deploy copies `dist/web/`, the same files with Jean's own code minified and each file compressed beside itself (D318).

**A first load without a bundle.** `npm run manifest` writes a `<link rel="modulepreload">` into `index.html` for every module the first load imports, so the browser fetches the graph in one round trip, and stamps `sw.js`'s `VERSION` line; `npm run manifest -- --check`, in CI, fails if either is stale. The first screen loads only what it draws (D76, D94, D148): the desktop app's host (`ui/host.js`, imported as Jean opens on 127.0.0.1 alone), the dialogs (`ui/dialogs.js`), the Anthropic adapter (imported by `core/llm.js`), the loop and the other adapters (with the first message), Auto, and what a message needs on its way (`ui/send.js`: the prompt, what the brain reads of the files, the run and its approvals, cache warming, loaded as the user starts typing) all load when first needed, and stay in the shell's precache for offline use. A web deploy sends them minified, each in brotli as `npm run build:web` wrote it (`scripts/web.js`, D318).

`vendor/`, `capabilities.json`, `manifest.webmanifest`, one per language in `manifests/` (D396) and a copy of `LICENSE`, all in `app/`, are made by `npm run dev`, `start`, `build` and `check` from Jean's own `node_modules` and the root's licence, and never committed (D43, D51, D52, D74, D243).

**Vendoring** (`scripts/vendor.js`). The three upfront libraries (only the lit-html files Jean imports) and the on-demand runtimes (`optionalDependencies`) are copied, as `package-lock.json` pins them, from Jean's own `node_modules` into `app/vendor/`, their bare specifiers rewritten where import maps don't reach (workers), and what Trusted Types and the CSP refuse patched, each patch found exactly as often as expected or the copy stops. A runtime is listed under the capabilities that use it, never in the shell, and nothing comes from a CDN (Transformers.js gets `wasmPaths`). `npm install` also fetches Transformers.js's Node backends (~300 MB), which never ship.

**The web's copy** (D318, `scripts/web.js`). `npm run build:web` copies `app/` into `dist/web/`, minifies Jean's own modules, workers and style sheets with esbuild (a dev dependency, pinned), and writes each file that compresses beside itself in brotli and gzip at their best, which the server sends as they are (Caddy's `precompressed br gzip`, nginx's `gzip_static`). Minifying takes out comments, whitespace and local names, nothing else: a classic script keeps its global names, no syntax is lowered and no prefix added (for the browser floor, esbuild would turn `\p{…}` regexes into `new RegExp` strings, un-nest `@starting-style` and add `-webkit-` prefixes), and a style sheet loses only whitespace and comments. The first load is about 40% less than what Caddy compressed on the fly (zstd), a second on a slow connection, and ONNX Runtime's wasm 3.8 MB rather than 6.2. The service worker, the bridge, the pages, `ui/touches.css` (shown as it is, D111) and third-party code stay as written. `capabilities.json` then lists the minified files' hashes and the version they make, which `sw.js` carries, while its render listing keeps the package's own hashes (D305). The budgets measure `app/` as written, and development, the desktop app and the render package use it as it is. Deploying is `npm ci && npm run build:web`, then copying `dist/web/`; the build takes about a minute, most of it brotli on ONNX Runtime's wasm.

**Budgets** ([budgets.json](../budgets.json), D86). `scripts/budgets.js` measures them in `npm run check`, and `npm run dev`, `dev:gateway`, `dev:share` and `start` run `scripts/budgets.js --short` as Jean starts, then after each change to `app/`, `cli/` or `budgets.json`, each time in a process of its own (D244): every budget over is said, a line each on the error stream, until all are met again, and as Jean starts those within 2% of their limit are named too; the server still serves. The line budgets (`loc.core`, `loc.app`, `loc.cli`, D246) count lines of code, by `scripts/loc.js`: a line counts when it holds anything but comments and white space, so a comment after code leaves its line counted, and what a string, a template or a regular expression holds is code, whatever it looks like. Modules are read as a browser reads them, style sheets by their comments, and a page by its own and those of its scripts and styles. `loc.cli` counts `cli/`'s modules (D240); `bridge/` and `gateway/` have no limit.

**Built on the browser, no dependency:** text from DOCX, XLSX and PPTX (zip through `DecompressionStream` and a small tag scanner, not `DOMParser`, so it runs in workers and under `node --test`); the backup zip (`CompressionStream`); BM25 search with `Intl.Segmenter` over an index made once, which ranks deferred tools, past conversations and the passages of documents, and `alike()`, which tells requests of the same kind apart (`core/search.js`), plus matching as people type over a fold of the text as long as the text (`fold()`, which drops accents, hamza and Arabic vowel marks and keeps marks that make letters, and `ranges()`, D133); ULIDs from `crypto.getRandomValues`; the system's voices; Web Locks and BroadcastChannel between tabs.

**Routing is one hash** (D59, D137, D220), read by `ui/router.js`: `#/c/<ulid>`, `#/p/<project ulid>/c/<ulid>` in a project other than home, `…/settings/<section>` with Settings open over either, and after a `?` the windows beside it, in the order they opened, each `name` or `name=state` (its slashes and colons as they are), as in `?flow=task&terminal&browser=https://example.com/`: `preview=files/<file>`, `browser=<address>` (`folder:`, `workspace:` and `made:` for Jean's own pages), `terminal`, `flow=<flow ulid>` (flow mode on a new task, the pane beside a task) or `flow=task`. `ui/windows.js` keeps them: each window's module calls `keep(name, { get, set })` as it loads, `get()` saying what it shows (null closed), `set()` showing a state again after checking it. Following an address, it waits for `app.ready`, closes the windows not named and those out of order, then loads each named window's module (once its capability is found) and sets it, giving the keys back where they were. The router writes the windows into the entry it is on rather than adding one, and follows them only when an address leads to another place: a reload, a link, or Back and Forward to another place shows its windows, while Back and Forward within a place (a site's own pages, Settings closing) leave them as they are, and a window shown again doesn't take the keys. A name Jean doesn't know, or one whose capability isn't found yet, is passed over, so an address stays good as windows come and go. Opening Settings adds one history entry, so Back closes it; another section takes the same entry, and Settings closed where it opened goes back. The unsent draft is kept per conversation in `sessionStorage`; other dialogs stay out of the address.

**Components are custom elements** (light DOM, prefix `app-`). Each capability is one module that defines its elements and registers its tools, hooks and slots ([Events and slots](#events-and-slots)); unlocking it is an `import()`, and any of its elements already on the page upgrade. `:not(:defined)` styles what isn't discovered yet. One the user turns off once found (D433) goes into settings' `off`, which `ui/app.js` adds to policy's `deny` as the page begins, so nothing unlocks it until its row in the case turns it on, at once (`turnOn()` in `ui/dialogs.js`, which allows it again first); turning off writes settings before it says so, and `ui/update.js` sees a capability loaded that is now off, here or in another tab, and opens the page afresh where it was once nothing is under way, as for a new version (D138), since a module can't be unloaded.

## Brand

```js
// brand.js — the only place the name lives
export const BRAND = Object.freeze({ name: 'Jean', domain: 'jean.is' })
```

- **For display only** (D4): UI strings (`{name}`), the system prompt, the page title and the web-app manifest. The wordmark is the name set in the display face, so there is no logo file to redo.
- **Never in anything that persists:** storage keys, OPFS paths, cache names, element prefixes, CSS classes, the desktop app's identifiers. Renaming changes one line and moves no data.
- **The assistant's name is a setting:** `settings.assistantName ?? BRAND.name`, which a project can override (D102).
- **Grammar:** translations never make a word agree with the name; in conversation, the brain handles grammar itself.
- **The origin is not a variable.** Storage belongs to the domain, so it is settled before the public launch (D27).

## Core

- **`loop.js`**: stream the reply, run tool calls, feed results back, repeat. Rules (Do it / Ask me first / Never) are checked before each tool runs, calls from scripts included. The prompt and declared tools are frozen for the conversation; changes arrive as notes ([below](#prompt-tools-and-caching)).
  - `tools` is every tool that can be called, and may be a function read again at each step, so a capability turned on mid-turn can be called at once. `declared` is what the brain sees; `hidden` tools are never declared (D64).
  - A tool's `check` runs before a call the rules don't refuse: it can ask even where they allow (a change in the user's folder) and give the card what it shows (ACP `diff` content). `ctx.content` is kept on the call's record before its result; `ctx.answer` is what the user answered (D152).
  - Sources are numbered from `firstSource`: tools call `ctx.cite()`, the brain's own search sends `cite` events that become ` [n]`, and both are recorded as `_meta.sources` (D90). `ctx.meta` records more (a picture). `ctx.progress()` says how a call is coming while it runs, a `tool_call_update` with `content` and `_meta` (the call's own, and more) that is shown and never kept (a picture as it forms, D265). A provider's `pause` (Anthropic's `pause_turn`) is sent back and resumed.
  - `ctx.turn()` runs a helper's child turn (`delegate` splits a task into up to five parts, run three at a time as hidden `helper` calls) with the same brain, rules, approvals and source numbers, its own prompt, history and tools; its records nest under the calling tool's (ids prefixed, `_meta.parent`, no thinking blocks) and its text is the call's result (D98).
  - `meta` on the brain entry says why Auto chose it (D70).
  - `ctx.update()` sends an ACP update of the tool's own (a plan), shown at once and kept after its call's record, the latest of each kind (D364).
  - Steps go in blocks of `maxSteps` (12, or 40 in a folder; after `resume`, counted from the step after it). At the end of one, `turn.limit` may give the turn another; a step whose calls are all `aside` isn't counted, one in a row at most; and a turn that stops there keeps its last brain entry again with `_meta.stopped: 'max_turn_requests'`, ACP's stop reason, which the room shows as a pause (D364). The events of a helper's turn carry `parent`, the call it works under.
  - `steer()` gives what the user sent while the turn works, as their records (`user_message_chunk` with `_meta.steer`), read at the top of each step, before compaction: kept, then read by the brain as the user's message after the last step's results. A helper's turn reads none (D365).
  - A request that fails before anything of its answer came is asked again after 1, 2 and 4 s, or after the provider's `Retry-After` when longer, up to 30 s, if the error may pass (`LLMError.retryable`: the connection, the provider busy or its server failing, and the browser offline, which looks the same as a refused cross-origin request; never the device's brain). Meanwhile the brain entry has `_meta.retrying` and the activity says "Trying again…". Once part of an answer came, or after the last wait, the error shows with Try again (D202).
- **`llm.js`** and **`anthropic.js`**: the OpenAI-compatible Chat Completions and Anthropic Messages adapters, over fetch and SSE (`sse.js`); together they reach almost every model. `llm.js` imports `anthropic.js` when an Anthropic brain is first used. Anthropic from the browser needs the `anthropic-dangerous-direct-browser-access: true` header; OpenRouter's PKCE sign-in (`oauth.js`) runs entirely in the browser. A `claudecode` or `copilot` brain is an Anthropic one, and a `chatgpt` brain an OpenAI-compatible one, whose address is This computer's bridge, which runs the user's own Claude Code or Copilot, or signs in to ChatGPT (D235 · D262). OpenRouter weighs the credits left against the longest answer a brain may give, which Jean leaves unsaid; when they fall short it answers 402 with how many tokens they cover, and Jean asks again for that many. Any other 402, or Anthropic's 400 that says the credit balance is too low, is `credits`: the error says the brain is out of credits, to add some or choose another brain, with Check the brain beside Try again, and isn't tried again by itself.
- **`hooks.js`**: Jean's events, which hooks watch, change or answer ([Events and slots](#events-and-slots), D293).
- **`events.js`**: the ACP records and their envelopes ([Activity events](#activity-events)), `splitSuggestions()` (D69), `versionsOf()` (D164), `isPicture`.
- **`prompt.js`**: the base prompt, the frozen sections and the notes that change them (D46, D81), and `toChatMessages()`, the records as the messages the brain reads after it.

## Events and slots

What Jean does passes through named events, and what the room draws for a capability goes through named slots that the capability fills (D293), the points apps will reach too.

**Hooks.** `fire(hooks, name, e, behaviour)` (`core/hooks.js`) runs the hooks on that event whose `match` the event holds (a value, one of a list, or a pattern its text matches), outermost tier first (`policy`, `user`, `jean`), in the order given within one. Each `run(e, next)` calls `next(e)` to go on, with the event or a changed copy, the last `next` reaching Jean's behaviour; returning without it answers the event. One that throws is passed over, or answers `{ refuse }` when it is a guard (`refuse` set); once it went on, what came back stands, and what Jean's behaviour throws goes through as it is. An answer a hook gave of its own, a plain object other than the one the chain gave it, carries `by`, whose it is (D299). A capability lists its `hooks`, which `contributions()` gathers, read again at each event as tools are, each by the capability's id unless it says whose it is.

**The device's brain's watermark** (D402, `caps/brain-local/watermark.js`): the worker hands `generate()` a logits processor and decodes greedily, so the processor decides each word. Among Gemma's 64 likeliest at a temperature of 1, the fewest whose chances reach 95%, as its generation config samples, the one whose `ln(u)/p` is highest wins, `u` a number in (0, 1) from a keyed MurmurHash3 of the four tokens before and the candidate (`seed()`, `unit()`): each is picked as often as sampling would pick it, and the same each time; every other logit becomes −∞. Between `<|channel>` and `<channel|>`, and `<|tool_call>` and `<tool_call|>`, the logits pass untouched, greedy. `lean()` counts a text: −ln(1 − u) for each token after its first four, each context and token once, which sums to n on average over n by chance, with a standard deviation of √n; `said()` calls 4 deviations above marked, fewer than 300 counted too short to tell, and anything else none found, which proves nothing: on E2B half of the answers of 500 tokens show it. The worker's `lean` request loads the tokenizer alone (`tokenizing`), from Transformers.js's cache or the weights host.

**The organisation's sign-in** (D385, [enterprise.md](enterprise.md#signing-in-at-work)): with `signIn` in policy, `start()` in `ui/app.js` imports `caps/signin/signin.js` before the room shows, and its `start()` signs in when nothing is kept: discovery from the issuer itself (`discover()` given the `issuer`, so no protected resource is asked for), `authorization()` with the gateway's scopes, the PKCE verifier and state in `sessionStorage` (`app.signin`), and `leave()` (`ui/brains.js`), which keeps the box's words, its files and the route. Back with `?state=…`, `comeBack()` puts them back and `finish()` trades the code. The tokens go to `.secrets/` as `signin`, with where signing out goes (`end_session_endpoint`), and the access token as the key of each policy brain with `auth: 'oidc'`, so every request reads it as any brain's key. A timer renews them five minutes before they end, a minute apart at least, and so does the page showing again: `token()` renews once per tab, and `renew()` once across tabs under a Web Lock, the next tab reading what the first kept. A refusal deletes them and offers the sign-in in a toast; a network error keeps them. Another part of policy may start a sign-in of its own under another id (`signin:audit`, D386). Settings › Brains says who signed in through the `brains` slot, with Sign out.

**Policy by group** (D429, [enterprise.md](enterprise.md#policy-by-group)): `whoOf()` keeps the ID token's `groups` and `roles` with the tokens, null when Entra says there were more than the token holds (`_claim_names`). With `groups` in policy, `start()` in `ui/app.js` calls `groups()` in `caps/enterprise/` as soon as policy is read: it finishes a return from the organisation's sign-in (`back()`, which `start()` then reads rather than finishing it again), and, with a key or on localhost, `ee/ee.js`'s `groups()` checks it and replaces `app.policy` with `forPerson()`'s (`ee/sections.js`): each section of the person's groups, in policy's order, over it as a JSON Merge Patch (RFC 7386). A profile's lock (D389), settings, denied capabilities and the oidc brains' keys all read it after. What fails leaves policy as it was, and `ee/groups.js` keeps why, so its `start()` throws it in `caps/enterprise/`'s, which stops Jean in the person's language (`groups.many` for a token past its groups). Its `brains` slot names the sections that apply.

**The organisation's places** (D434, [enterprise.md](enterprise.md#data-residency)): with `jurisdictions` in policy, `start()` in `ui/app.js` calls `groups()` in `caps/enterprise/` as it does for `groups`, and `ee/ee.js` gives policy back with only the brains `kept()` (`ee/places.js`) allows: on this device or this computer (`isLocal()`), or declaring a `jurisdiction` within one of the places (a code itself, its subdivisions, or the EU's member states for `EU`), after any group's sections. **Prices** (D255): `ui/prices.js` reads `https://models.dev/api.json` (`urls.prices`, which settings or policy replace, or turn off with `''`) the first time a price the provider doesn't give is wanted in a session, never at the start, and keeps in `.cache/prices.json` only what a price needs of the providers Jean knows: dollars per million tokens read, written and read again from the cache, about 30 KB of a 5 MB catalogue. It is read again a week later or when its address changes; when it can't be, what was read before stays. A model is found by its id, or its name without its maker's, a variant or a date (`google/gemini-…`, `…-20261001`). OpenRouter lists its prices with its models, so its own are used. A brain that answers from a plan the user pays for costs nothing per token and no catalogue is read for it: the answer's cost and the picker say it is in the plan, named.

**Kept to projects** (D194): a brain's `projects` keeps it to those projects, and without it the brain is in every one (`usedIn()` in `core/settings.js`, as for connections). `brainsHere` in `ui/state.js` is the room's project's, and Auto, the picker, `activeBrain`, Double-check, pictures and films, routines and Since last time read it; Settings › Brains lists every brain, one kept elsewhere unable to be chosen, and ticks where each is used, under its button (`where()` in `ui/dialogs.js`, which Connections shares).

## Reflexes

`decide(state, questions)` takes typed questions (`noul`, `choice`, `score`) and returns calibrated probabilities, in the Jev/Decisions API shape that Jev, Clef, Strands Decider, Laya, Kev, Ollaya and OpenRouter's `/api/alpha/decisions` share, so backends can be swapped. In the UI, reflexes are **Intuition**.

```js
// ui/discovery.js, with the questions from caps/reflexes/questions.js
const { demand, personal, capability } = await decide(message, {
  demand:     { type: 'score',  instructions: 'How demanding is this request?', criteria: ['a quick chat or a simple fact', 'reading, writing or summarising', 'several steps of work or analysis', 'expert reasoning'] },
  personal:   { type: 'noul',   instructions: 'Does the message share personal, health, financial or confidential information?' },
  capability: { type: 'choice', instructions: 'Which of these would help with this message, if any?', criteria: { compute: 'exact numbers, maths, or analysing a table of data', none: 'nothing new is needed' } },
})
```

**A child's danger** (D390): in a child's profile, the first pass also asks which danger the message tells of (`danger`, a choice of self-harm, abuse, an adult asking for secrecy, pictures or a meeting, bullying, or none) and whether the person hurting them lives with them (`home`); `dangerOf()` reads them as the danger, or `home` for any but self-harm, which Profiles' `modes` notes turn into a note for the brain and, but at home, a concern for the parent. **How Kev is asked** (D67): all of a state's questions in one forward pass, each with its options between Kev's delimiters (ids from its `config.json`: the model card's sample escapes them, which flattens every score); each option's score softmaxed within its question; a score read as its most likely level, since Kev hedges toward the middle; a yes, or an offer, at 0.6. **Measuring offers** (D284): `test/offers/<lang>.json` holds 43 requests in eight languages (English, Arabic, Spanish, French, Hindi, Japanese, Swahili, Simplified Chinese), each labelled with the capability the brain's `offer` should name, or none. `npm run offers` reads the frozen prompt and declared tools a first conversation sends, from the page in headless Chromium, then sends each request through core's loop to the brain `BRAIN` names (as jean-cli's `--brain`, its key in `<PROVIDER>_API_KEY`), `BRAIN_BODY` is added to each request, so the device's Gemma answers without thinking, as in the tab. There is always a default project, hidden until Projects is discovered, so one code path handles everything.

- **Writes.** One storage worker writes with `createSyncAccessHandle` (Safari 16.4+, Chrome 108+, Firefox 114+, which has module workers; D12). Conversations are append-only, so a crash costs at most a half-written last line, ignored on read (going back to a request rewrites one whole, D188); files rewritten whole go to a temporary file first, then are swapped in.
- **Several tabs.** Web Locks serialise writes per file; BroadcastChannel tells other tabs to refresh.
- **Sealed at rest** (D371, [encryption.md](encryption.md)). The storage worker seals every file it writes in OPFS and opens every one it reads (`ui/seal.js`), so nothing above `FS` knows: a 32-byte header (`\x89seal`, the vault's id, a salt) and records of AES-256-GCM of 64 KiB at most, the file's key derived from the vault key and its salt by HKDF, each record bound to the header and the file's path. A whole write takes a new salt and goes through the temporary copy; an append is records after the last; a record cut short or torn at the end is left out, as a half-written line was. `stat` gives the size as stored. The vault, a profile's, opens at the first `ping`, which names its folder: a first run makes its key and seals it under this device's (a non-extractable key in IndexedDB's `app-keys`, by the folder), and with a lock (`caps/lock/`) the worker answers `locked` and waits for the key the lock screen hands it, or another tab, on BroadcastChannel's `app-vault`. Files with no vault that opens them answer `sealed`, with only starting afresh offered. A folder of the user's, and `.secrets/vault.json`, stay plain.
- **Folders of the user's** (D141, D149, D152). A project or a conversation opened on a folder of the computer gets an `FS` of its own (`folderFS` in `ui/opfs.js`): a storage worker started on the folder's handle, writing in place with `createWritable`, without the temporary copy and without telling other tabs. `stat` gives a file's size and `lastModified`, which a change checks against what the conversation read. Handles live in IndexedDB's `app-folders` (the profile's, D228) under the project's or conversation's ULID (a conversation duplicated from another gets that one's, D230), with the folders "Always allow" was given for; the folder's name is in `project.md` and `<folder>`, so a missing handle is asked for again by name. Tools work in the folder of the conversation that asked (D147). Outside Chromium, a folder is a read-only copy for the visit (`caps/folders/copy.js`), and what Jean changed is saved as one zip. Nothing of Jean's is written there.
- **Profiles** (D228). A profile is a whole Jean: its settings (brains and keys, rules, look, language), its vault and lock, the person's instructions and memory, its projects, connections, sync places and routines. `opfsFS()` (`ui/opfs.js`) chooses it at the start, before any of it is read: the one holding the project or task the address's first ULID names (`profileOf()`, `core/settings.js`), else this tab's (`sessionStorage`'s `app.profile`), else the last opened in this browser (`localStorage`'s), else the first; a first run makes `profiles/<ulid>-profile/`. It gives `rootedFS()` (`core/fs.js`), which sees that folder as its root and hears of changes in it alone, so no other module knows of profiles, and `app.whole`, the whole FS, which only Profiles reaches. The storage worker gets the folder with its first `ping`: the vault's files are there, sealed with their paths from it, and outside it bytes go and come as given. `mine(key)` names a browser's key by the profile (`app.theme:<folder>`, as `index.html`'s first-paint line reads them); so are IndexedDB's `app-folders` and `app-sync`, and the device's keys in `app-keys`. Nothing crosses between profiles (memory, search, @, meetings, Since last time): a project moves by export and import, or a sync place. The first one is unseen until a second: Profiles (`caps/profiles/`) loads at the start once there are two, puts them atop the person's menu, adds one (its dialog in `dialog.js`), and names and removes them in Settings › Profiles, each listed from its `vault.json`. Switching opens the other afresh (D138), at no address. The lock screen lists the others, and a profile's "start afresh" removes it alone.
- **A child's profile** (D389, D390). Its `vault.json` names its parent's profile and the public half of a key that profile keeps (`family.json`). What the parent set, `parent.json` (`tier.js`), becomes `app.policy` before settings are read: `searches`, `pictureCheck` at its strictest, `capabilities.deny` (connections, this computer, apps, the browser at first), `rules` and `brains` as the parent left them, even none, which locks Brains, and `instructions` made from the year of birth, the topics' choices and the rules every child's has (the school programme as their book, never their work done, a danger answered with care and the child helpline, `helpline()` by the browser's region); `child: true` hides Start for free and makes a lock say "Set by a parent" (`lockedBy()`). Settings › Set by a parent shows it; the parent's way in (`ways()` in the lock, on their `vault.json`) lifts it while they change it there and in Settings, and Done keeps it, seals the slots again for the child's age (until the school year they turn 13, one sealed under the parent's vault key, `kind: 'parent'`; then this device's, or the child's own lock), and opens it afresh. Each message the child sends comes after Learn it's steps (`learning()`), read from `caps/skills/directory/learn-it/SKILL.md` whether or not the profile has the skill, as Visual answers reads its own (D300), so a brain needn't pick it: with Learn it only listed, `npm run tutor` found brains gave a child the answer far more often (D394). Minutes on screen are counted in `localStorage`, and every five sealed for the parent (`family.js`: ECDH P-256 with a key made for each, AES-256-GCM) as `family/<parent ULID>/time-<child ULID>.json`; a concern goes there as `<ULID>.json` and a `BroadcastChannel` tells a parent's tab, which shows it above the box until seen, in Settings › Profiles, and as a notification once allowed (asked as the child's profile is made).
- **Format changes.** Every file carries a `format` version, to be upgraded lazily when read once Jean has users; until the public launch nothing is kept for earlier shapes (D173).
- **Preventing loss:** `navigator.storage.persist()`; installing the app (Safari can wipe a site not visited for 7 days); backup offered early; Sync (D157) as a continuous copy in Chrome and Edge; usage shown in plain words; model weights evicted first, never user data.
- **What takes up space** (D177, Settings › Your data): `weigh()` in `core/files.js` totals Jean's files by kind (the projects' conversations, files and workspaces, and the rest); `ui/dialogs.js` adds the browser's caches by name, `transformers-cache` as the brains on this device, `app-cap-…-computer` with the Computer's workspace, the other `app-shell-` and `app-cap-` caches and `app-sounds`, a score's instruments, as the offline copy, each response by its `Content-Length` unless it came compressed. What `estimate()` counts beyond them is everything else's.
- **Secrets.** API keys and tokens are kept in `.secrets/keys.json`, sealed as every file is and behind the lock when there is one, and never exported, synced or shared. They change one at a time, across tabs too (a Web Lock), so that writers at once keep each other's, and never over a file that can't be read. The key that seals certificates (D252) is a non-extractable `CryptoKey` in IndexedDB (`deviceKey` in `ui/secrets.js`). Folder handles can't be encrypted or kept in a file; IndexedDB keeps them, never in a backup.
- **A task as a web page** (D305). `saveTask()` (`ui/export.js`, loaded from the task's ⋮ menu or ⌘S) reads the conversation's file and saves what `pageOf()` makes of it, under the task's name, in the language Jean speaks: the file in a `<script type="application/jsonl">` block, each `<` written `\u003c`, which leaves every line the same JSON and the block nothing to end it with, then `draw()`'s own source, which shows each request and each answer as written (an answer's steps one after another, its follow-ups left out, a shared file by its name) with when it was said, and the pictures it made. Those are among `filesOf()`'s: every file the task's records name (`filesIn()`: those its calls made, pictures and those its brain or its computer wrote, then those shared with it), read from its project and kept as they are, as `data:` addresses, in a JSON block by their addresses in the project, whose pictures the policy without the package allows too. Then the render package, at the address `urls.render` gives (jsDelivr's, at the version `capabilities.json` names; none when ''): what the page was saved with in a JSON block (the look, the kinds of block the room's skills declared, what pages may do, offline, and the map service's styles when maps were allowed), an import map that finds Jean's own import map's libraries and `ui/state.js`'s stand-in there, with every module's `integrity`, and `ui/reader.js` by its hash. The reader folds the records as `ui/chat.js` does and draws them with `markdown()` and the capabilities that draw answers (layouts, math, charts, scores, slides, interactive), which it imports, a picture made under its answer, as `<app-picture>` shows it, and any other file the page holds as its name in a `<details>` (`files()`), which the first time it opens draws the file in it as the preview does (`viewOf()`, `ui/view.js`, its style sheet loaded with the page's), doing what the page was saved to let pages do: a PDF's pages by pdf.js, an Office file or a CSV as Office draws it, Markdown laid out, a sound or a film played; a file it doesn't hold, a request's that didn't go with a share, by its name alone. Then the page's own lines step aside. `ui/reader-state.js`, in `ui/state.js`'s place for them, has the task, what the page was saved with and light or dark as the system has it, loads the words from the package in the page's language, and keeps and sends nothing. Its scores play on MS Basic's instruments, from the sounds package on jsDelivr at the saver's version of it (`urls.sounds`, by default `@jean-is/sounds`), their sound made on the page, since no worker starts from the package's address, and decoded in WebAssembly, which its policy allows (D338). That policy therefore allows inline scripts, data and blobs, sounds and films from them, the package's address, and the map service's when maps were allowed, and nothing else; without the package, the page's style and lines alone, by their hashes.

## Service worker

- **On install:** cache the shell (`sandbox.html` and `preview.html` included) and every locale file, so switching language is instant and offline. Files come through the HTTP cache and are checked against the integrity hashes in `capabilities.json`; a stale copy is fetched again. The install icons and screenshots stay out (D131, D168).
- **On unlock:** cache the capability's files, listed in `capabilities.json` with content hashes, with the modules of other capabilities it imports (the Computer's from Folders and Files), so it works offline on its own. The cache is the record of what has been unlocked.
- **On update:** download the new shell and new versions of unlocked capabilities only, then delete old caches. When the user lets it in, the new version takes the page's place where it was (`ui/update.js`, D138).
- **Model weights** live in their own cache, so an update never downloads 3 GB again.
- **A notification the page can't show itself** (Android's browsers refuse `new Notification()`) is shown by the service worker, and a tap on it focuses Jean's window at the task's address, or opens one there (D334).
- **Offline:** history, files and the device's brain keep working; with only a cloud brain, Jean says so. The site's policy holds as last read: `ui/app.js` keeps a copy in the `app-policy` cache, read whenever `policy.json` can't be, so an organisation's brains, locks and denied capabilities never lift with the network. The Computer and pages in answers need the site to start their frame, which Chromium loads past the service worker, sandboxed as it is: offline, the sandbox says so within 5 s of its frame loading.

## Security

Every HTML document has its own CSP in a `<meta>`, which works on any static host. Each is checked in every engine by the browser's own reports (D326): `scripts/serve.js --csp-reports` serves each page's `<meta>` policy again as a `Content-Security-Policy-Report-Only` header whose reports it keeps, by the `csp` cookie that names whose they are, so a browser says what its policy refused, Trusted Types and workers made from blobs included, with no hook into the page. `test/csp.spec.js` takes Jean through an answer drawn from Markdown, a page in it charting with the ECharts Jean lends, the sandbox's script and its page beside the conversation, Python, Settings and the check page, after a refusal made on purpose that shows the browser reports at all, and fails on any other: with the smoke tests in Chromium and WebKit, and in Firefox, Chrome and Edge themselves, where installed, with `npm run csp` (`test/browsers.config.js`), which then drives Safari and Firefox themselves over WebDriver (`scripts/csp.js`: `safaridriver` once Safari's Allow remote automation is on, `geckodriver`). Two refusals are expected. Pyodide asks whether its worker is a classic one by importing an empty `data:` script, which the sandbox's policy refuses, and goes on as a module worker would, Python working either way. Safari makes a Trusted Types policy of its own in the room, from a script it puts in the page and not through the page's `trustedTypes` (a hook on it saw Jean make only `lit-html` and `app-urls`), so its report names the page and no file of Jean's; an empty page, or one with a form, gets none.

**`index.html`** runs only Jean's own code:

```text
default-src 'self'; script-src 'self' 'wasm-unsafe-eval' 'sha256-<import map>' 'sha256-<first paint>'; style-src 'self';
img-src 'self' blob: data: https:; media-src 'self' blob:; font-src 'self';
connect-src 'self' https: wss: http:;
worker-src 'self' blob:; manifest-src 'self'; frame-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none';
require-trusted-types-for 'script'; trusted-types lit-html app-urls
```

- **`connect-src` is broad** because users add any OpenAI-compatible endpoint, and untrusted code never runs in this document. Organisations tighten it with an HTTP header ([enterprise.md](enterprise.md)).
- **Plain HTTP reaches this computer alone** (D260). Before it reads anything Jean keeps, `start()` in `ui/app.js` adds a second policy, which holds as well: `connect-src 'self' https: wss:` and `http://<name>:*` for `localhost`, `127.0.0.1` and, in the desktop app, each of the computer's own IPv4 addresses; Settings › Web search reads that policy to tell what it can reach (`insecure()`). `addresses()` in `ui/host.js` reads them from what `ifconfig` writes (`ip` where there is none, `ipconfig` on Windows), run with `os.spawnProcess` and heard through its `spawnedProcess` events, waiting 2 s at most. A policy can only narrow, so an address the computer takes later (another network) holds from the next load.
- **`img-src` allows `https:`** for the site icons on web sources' chips, whose address is replaceable (D210), and the pictures sources give (D35): an answer draws a Markdown image only when its address is a source's picture, then loads the address the source gave, and shows any other as its words.
- **A source's picture** (D35, D336). Wikipedia's and Vikidia's search bring each page's lead picture (`pageimages`, 500 pixels, without the `utm_` words Wikipedia adds), and so does `browse` for an article of their sites, whose pages refuse other sites' reads: it reads the article, whole and redirects followed, through MediaWiki's API at the source's address (`readWiki()`). Any other page `browse` reads gives its own (`og:image`, else `twitter:image`, https alone). Each is told to the brain on a `Picture:` line under the source and recorded with it in `_meta.sources`; a shared picture goes by its name. `ui/markdown.js` hands an image to the layouts capability, which draws it only when its address, escaped or not, is one of those, and then loads the source's own address, never the one written, without a referrer, dropping one that doesn't load; its site is among those About this answer says the answer reached (D252). At the head of a comparison's card it shows above the option's name, as tall in every card and on white, as shops show what they sell. Compare and choose puts one there for each option when they are things one looks at, or none, and browses an option's own Wikipedia article when no source gave one: the brain's own search (Anthropic, OpenRouter) brings no pictures, and shops' pages refuse other sites' reads, so with it an option without an article, or with the browser off, has none.
- **A runtime that needs `'unsafe-eval'`** gets a worker document of its own, never a looser `index.html`.

**`sandbox.html`**, framed with `sandbox="allow-scripts"` and never `allow-same-origin` (D65, D162):

```text
default-src 'none'; script-src 'sha256-<relay>' blob: 'wasm-unsafe-eval' 'unsafe-eval'; worker-src blob:;
connect-src 'none'; base-uri 'none'; form-action 'none'
```

- **No access to Jean's storage** (its origin is opaque) **and no network at all.** It holds only a small inline relay, allowed by its hash. `test/html.test.js` checks the hash and that the frame never gets `allow-same-origin`.
- **The parent sends everything in.** `ui/sandbox.js` fetches the worker's source and, when a run first needs them, an engine's files (listed in `capabilities.json`), and posts them to the relay.
- **Untrusted code runs only in a Worker** made from a `blob:` URL, so it inherits the sandbox's CSP; workers have no navigation, no WebRTC and no `sendBeacon`. It is a classic worker, since browsers refuse module workers from `blob:` in an opaque origin; it can still `import()` blob modules and compile wasm, and Emscripten gets `wasmBinary` and `wasmLocation` so nothing resolves against a `blob:` base.
- **QuickJS:** 64 MB of memory, 20 s of computing time (waiting on Jean or the user doesn't count), 20 s to start, 8,000 characters of output; a script reaches only what Jean hands it ([Codemode](#prompt-tools-and-caching)).
- **Pyodide** needs `'unsafe-eval'` as it starts (Emscripten builds some functions with `eval`); with nothing to steal and nowhere to send it, that costs nothing. Its files are Jean's own pinned copy (D43), sent in like QuickJS's; its `fetch` serves only those, under an address that never resolves. `import js` reaches only Jean's `fetch` and what pyfetch needs. Its memory and time can't be capped without cross-origin isolation, so the parent's watchdog stops a run that goes quiet; 60 s to start.

|---|---|---|

| Send and receive over the internet | off | `connect-src`: any https site (`*`), or only the sites listed, each added with Enter: `example.com`, `*.example.com`, `*.com`, and this computer over http (`localhost:3000`, `localhost:*`) |

## Languages (i18n)

- **Strings** live in `locales/<lang>.json`, English the source, with `{name}` placeholders. Plurals use `Intl.PluralRules` (Arabic has six forms); dates, numbers, lists and relative times use `Intl`; language names come from `Intl.DisplayNames`, each in its own language.
- **Choosing.** `preferredLocales` matches `navigator.languages` to the catalogues by language and likely script (`Intl.Locale.maximize`), so `zh-TW` finds `zh-Hant`, `pt-BR` finds `pt` and `iw` finds `he`; the menu lists those matches first, under "Your languages".
- **One catalogue per person, in parts** (D76, D97). `useLocale()` fetches only the chosen language, English only when that fails. The dialogs' strings are `locales/dialogs/<lang>.json`, loaded with `useStrings('dialogs')` by `ui/dialogs.js`, which every module showing a dialog imports. A capability whose strings would weigh on the first load has its own part, `locales/<id>/<lang>.json`, loaded with `useStrings(id)` and cached with it. The first-load budget counts the largest first part; each part has the per-file budget.
- **Instant switching.** The locale is a signal, so every bound text re-renders; `<html lang dir>` flips, and CSS uses logical properties only, so right-to-left mirrors at once.

## Prompt, tools and caching

Four mechanisms from pi 1.0, fitted to Jean, share one idea: what the brain has read never changes, so providers can cache it and the device's runtime can keep it in memory.

**A frozen prefix** (D46). When a conversation starts, Jean fixes the system prompt and the declared tools, and neither changes until it ends. Providers cache by prefix (Anthropic reads tools, then system, then messages), so one changed byte at the front re-bills the whole conversation; on the device, the same rule keeps the KV cache between turns.

**System notes** (D46, D81). A change mid-conversation (language, rules, instructions, memory, skills, the project, new tools, the date) is a note appended to the transcript where it happens.

- **Sections.** The project, instructions, memory, skills, connections (`<connections>`, D89), the folder (`<folder>`: its name, top level and four tools, and its `AGENTS.md` when the user took it, D152) and the page on show (`<page>`, D140) are sections of the frozen prompt, each asked for the task the message goes to (`sections(task)`, null for a new one on screen: a task out of sight has its own folder and no page, D317); each has a fingerprint (FNV-1a), and one that changed arrives whole in a note ("The <memory> section is now: …").
- **Notes a message comes with:** "Since last time" starts with when the user was last here (D101); the terminal's commands, with their exit codes and output (D166); what / and @ named in it, a skill with its steps, an earlier task as it went (D199).
- **Recorded:** a note is an ACP extension update (`_system_note`) in the conversation's JSONL, holding the English the brain sees and data for the UI's label, so replaying the file rebuilds what the brain was told, and when.
- **Rendered per adapter:** for Anthropic, a `system` message after the next user message, on models that take one; for OpenAI and OpenRouter, a `system` message where the note falls; for other servers and the device's brain, whose templates allow a system message only at the start, a tagged block at the top of the next user turn.
- **Never deleted:** removing a note is an edit, which breaks the cache from there on.

**Deferred tools** (D47, D63, D64, D104). A conversation declares the tools unlocked when it started; anything later is deferred, including every connection's tools.

- `find_tools` and `offer` come from the `discovery` capability, always loaded, so every conversation declares them. `find_tools(query)` ranks undeclared tools by name and description with BM25 and returns up to five signatures (`name({ file: string, pages?: string }): what it does`).
- A capability turned on mid-conversation adds the note "New tools can be found with find_tools: …" (`data: { kind: 'tools', added }`).
- A tool the user turns off (`off`, Web search's switch, D304) is declared by no conversation started meanwhile, and stays declared where it was, so the prefix holds: that conversation is told it is off, then on again (`data: { kind: 'switch', off | on }`), the loop refuses its calls, and `find_tools` never offers it.
- With `javascript` declared, deferred tools are called from a script and the declared list never changes. Otherwise `find_tools`, or an accepted offer, declares them from the next request on, recorded as `_meta.declare` on the call, at the cost of one cache miss. A tool called by its exact name, as `<connections>` gives it, runs under the rules without being declared; a missing argument gets the signature back.
- A provider's native deferral (Anthropic's `defer_loading`) may replace this later, with the same behaviour. The next conversation declares a newly unlocked capability's tools directly; connections' stay deferred.

**Codemode** (D48). `javascript` runs a snippet in QuickJS on the conversation's computer; top-level `await` works, and the result is what the script returns or its last expression. Inside, Jean exposes what the user has granted, and nothing else:

| Global | What it does |
|---|---|
| `file(name)` | A shared file's whole text (spreadsheets as tab-separated rows), or a file of the conversation's folder, through the hidden `file` tool |
| `csv(text)` | CSV or tab-separated text as rows: objects keyed by the header, numbers as numbers. The separator and quoted cells as `csvRows` reads them; the header is the first row of two filled cells or more, past a title line |
| `tools.<name>(args)` | Any granted tool, deferred and connection tools included; not `bash`, `javascript`, `python`, `offer`, `delegate` or `ask_user` |
| `fs.readFile`, `fs.writeFile`, `fs.readdir` | The computer's files: /workspace, kept after the run (D162) |
| `fetch(url, init)` | The internet, through Jean, as Settings › Computer allow |
| `searchTools(query)` | `find_tools`, from a script |
| `models.decide(state, questions)` | Kev on the device when Intuition is on, through the hidden `decide` tool |

Every nested call goes through the rules (`ctx.call` in `core/loop.js`); a call that needs approval pauses the script, and the wait doesn't count against its time. Nested calls carry `_meta.parent`, show under their call, and stay out of the brain's context, since the script's result holds what matters. Each crosses to Jean as a message and Jean makes it with its own keys, so the sandbox never sees a secret. Declared tools stay callable directly, because small brains call tools more reliably than they write scripts.

**Thinking blocks are kept** (D54) on each step's brain entry and replayed unchanged to the model that wrote them.

**A conversation near its window is summed up** (D359, `caps/compact/`), the way Anthropic's "simple compaction" does it, for every brain. `runAgent` gives the turn its brain's window (as files get theirs, D55) and what it last read and wrote; before each step, `turn.compact` asks Compaction, which loads the first time a conversation passes half its window (a local server's: half of 4,096, its smallest). Its size is the last request's usage plus Jean's estimate of what came since (a third of the bytes), or the estimate alone, and the larger of the two on a local server, which may count only what it kept; Ollama (`/api/ps`, loading the brain with `/api/generate` and no prompt when it isn't) and LM Studio (`/api/v1/models`, `loaded_instances[].config.context_length`, else `/api/v1/models/load` with `echo_load_config`) are asked the window they gave their brain, once past 3,072 tokens, and the answer is kept for the page's life. Past 75%, the same brain is asked, on the same system prompt, tools and history plus one request in English, for a summary in the conversation's language: a cache hit over the whole history, and local when the task is. The record is ACP's `compaction_update`, appended with the step it comes before, `completed` with a ULID for `compactionId`: its `summary` is the brain's, for the user to read, and `_meta.text` holds what the brain reads from then on, as the user's message: the summary, then what Jean knows for sure, the sources and files by number (D71, D55), the latest note of each kind in force, the plan as it stood (D364), and the request being worked on, word for word, with the notes it came with, and what the user said since to steer it (D365); `_meta` also says why (`reason`), by which brain and what it cost (`usage`). `toChatMessages()` starts at the last one, the loop replaces its history with it, and the turn goes on, so no thinking block is bound across it, nothing waits (D212), and the frozen prefix still holds: tools and system stay cached, the messages miss once. A request too long before anything came (`too_long`: Anthropic's "prompt is too long" and 413, OpenAI's "maximum context length", Gemini's "maximum number of tokens", a local server's "context size") is summed up once and asked again, with what calls brought in cut short if the summary itself doesn't fit; a second one shows the error. A local server's request past the window it gave is held until it says how much it read: far less than was sent means it cut, which counts as too long. The room shows the conversation whole: the request that wrote the summary is a line of the activity ("Summarizing the work so far, to make room…"), and a line above the answer says the earlier work was summarized, which opens on the summary, to read only. Going back before a summary removes it with the rest (D188), and duplicating copies it (D230). Helpers' and flow steps' turns have no window, so they never are.

**Caching and warming on Anthropic** (D49). One `cache_control` breakpoint on the system prompt's last block, plus top-level automatic caching for the conversation. When the user starts typing after about 5 minutes without a request, Jean sends the same prefix with `max_tokens: 0`, unstreamed, with the real request's thinking and effort, its breakpoint on the last message already there; skipped below the model's minimum cacheable size. OpenAI caches by itself; local servers keep their KV cache, which the frozen prefix keeps valid; the device's brain reads only what follows the text it already read (D58), a long prompt 2,048 tokens at a time, each part going into the cache before the next (D350).

## Retrieval and extraction

- **Extraction:** DOCX, XLSX and PPTX through the tag scanner; PDFs with pdf.js, on demand. A spreadsheet's date cells read as dates (`dateStyles`), and each page of a long sheet names its columns. A PDF page's text is joined by `pageText` (`caps/files/extract.js`, which node runs too): a right-to-left line in reading order (pdf.js gives each word right but the words as drawn), Arabic presentation forms, Kangxi radicals and compatibility ideographs as the letters and characters they stand for, a line wrapped between Chinese or Japanese characters or a code cut at its hyphen joined again, and lines set larger than the size most of the document is set in marked as headings (`#` to `###`), a heading wrapped over two lines as one. Pictures (PNG, JPEG, WebP, GIF), dropped, pasted, picked or captured from the screen (one frame of a shared screen, window or tab), show themselves in the request, read from the project's files only once on the page (`ui/shown.js`, as Pictures reads those Jean made), are kept no larger than 1,568 pixels a side and go to brains that can see, right after their `<document>` tag (`image_url` for Chat Completions, an `image` block for Anthropic); a brain that can't is told there is one (D105). So is a scan, a PDF whose pages have no text: `pagesSeen` (`caps/files/pictures.js`) has pdf.js draw its first twenty pages as JPEGs of that size, and a brain that can't see is told it is a scan (D479).
- **A shared file in the message** (D24, D55, D301): a document that fits in about 25% of the brain's context goes in whole; otherwise its first pages do, or for a brain of 32k or less its page 1 and the pages that match the message, and `read(file, pages)` reaches the rest. The choice is made once, when the message is sent, and recorded on the file's link (`_meta.pages`, a list of page ranges). Tokens are estimated as UTF-8 bytes / 3. Past conversations are searched with BM25 (`recall`).
- **Searching inside documents** (D24, D301), in core: `passages()` cuts a document's pages into passages of about 100 tokens, never across a page, where a line ends or a heading starts; each carries the path of the headings above it (or its page's first line that reads like a heading and isn't a running header) and a table's column names. `lexicon()` indexes them once, in typed arrays, by folded words and codes kept whole (C-4471 as well as c and 4471); `lookup()` ranks across several files' indexes as if they were one. `preselect()` picks, for a brain too small for a file, the pages that best match the message instead of the first ones: a brain of 32k or less gets them, as page ranges in `_meta.pages` (D301). The files capability declares `search_files` (`caps/files/search.js`), which gives the best passages with their file, page and source number, or every place a phrase is, case, accents and line breaks aside, counted (`every()`). A file's passages and index are made the first time it is searched and kept as `.cache/words/<file's hash>.idx` (`indexed()`): a JSON header with the format, the terms and the headings, then the numbers; one in another format is made again. Search by meaning reads its passages there too. It and `read` reach every file of the project, the conversation's own first on a name: the capability keeps the library's list as @ lists it (`library()` in `ui/complete.js`), again when the project changes or files are added.
- **Search by meaning** (D302, `caps/meaning/`), a capability of its own, offered by the brain when `search_files` finds nothing by words (the tool's answer says it may). Turned on, it downloads EmbeddingGemma 2's text model, about 175 MB once, on WebGPU only (q4f16 with `shader-f16`, else q4): both graphs keep the vocabulary quantized with an operator ONNX Runtime's WebAssembly lacks (`GatherBlockQuantized`), so where there is no WebGPU it isn't offered or in the house. In Chromium on an M-series Mac it reads about 80 passages a second (q4f16), 49 in q4: an 800-page file in 2 to 3 minutes, a 4,200-page one in 11 to 18, and its worker (`embed-worker.js`) leaves the vision and audio encoders out. Each file of the project is read, in the background, into a vector for each of the passages `search_files` cuts (prefixed `title: none | text:`), 768 numbers in a byte each, kept as `.cache/meaning/<dtype>/<file's hash>.i8`; a question's vector (`task: search result | query:`) is compared with every passage's, a flat scan, no index. `search_files` then fuses the best 200 by words with the best 200 by meaning by their ranks (reciprocal rank fusion, k = 60). A search waits up to 3 s for files still being read, then goes on without them. On the document evals' L files (506 questions, three seeds), words and EmbeddingGemma 2 find 91% of the evidence within 32k tokens and 88% within 8k, multilingual-e5-small 88% and 81%, harrier-oss-v1-270m 91% and 80%, Qwen3-Embedding-0.6B 87% and 80%, granite-embedding-97m-multilingual-r2 84% and 72%, and words alone 73% and 62%; on questions in another language 94%, e5 83%; at the 4,200-page size, 89% and 84%, e5 81% and 75%. It ties EmbeddingGemma 300m, whose terms are Gemma's where its are Apache 2.0, and 4 bits cost it nothing measured.
- **What the document evals found** (D24, D301): `test/documents/results.md`, a fictional company's files up to a 4,196-page PDF of 4.3M tokens. For a 32k brain, the matching pages answered every lookup and the first pages none (H7); at that size the first pages hold 12% of the evidence within 32k tokens, lexical search 66%. A large brain searching for itself is right on 79% of ten questions of each kind, wrong as if true on 4%, and says so on every question about something absent. A flat scan of vectors stays fast up to 5–8 times that size (H1). That file's index takes 2.5 s to make in Chromium and 10.9 s on a computer four times slower, and 60 ms and 0.3 s to read back from `.cache/`, for 22.5 MB (H6). Embeddings earn their place for meaning (H4 refuted: on paraphrases and other languages, lexical search answers 20 points below hybrid).
- **The document evals** (`test/documents/`, `npm run documents`): a fictional company's files made from a seed at five sizes, the largest a 4,196-page PDF of 4.6 million tokens printed by Chromium, in every format Jean reads and four languages, with nine kinds of questions whose answers and evidence are known. `npm test` checks the corpus itself (each answer's evidence found once in the text Jean extracts, in every format); the runner scores each strategy on the evidence it hands over within a budget, and OpenRouter's brains answer through Jean's own loop and tools (a paid Nemotron 3 Super held to one provider, a free small one), graded without a brain. ## jean-cli

`cli/` is Jean outside the browser, on Node 22 or later, published as `jean-cli` (D241), for the editors that speak ACP (Zed, JetBrains, Neovim, Emacs). `main.js` reads the command, and the terminal's language (`LC_ALL`, `LC_MESSAGES`, `LANG`, then the system's) picks `cli/locales/`'s.

- **`jean-cli acp`** (`acp.js`): ACP on its input and output through `rpc.js`, JSON-RPC a message a line, requests answered side by side so `session/cancel` is heard during a prompt; anything printed goes to the error stream. `session/new` makes a conversation (`createConversation`) in the folder `--folder` names, which must hold Sync's `mirror.json`, in the project whose `folder` is the editor's folder's name, else the home one; its ULID is the session's. `session/load` reads one back and tells it again as updates, a call's later records as `tool_call_update`. `session/prompt` keeps the files the prompt shares (a file the editor names, its contents, a picture) as the project's (`addFile`, the pages that fit decided then), then the prompt or the notes since and the request, and runs `runTurn`: its updates go out as they are, but for brain entries (`brain-…`), notes and an answer's `<suggestions>`, cut as it streams with `splitSuggestions`, and a diff's or a location's path goes out in full; a summary (`compaction_update`, D359) goes only to an editor whose `clientCapabilities.session.compaction` says it takes them, as ACP asks, live and on `session/load`, without `_meta.text`. A question is `session/request_permission`; "always" and "never" set the rule of a kind not kept to a folder, as in the browser. `max_steps` ends as `max_turn_requests`, a stop as `cancelled`, and a brain's error is worded as the browser words it. `settings.json` at the top of the folder, which `carried()` leaves out, is this computer's: `device` (who writes), `rules`, and `always` by folder.
- **Tools** (`tools.js`): `list`, `find_in_files`, `open` and `change` on the editor's folder with `caps/folders/work.js`, whose `SPECS` and `USE` are what the capability tells the brain too. Listing and searching read the disk (`nodeFS`, writing in place there); opening and changing a text go through the editor when it offers `fs` (`fs/read_text_file`, `fs/write_text_file`), so its unsaved changes count. A change is checked against what was read (`lastRead`) and asked with its diff unless always allowed in that folder. `bash`, when the editor offers `terminal`, runs `bash -c` there (`terminal/create`, `wait_for_exit` within two minutes, else `kill`, then `output` and `release`), its terminal shown on the call while it runs and after; JavaScript and Python never run there, only in the sandbox. `read`, `recall`, `remember` and `skill` work on the project's and the person's files, `read` and `recall` as the browser's own (`readTool`, `recallTool`) and `skill` with `skillSteps`; the editor's MCP servers (`connect()`: a program, spoken to with `rpc.js`, or an address, through `mcpClient`) give deferred `<server>_<tool>` tools, with `find_tools` and `<connections>`.
- **The brain** (`brain.js`): `--brain <provider>[:<name>]`, with `--address` for a server of the user's, else the first provider whose key is in the environment (`<PROVIDER>_API_KEY`, `HF_TOKEN`, `AI_GATEWAY_API_KEY`), those with a brain of their own first, else Claude Code once `claude auth status` says it is signed in: `bridge()` on a free port of 127.0.0.1, with a key made for it, as a `claudecode` brain. `--brain copilot` and `--brain chatgpt:<name>` are the other plans' brains the same way (D262), ChatGPT's with the sign-in Jean's bridge keeps on this computer. It is chosen at the first prompt. Keys come from the environment only, never from a file.
- **`jean-cli gateway`**: `gateway/gateway.js` behind `gateway/serve.js`'s listener, `--origin` added to `GATEWAY_CONFIG`'s origins, on `--port` (8787) and `--host` (127.0.0.1); it answers Private Network Access for the origins it serves, so Jean's own address reaches one on this computer.
- **The package** (`npm run cli`, `scripts/cli.js`): every module `cli/main.js` reaches, statically or through the `import()`s it lists, copied as written and where they are (Jean's own under `app/`) into `dist/cli/` with `cli/locales/`, `app/brand.js`, `LICENSE`, `cli/README.md` and a `package.json` (`bin: jean-cli`; `@preact/signals-core` and `marked`, the two runtime dependencies those modules import). `cli/locales/` holds the approvals' names and the brains' errors copied from each catalogue, the rest translated, outside `app/` so the web never ships them (D243).

## Voice

- **Speech to text** (D56, D61, D110, D205, D374): the browser's on-device recognition where it works, never its cloud recognition, otherwise a worker: Whistle (Cactus Compute, Apache-2.0, ~18 MB) in English, German, French, Spanish, Italian and Dutch, Whisper base (~80 MB) through Transformers.js in the other languages. Measured on 24 test recordings per language, Whistle made as few errors as Whisper base or fewer in those six and more in Polish (35% against 28%), was 3 to 10 times faster, and gave no words for silence where Whisper invented some. Clips over 30 s are cut at their quietest moment. Both write as the user speaks (`caps/voice/passes.js`, under `node --test`): the microphone comes through an AudioWorklet (`caps/voice/capture-worklet.js`) in a context at its own rate, since Firefox connects it to no context at another, which brings it to 16 kHz in frames of 96 ms, each sample the mean of the input over its span, so frames meet with no seam; what was said since the last pause is written again each half second, then kept once a pause of 0.8 s follows it, so no pass grows long; 14.4 s with no pause is cut at its quietest frame. A frame is speech when louder than three times the quietest one heard, kept between 0.004 and 0.03, and silence is never written, so Whisper invents nothing there. Whisper reads a padded 30 s each pass, about 2.5 s on WebAssembly, so its words come in steps, Whistle's every half second; a pass that ended in a pause keeps its words even if speech came again while it ran. A session that ends in an error or no words moves to the model for the visit; the browser's own download gets 15 s, its stop 2 s.
- **Text to speech** (D109, D114): `speechSynthesis` with local voices only, each answer in its own language, by the voice `rankVoices()` in `ui/language.js` puts first: the user's pick, then their variety, natural voices before compact ones, novelty voices last; `ui/language.js` guesses the language offline, and with no voice for it, Jean says so.
- **The natural voice** (D455, `caps/reader/`): Kyutai's Pocket TTS (its weights CC BY 4.0, each voice's recording CC BY 4.0 or CC0), read through ONNX Runtime on one WebAssembly thread, in the six languages Kyutai documents (`NATURAL` in `ui/voices.js`): English, German and Portuguese in Alba MacKenna's voice, French in Stuart Bell's (a LibriVox reader's, from Voice-Zero), Spanish and Italian in Common Voice's Lola and Giovanni; German's and Portuguese's own voices state no licence, and Alba's was as clear in them; Stuart Bell's was preferred by ear to Kyutai's own Estelle, and Whisper misheard fewer of its words (5.6% of FLEURS's, against 6.3%). `ui/voices.js` hands an answer in one of them to it once its language is here (`natural.read`), and from the third answer read aloud in one of them, an event has `ui/discovery.js` offer it. A manifest pinned by SHA-256 pins the rest: one binary for the decoder every language shares (about 11 MB), one per language (about 97 MB) holding its three graphs, their large weights as 8-bit numbers with an fp32 scale per output channel, its voice's state (the prompt's keys and values, as Kyutai's predefined voices hold them) and its tokenizer. The worker (`reader-worker.js`) keeps one language loaded, its weights expanded to fp32 at load: on WebAssembly the fastest of fp32, fp16 and ONNX Runtime's 8-bit graphs, and faster than WebGPU, which pays for each of its steps. Its text first has its numbers in words (`words.js`, under `node --test`), as the model learnt to read them: in digits, or beside a symbol such as €, it stumbles and loops. Amounts take their currency's name, measures their unit's and dates their month's, all three from `Intl`; times, ranges, decimals, arithmetic (signs, powers, roots, a fraction's bar, minus beside a figure, 3 x 4), French and English ordinals and English and German years (nineteen ninety, neunzehnhundertneunzig) are written out too, and each line ends a sentence, without its bullet. Then it goes as pocket-tts 4.0.0 sends it (`pocket.js`, under `node --test`, and the same ids as Kyutai's for every round-trip sentence): characters the language wasn't trained on replaced, sentences cut at the tokenizer's marks but decimal points, those over 100 tokens at their commas, joined up to 100, a capital first and a final mark; ids by its SentencePiece Unigram model, a character it lacks as its bytes. pocket-tts joins up to 50, but each chunk is read afresh from the voice's state and ends as a sentence does, so its cuts at commas, which most French sentences of 30 words had, were heard as stops; 100 keeps the voice's prompt, the text and the frames it may make within the 1,000 its graph holds. Each chunk starts from the voice's state; a frame is the main graph's step, Gaussian noise of variance 0.3 and one flow step, until 1 to 3 frames after the end-of-speech logit passes −4 (6 frames at least); the decoder runs on 2 frames, then 4, then 12 once 24 are out, so the first sound comes soon and the rest keeps ahead, faded in over 5 ms. The worker takes one request at a time, and gives its event loop a turn after each frame: ONNX Runtime's runs settle without one, so a stop would otherwise wait for the whole answer, and the next reading behind it. The page plays the pieces back to back in an `AudioContext` made in the click, or for Live conversation in Live's own, which its microphone keeps running: Live hands it each sentence as it is ready (`natural.live`), queued after the last, and silences it when the user speaks over Jean. On an M3 Max, a language loaded from the cache in 0.7 s in Chromium and 1.9 s in WebKit, the first sound came 0.18 to 0.26 s after the click, it was made 2.1 times faster than it lasts in Chromium and 2.3 in WebKit, and Whisper misheard 2 to 6% of FLEURS's words, 4 to 11% in its sentences with figures, which read as digits had 14 to 23%; these graphs and Kyutai's are within 1e-3 a step. The first language downloads when the user takes it; another is offered, by a notice, the first time an answer in it is read aloud with its voice not here. Settings › General turns it off (`naturalVoice` in settings) and credits Kyutai and Alba MacKenna.
- **Live conversation** (D93, D374): dictation's AudioWorklet feeds 16 kHz frames of 96 ms, three of Silero's 32 ms, made from the microphone at its own rate, to Silero voice detection (~2 MB), in a worker of its own so that a turn's end is heard on time rather than behind a pass of Whisper → Whistle or Whisper, written in the box as the user speaks through dictation's passes, the box showing only the turn being said → the brain once the turn ends, streamed → read sentence by sentence, by the natural voice where it is on and reads the answer's language, else by the system's voices. A turn starts after 250 ms of speech, with the 0.7 s before it, and ends after 800 ms of silence, by when its words are mostly written; speaking over Jean for half a second interrupts it. `caps/live/turns.js` holds the turn-taking, tested under `node --test`.
- **Real-time speech models** from providers (OpenAI Realtime over WebRTC, Gemini Live) could come later; `wss:` is already in `connect-src`.
