# Architecture

How Jean is built, as it is now. Why each choice was made, and what was rejected, is in [decisions.md](decisions.md), cited here as `Dnnn`.

## Principles as rules

| Principle | Rule that can be enforced |
|---|---|
| KISS | Hard limits in [budgets.json](../budgets.json), checked in CI. Going over means deleting something first. |
| Portable | All data is plain files: Markdown, JSONL, `SKILL.md` folders. Export is a zip; import is dropping a folder. |
| Universal | Standards, not adapters: OpenAI-compatible and Anthropic Messages, MCP, Agent Skills, ACP events, the Jev-style Decisions API. |
| Browser-ready | Static files, offline after the first load, opened from a link. |
| System-agnostic | `core/` uses only standard web APIs and runs unchanged in a browser, a worker, Node, Deno or Bun; its tests run under `node --test`. |
| Incremental | Capabilities are discovered as situations call for them, offered by Jean, granted by the user, and only then loaded. |

## Stack

**No build step** (D9). Plain ES modules and an import map; types in JSDoc, checked by `tsc --noEmit`. Deploying means copying `app/` (D243), and view-source is the source.

**A first load without a bundle.** `npm run manifest` writes a `<link rel="modulepreload">` into `index.html` for every module the first load imports, so the browser fetches the graph in one round trip; CI fails if the links are stale. The first screen loads only what it draws (D76, D94, D148): the dialogs, the Anthropic adapter, the loop and the other adapters, Auto, and what a message needs on its way (`ui/send.js`) load when first needed, sending as soon as the user types.

`vendor/`, `capabilities.json`, `manifest.webmanifest` and a copy of `LICENSE`, all in `app/`, are made by `npm run dev`, `start`, `build` and `check` from Jean's own `node_modules` and the root's licence, and never committed (D43, D51, D52, D74, D243).

**Built on the browser, no dependency:** text from DOCX, XLSX and PPTX (zip through `DecompressionStream` and a small tag scanner, not `DOMParser`, so it runs in workers and under `node --test`); the backup zip (`CompressionStream`); BM25 search with `Intl.Segmenter`, which ranks deferred tools and past conversations, and `alike()`, which tells requests of the same kind apart (`core/search.js`), plus matching as people type over a fold of the text (`fold()`, `ranges()`, D133); ULIDs from `crypto.getRandomValues`; the system's voices; Web Locks and BroadcastChannel between tabs.

**Routing is one hash** (D59, D137, D220), read by `ui/router.js`: `#/c/<ulid>`, `#/p/<project ulid>/c/<ulid>` in a project other than home, `…/settings/<section>` with Settings open over either, and after a `?` the windows beside it, in the order they opened, each `name` or `name=state` (its slashes and colons as they are): `preview=files/<file>`, `browser=<address>` (`folder:`, `workspace:` and `made:` for Jean's own pages), `terminal`, `flow=<flow ulid>` (flow mode on a new task, the pane beside a task) or `flow=task`. `ui/windows.js` keeps them: each window's module calls `keep(name, { get, set })` as it loads, `get()` saying what it shows (null closed), `set()` showing a state again after checking it. Following an address, it waits for `app.ready`, closes the windows not named and those out of order, then loads each named window's module (once its capability is found) and sets it, giving the keys back where they were. The router writes the windows into the entry it is on, and follows them only when an address leads to another place.

**Components are custom elements** (light DOM, prefix `app-`). Each capability is one module that defines its elements and registers its tools; unlocking it is an `import()`, and any of its elements already on the page upgrade. `:not(:defined)` styles what isn't discovered yet.

## Brand

```js
// brand.js — the only place the name lives
export const BRAND = Object.freeze({ name: 'Jean', domain: 'jean.is' })
```

- **For display only** (D4): UI strings (`{name}`), the system prompt, the page title and the web-app manifest. The wordmark is the name set in the display face, so there is no logo file to redo.
- **Never in anything that persists:** storage keys, OPFS paths, cache names, element prefixes, CSS classes, the desktop app's identifiers. Renaming changes one line and moves no data.
- **The assistant's name is a setting:** `settings.assistantName ?? BRAND.name`, which a project can override (D102).
- **Grammar:** translations never make a word agree with the name; in conversation, the brain handles grammar itself.
- **The origin is not a variable.** Storage belongs to the domain, so it is settled before the public launch (D27).

## Core

- **`loop.js`**: stream the reply, run tool calls, feed results back, repeat. Rules (Do it / Ask me first / Never) are checked before each tool runs, calls from scripts included. The prompt and declared tools are frozen for the conversation; changes arrive as notes ([below](#prompt-tools-and-caching)).
  - `tools` is every tool that can be called, and may be a function read again at each step, so a capability turned on mid-turn can be called at once. `declared` is what the brain sees; `hidden` tools are never declared (D64).
  - A tool's `check` runs before a call the rules don't refuse: it can ask even where they allow (a change in the user's folder) and give the card what it shows (ACP `diff` content). `ctx.content` is kept on the call's record before its result; `ctx.answer` is what the user answered (D152).
  - Sources are numbered from `firstSource`: tools call `ctx.cite()`, the brain's own search sends `cite` events that become ` [n]`, and both are recorded as `_meta.sources` (D90). `ctx.meta` records more (a picture). `ctx.progress()` says how a call is coming while it runs, a `tool_call_update` with `content` and `_meta` (the call's own, and more) that is shown and never kept (a picture as it forms, D265). A provider's `pause` (Anthropic's `pause_turn`) is sent back and resumed.
  - `ctx.turn()` runs a helper's child turn with the same brain, rules, approvals and source numbers, its own prompt, history and tools; its records nest under the calling tool's (ids prefixed, `_meta.parent`, no thinking blocks) and its text is the call's result (D98).
  - `meta` on the brain entry says why Auto chose it (D70).
  - A request that fails before anything of its answer came is asked again after 1, 2 and 4 s, or after the provider's `Retry-After` when longer, up to 30 s, if the error may pass (`LLMError.retryable`: the connection, the provider busy or its server failing, and the browser offline, which looks the same as a refused cross-origin request; never the device's brain). Meanwhile the brain entry has `_meta.retrying` and the activity says "Trying again…". Once part of an answer came, or after the last wait, the error shows with Try again (D202).
- **`llm.js`** and **`anthropic.js`**: the OpenAI-compatible Chat Completions and Anthropic Messages adapters, over fetch and SSE (`sse.js`); together they reach almost every model. `llm.js` imports `anthropic.js` when an Anthropic brain is first used. Anthropic from the browser needs the `anthropic-dangerous-direct-browser-access: true` header; OpenRouter's PKCE sign-in (`oauth.js`) runs entirely in the browser. A `claudecode` or `copilot` brain is an Anthropic one, and a `chatgpt` brain an OpenAI-compatible one, whose address is This computer's bridge, which runs the user's own Claude Code or Copilot, or signs in to ChatGPT (D235 · D262). OpenRouter weighs the credits left against the longest answer a brain may give, which Jean leaves unsaid; when they fall short it answers 402 with how many tokens they cover, and Jean asks again for that many. Any other 402, or Anthropic's 400 that says the credit balance is too low, is `credits`: the error says the brain is out of credits, to add some or choose another brain, with Check the brain beside Try again, and isn't tried again by itself.
- **`events.js`**: the ACP records and their envelopes ([Activity events](#activity-events)), `splitSuggestions()` (D69), `versionsOf()` (D164), `isPicture`.
- **`prompt.js`**: the base prompt, the frozen sections and the notes that change them (D46, D81).
- **`deferred.js`**: `find_tools`, tool signatures, and `reach`, which says how to call a tool that isn't declared (D63, D104).
- **`rules.js`**, **`settings.js`**: the rules and their defaults; settings resolved as defaults ← user ← policy, `DEFAULT_URLS`, `PROVIDERS`, projects.
- **`fs.js`**, **`files.js`**, **`conversations.js`**: storage, shared files (original, text and metadata, source numbers), transcripts.
- **`search.js`**: BM25 over short texts, `alike()`, and matching as people type (D133).
- **`decide.js`**: Kev's input and answers in the Decisions API's shape; the questions themselves are in `caps/reflexes/questions.js` (D62).
- **`memory.js`**, **`skills.js`**: the `memory.md` format and the lines that fit (D79); `SKILL.md` folders, of which only names and descriptions go into the prompt (D83, D121), the kinds of block each declares (D196), and the metadata each came with, kept when it is saved (D222).
- **`i18n.js`**, **`zip.js`**, **`ulid.js`**.

## Brain ladder

1. **On this device:** Gemma 4 E2B, q4f16, through Transformers.js on WebGPU: native tool calling, 140+ languages, image and audio input. About 3.1 GB for text, downloaded once with consent; the image and audio encoders follow when first needed. Offered only where it runs: WebGPU with `shader-f16`, 3–5 GB of memory while answering, enough free storage (D42). The download screen offers a free account alongside.
2. **One click:** OpenRouter sign-in, no key to paste.
3. **Advanced:** the user's own key (OpenAI, Anthropic, Google Gemini, Vertex AI, Mistral AI, OpenRouter, Vercel AI Gateway, Hugging Face, Groq, Cerebras, Together AI, Fireworks AI, xAI; D136), or a local server (Ollama, LM Studio, any OpenAI-compatible endpoint).

Not used: the browsers' built-in models (too experimental) and native OS models.

**Beside the page** (D285): a model on this device works on the GPU that draws the window, where each frame waits behind what was sent before it. `holdStill()` in `ui/model.js` holds the page still while the device's brain answers or a picture is made or checked here: it sets `--loops` on the root to `paused`, through CSSOM as `--warmth` is (D73), and every infinite animation takes its play state from it (`var(--loops, running)`), so only what changes is drawn, and an entrance still plays. `test/looks.test.js` checks that every loop does.

**One runtime, kept compiled** (D287): every model's worker imports `ui/model-worker.js`, which points ONNX Runtime at its WebAssembly (`vendor/transformers/ort-wasm-simd-threaded.asyncify.wasm`) and turns off Transformers.js's own copy (`useWasmCache`), so ONNX Runtime streams it from the file. Served from the service worker's copy, Chrome keeps what it compiled and optimized beside it, and the next worker, in this visit or a later one, starts from that. On `npm run dev` it keeps nothing (`no-cache`, no validators), so each worker compiles it.

**Kept to projects** (D194): a brain's `projects` keeps it to those projects, and without it the brain is in every one (`usedIn()` in `core/settings.js`, as for connections). `brainsHere` in `ui/state.js` is the room's project's, and Auto, the picker, `activeBrain`, Double-check, pictures and films, routines and Since last time read it; Settings › Brains lists every brain, one kept elsewhere unable to be chosen, and ticks where each is used (`where()` in `ui/dialogs.js`, which Connections shares).

## Reflexes

`decide(state, questions)` takes typed questions (`noul`, `choice`, `score`) and returns calibrated probabilities, in the Jev/Decisions API shape that Jev, Clef, Strands Decider, Laya, Kev, Ollaya and OpenRouter's `/api/alpha/decisions` share, so backends can be swapped. In the UI, reflexes are **Intuition**.

```js
// ui/discovery.js, with the questions from caps/reflexes/questions.js
const { demand, personal, capability } = await decide(message, {
  demand:     { type: 'score',  instructions: 'How demanding is this request?', criteria: ['a quick chat or a simple fact', 'reading, writing or summarising', 'several steps of work or analysis', 'expert reasoning'] },
  personal:   { type: 'noul',   instructions: 'Does the message share personal, health, financial or confidential information?' },
  capability: { type: 'choice', instructions: 'Which of these would help with this message, if any?', criteria: { compute: 'exact numbers, maths, or analysing a table of data', none: 'nothing new is needed' } },
})
```

| Backend | When |
|---|---|
| **Kev-0.6B** through Transformers.js | The default (D41, D67): q4f16 on WebGPU with `shader-f16`, otherwise q4 on WebAssembly; about 345 MB once, with consent; about 60 ms a message on WebGPU after warm-up |
| Jev through OpenRouter | Later, when a cloud brain is connected |
| Ollaya (a local server) | Advanced users, later |
| The brain itself, with constrained JSON | Last resort, later |

**How Kev is asked** (D67): all of a state's questions in one forward pass, each with its options between Kev's delimiters (ids from its `config.json`); each option's score softmaxed within its question; a score read as its most likely level, since Kev hedges toward the middle; a yes, or an offer, at 0.6. Each message gets one pass for demand, personal and capability, and a second for "unhappy" with the previous answer, both capped at 2.5 s.

**Measuring Kev** (D68, D84): `test/reflexes/<lang>.json` holds 44 labelled examples per launch language, machine-translated; `npm run reflexes` runs Kev on the CPU under Node with Jean's own questions and thresholds, and writes [test/reflexes/results.md](../test/reflexes/results.md). 67% overall: tables reliable everywhere, capability and email fine in the major languages, personal, unhappy and lasting near chance, the low-resource languages lowest. The next step, before launch, is a fine-tuned "Jean reflexes" checkpoint, published under Apache 2.0. The test set is the lasting asset.

**Measuring offers** (D284): `test/offers/<lang>.json` holds 43 requests in eight languages, each labelled with the capability the brain's `offer` should name, or none. `npm run offers` reads the frozen prompt and declared tools a first conversation sends, from the page in headless Chromium, then sends each request through core's loop to the brain `BRAIN` names (as jean-cli's `--brain`, its key in `<PROVIDER>_API_KEY`), Jean's first tools answering as they do, and writes a section per brain into [test/offers/results.md](../test/offers/results.md): per capability, how often it was offered when needed, what came instead, and how often it was offered when not.

| Question | Type | Status |
|---|---|---|
| Which capability, if any, would help? | choice | Built |
| How demanding is the request? | score | Built |
| Personal, health, financial or confidential content? | yes/no | Built |
| Is the user unhappy with the last answer? | yes/no | Built |
| Does this text compare numbers across several items? ("As a table") | yes/no | Built |

There is always a default project, hidden until Projects is discovered, so one code path handles everything.

- **Writes.** One storage worker writes with `createSyncAccessHandle` (Safari 16.4+, Chrome 108+, Firefox 111+; D12). Conversations are append-only, so a crash costs at most a half-written last line, ignored on read (going back to a request rewrites one whole, D188); files rewritten whole go to a temporary file first, then are swapped in.
- **Several tabs.** Web Locks serialise writes per file; BroadcastChannel tells other tabs to refresh.
- **Folders of the user's** (D141, D149, D152). A project or a conversation opened on a folder of the computer gets an `FS` of its own (`folderFS` in `ui/opfs.js`): a storage worker started on the folder's handle, writing in place with `createWritable`, without the temporary copy and without telling other tabs. `stat` gives a file's size and `lastModified`, which a change checks against what the conversation read. Handles live in IndexedDB's `app-folders` under the project's or conversation's ULID (a conversation duplicated from another gets that one's, D230), with the folders "Always allow" was given for; the folder's name is in `project.md` and `<folder>`, so a missing handle is asked for again by name. Tools work in the folder of the conversation that asked (D147). Outside Chromium, a folder is a read-only copy for the visit (`caps/folders/copy.js`), and what Jean changed is saved as one zip. Nothing of Jean's is written there.
- **Format changes.** Every file carries a `format` version, to be upgraded lazily when read once Jean has users; until the public launch nothing is kept for earlier shapes (D173).
- **Preventing loss:** `navigator.storage.persist()`; installing the app (Safari can wipe a site not visited for 7 days); backup offered early; Sync (D157) as a continuous copy in Chrome and Edge; usage shown in plain words; model weights evicted first, never user data.
- **What takes up space** (D177, Settings › Your data): `weigh()` in `core/files.js` totals Jean's files by kind (the projects' conversations, files and workspaces, and the rest); `ui/dialogs.js` adds the browser's caches by name, `transformers-cache` as the brains on this device, `app-cap-…-computer` with the Computer's workspace, the other `app-shell-` and `app-cap-` caches as the offline copy, each response by its `Content-Length` unless it came compressed. What `estimate()` counts beyond them is everything else's.
- **Secrets.** API keys and tokens are encrypted with a non-extractable `CryptoKey` kept in IndexedDB, and never exported, synced or shared. The key that seals certificates (D252) is kept there too (`deviceKey` in `ui/secrets.js`). Folder handles can't be encrypted or kept in a file; IndexedDB keeps them, never in a backup.
- **Layout rules that keep sync possible:** one file per entity, named by ULID and never renamed; attachments named by content hash; no central index of record; `author` and timestamps on every entity; only `core/fs.js` touches storage.

## Service worker

- **On install:** cache the shell (`sandbox.html` and `preview.html` included) and every locale file, so switching language is instant and offline. Files come through the HTTP cache and are checked against the integrity hashes in `capabilities.json`; a stale copy is fetched again. The install icons and screenshots stay out (D131, D168).
- **On unlock:** cache the capability's files, listed in `capabilities.json` with content hashes, with the modules of other capabilities it imports (the Computer's from Folders and Files), so it works offline on its own. The cache is the record of what has been unlocked.
- **On update:** download the new shell and new versions of unlocked capabilities only, then delete old caches. When the user lets it in, the new version takes the page's place where it was (`ui/update.js`, D138).
- **Model weights** live in their own cache, so an update never downloads 3 GB again.
- **Offline:** history, files and the device's brain keep working; with only a cloud brain, Jean says so.

## Security

Every HTML document has its own CSP in a `<meta>`, which works on any static host.

**`index.html`** runs only Jean's own code:

```text
default-src 'self'; script-src 'self' 'wasm-unsafe-eval' 'sha256-<import map>' 'sha256-<first paint>'; style-src 'self';
img-src 'self' blob: data: https:; media-src 'self' blob:; font-src 'self';
connect-src 'self' https: wss: http:;
worker-src 'self' blob:; manifest-src 'self'; frame-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none';
require-trusted-types-for 'script'; trusted-types lit-html app-urls
```

- **`connect-src` is broad** because users add any OpenAI-compatible endpoint, and untrusted code never runs in this document. Organisations tighten it with an HTTP header ([enterprise.md](enterprise.md)).
- **Plain HTTP reaches this computer alone** (D260). Before it reads anything Jean keeps, `start()` in `ui/app.js` adds a second policy, which holds as well: `connect-src 'self' https: wss:` and `http://<name>:*` for `localhost`, `127.0.0.1` and, in the desktop app, each of the computer's own IPv4 addresses; Settings › Web search reads that policy to tell what it can reach (`insecure()`). `addresses()` in `ui/host.js` reads them from what `ifconfig` writes (`ip` where there is none, `ipconfig` on Windows), run with `os.spawnProcess` and heard through its `spawnedProcess` events, waiting 2 s at most. A policy can only narrow, so an address the computer takes later (another network) holds from the next load.
- **`img-src` allows `https:`** for the site icons on web sources' chips, whose address is replaceable (D210). Answers never load an image: Markdown images are shown as text.
- **A runtime that needs `'unsafe-eval'`** gets a worker document of its own, never a looser `index.html`.

**`sandbox.html`**, framed with `sandbox="allow-scripts"` and never `allow-same-origin` (D65, D162):

```text
default-src 'none'; script-src 'sha256-<relay>' blob: 'wasm-unsafe-eval' 'unsafe-eval'; worker-src blob:;
connect-src 'none'; base-uri 'none'; form-action 'none'
```

- **No access to Jean's storage** (its origin is opaque) **and no network at all.** It holds only a small inline relay, allowed by its hash. `test/html.test.js` checks the hash and that the frame never gets `allow-same-origin`.
- **The parent sends everything in.** `ui/sandbox.js` fetches the worker's source and, when a run first needs them, an engine's files (listed in `capabilities.json`), and posts them to the relay.
- **Untrusted code runs only in a Worker** made from a `blob:` URL, so it inherits the sandbox's CSP; workers have no navigation, no WebRTC and no `sendBeacon`. It is a classic worker, since browsers refuse module workers from `blob:` in an opaque origin; it can still `import()` blob modules and compile wasm, and Emscripten gets `wasmBinary` and `wasmLocation` so nothing resolves against a `blob:` base.
- **QuickJS:** 64 MB of memory, 20 s of computing time (waiting on Jean or the user doesn't count), 20 s to start, 8,000 characters of output; a script reaches only what Jean hands it ([Codemode](#prompt-tools-and-caching)).
- **Pyodide** needs `'unsafe-eval'` as it starts (Emscripten builds some functions with `eval`); with nothing to steal and nowhere to send it, that costs nothing. Its files are Jean's own pinned copy (D43), sent in like QuickJS's; its `fetch` serves only those, under an address that never resolves. `import js` reaches only Jean's `fetch` and what pyfetch needs. Its memory and time can't be capped without cross-origin isolation, so the parent's watchdog stops a run that goes quiet; 60 s to start.
- **The internet goes through Jean** (D162): a request crosses to Jean, which judges it by Settings › Computer (`caps/computer/net.js`), asks first for a new site, and makes it with no cookies and no referrer, through the relay when there is one, adding a registry's key there. See [Computer](#computer).

**The preview** (D126, D143, D158) shows a web page in `preview.html`, framed with `sandbox="allow-scripts"` only, given nothing but the page and its policy. `preview.html`'s own policy is the most Settings can allow:

```text
default-src 'none'; script-src 'unsafe-inline' data: blob: 'wasm-unsafe-eval' https:; style-src 'unsafe-inline' https:; img-src data: blob: https:; media-src data: https:;
font-src data: https:; connect-src https: http://localhost:* http://127.0.0.1:*; frame-src 'none'; base-uri 'none'; form-action 'none'
```

Its relay, inline under `'unsafe-inline'` (a hash would turn that keyword off), writes a doctype, then the policy Jean sent as a `<meta>`, then the page, which keeps the document's policy and adds that one. `ui/csp.js` makes it, and the frame's `allow`, from five switches in Settings › Approvals, which `pages` in `policy.json` can set and lock:

| Switch | Default | Adds |
|---|---|---|
| Run its code | on | `script-src 'unsafe-inline'`; for a page whose scripts are data (the user's folder, the workspace, an Office file), also `data:`, `blob:` workers and pictures, and `'wasm-unsafe-eval'` |
| Go full screen | on | `fullscreen *` in the frame's `allow` (`*`: WebKit doesn't match an opaque origin to `'src'`) |
| Save files | on | Jean saves a file the page hands it, after a click |
| Load things from the internet | off | `https:` for pictures, sounds, fonts, styles and, when they run, scripts |
| Send and receive over the internet | off | `connect-src`: any https site (`*`), or only the sites listed, each added with Enter: `example.com`, `*.example.com`, `*.com`, and this computer over http (`localhost:3000`, `localhost:*`) |

- **A page in an answer** (D289) is framed the same way, under the policy of a page whose scripts are data. Sent with `open`, the relay keeps it open and writes the rest as Jean sends it, closing it once it is whole; it says how tall it is (a `ResizeObserver` on its root) and gives it `sendPrompt(text)` before writing it, which Jean takes only from that frame, on a click of the user's.
- **Copying** needs no switch: `allow` always has `clipboard-write *`, and `execCommand('copy')` works on a click anyway.
- **Saving goes through Jean.** The sandbox never has `allow-downloads` (WebKit takes a frame's download for a navigation, which `frame-src 'self'` refuses). The relay watches `URL.createObjectURL` before the page runs, and a `download` link to a `blob:` or `data:` address, clicked by the user or the page's code, hands the file to Jean, which saves it when Save files is on and the user has just clicked (`navigator.userActivation`).
- **No WebRTC** (D267). It sends to whatever server it names, whatever the policy says (no browser knows `webrtc 'block'`), so the relay deletes `RTCPeerConnection` and its prefixed names from the page's window before writing the page. That window is the only one the page reaches: a frame it opens gets an opaque origin of its own from the sandbox, so its window throws a `SecurityError`, pop-ups are refused, and a worker has no `RTCPeerConnection`. `document.open()` keeps the same window.
- **Nowhere to go:** no form, no pop-up, and `index.html`'s `frame-src 'self'` keeps the frame on Jean's addresses. `test/html.test.js` checks the policy each switch makes, which sites are taken as typed, that `preview.html`'s is the loosest, the relay's order, `frame-src 'self'` and the frame's one sandbox flag.
- **Word, Excel and PowerPoint files** (D183), and a CSV made a workbook by Jean's own writer (`makeFile`), are drawn in a frame of the same kind by `@silurus/ooxml`: a document's pages and a deck's slides scroll, with a text layer to select, and a workbook has its sheets' tabs. `caps/files/office.js` makes the page: the kind's modules from `vendor/ooxml/graph.json` as `data:` addresses under an import map, the parser as the viewer's `wasmUrl` (a `data:` address, decoded without a fetch) and the file as data. Its policy is a folder page's, so the parser's worker starts from a blob. With Run its code off, the file shows its text. In the preview, a workbook's page also has the box that changes a cell (D229): it sends the sheet, the cell, what it is to hold and where the grid was; `changeCell()` in `ui/view.js` checks it, changes what the file holds with `caps/files/cells.js` (which works the formulas using it out again) and appends a `cells` note for the brain; `ui/preview.js` keeps the changed copy with `addFile`, appends a `cells` note that the file on show (`was`) holds it now (`uri`), and shows it again where it was (`officePage`'s `at`). `latestOf()` (`core/events.js`) says what a file holds now, for the preview, a card's Save, `edit`, and Files' `read` and `file`. The browser writes a workbook of the folder or the workspace where it is, through the folder's `FS` or the computer's `workspace()`. The file shows again in a frame of its own, as the one on show would keep its page.
- **Every other file shows in Jean's own document,** from what Jean keeps: a picture as an `<img>` (a drawing's scripts never run there), a film or a sound with its controls, a MIDI file as the WAV Jean's own synthesizer makes of it (`caps/files/midi.js`, D197), a PDF's pages drawn by pdf.js, a Markdown file or a document Jean wrote laid out as an answer is, anything else as its text, through lit-html. A file that isn't text (a zero in its first 8000 bytes, as Git tells, unless it is UTF-16), or a picture, film or sound this browser can't draw or play, shows a note saying it can't be shown.
- **One way to show a file,** `viewOf()` in `ui/view.js`, with its style sheet: the preview gives it a file Jean keeps, with the text read from it; the browser a file of the conversation's folder or the project's workspace that isn't a page (D190).

**The browser** (D140) frames other sites' pages inside `caps/browser/browser.html`, a document with no script whose policy alone lets a frame show another site, so `index.html` keeps `frame-src 'self'`:

```text
default-src 'none'; style-src 'sha256-<its style>'; frame-src https: http://localhost:* http://127.0.0.1:*;
base-uri 'none'; form-action 'none'; require-trusted-types-for 'script'; trusted-types 'none'
```

- **A fresh frame for each address,** with no referrer, `sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox allow-modals allow-downloads allow-storage-access-by-user-activation"` and never top navigation, so the site keeps its own origin and storage but can't take Jean's place. It is the one frame with both of the first two flags: it only ever holds another site, never one of Jean's addresses, a blob or data; for another site, both flags are strictly safer than no `sandbox`. `test/html.test.js` checks the policy, that no other module combines them, and the absence of top navigation.
- **Jean's tab keeps to Jean while a page opens.** Arc puts a page that refuses frames in the place of the page around it, so until 3 seconds after a page loads, a navigation of Jean's tab to that site is called off (the Navigation API's `navigate`), and leaving otherwise asks first (`beforeunload`).
- **What Jean can't see:** a framed page's address once it moves on, its title, and whether it refused to be framed. Back walks the tab's history only while its entries are known to be the site's (`caps/browser/pages.js`); a fresh frame first drops what is ahead of Jean's entry. A way out, a new tab, stays under a site's page until the site is seen working. `browse` reads a page without cookies, only where the site allows CORS.
- **Jean's own pages** show at `<folder>/<path>` (the conversation's folder, D156) and `/workspace/<path>` (the project's workspace, D167; with a folder open, it leads to the folder), never in the sites' frame: in a frame of the preview's kind, with `data:` added to `script-src`. No service worker serves an opaque origin, and a frame of Jean's origin with scripts is never allowed, so `caps/folders/site.js` puts the page together: style sheets as `<style>` with their imports inside; scripts, pictures, sounds and fonts as `data:` addresses; modules through an import map of `data:` addresses, their relative imports made absolute first; and the data files its scripts name, served by a small `fetch` in front of the page. A `/` starts from the page's project, the nearest folder up holding a `package.json`, as its dev server would serve it, or else from the folder's top. Only files inside the folder whose names don't start with a dot. A page that only a build makes runnable (D277: a script or module in JSX, TypeScript, Vue or Svelte; a style sheet, or a file without its ending, imported; a package by its name, with no import map of the page's own) shows a note in its place naming the file, and comes again when its files change; This computer is offered, where its dev server runs (D198). A folder shows its `index.html`, or else its name and what it holds, which the browser draws in Jean's own document with `..` to go up; any other file comes back as its bytes and type, and shows as in the preview, by `ui/view.js` (D190), its web links opening in the browser. Only pages need the frame, so the rest shows even in an app's pane that refuses it. The relay tells the browser where a link leads, and the browser follows it. A page made or changed in the conversation on screen opens there (or, before the browser is on, has it offered), and the page on show comes again when one of its files changes: at once after a run, within 1.5 s otherwise.
- **A web page's card** opens there once the browser is on (D172): at `/workspace/<path>` while the workspace still holds the card's version (`workspaceKeeps`, comparing content), otherwise that version alone at `made:<file>`, its links leading nowhere.

## Languages (i18n)

- **Strings** live in `locales/<lang>.json`, English the source, with `{name}` placeholders. Plurals use `Intl.PluralRules` (Arabic has six forms); dates, numbers, lists and relative times use `Intl`; language names come from `Intl.DisplayNames`, each in its own language.
- **Choosing.** `preferredLocales` matches `navigator.languages` to the catalogues by language and likely script (`Intl.Locale.maximize`), so `zh-TW` finds `zh-Hant`, `pt-BR` finds `pt` and `iw` finds `he`; the menu lists those matches first, under "Your languages".
- **One catalogue per person, in parts** (D76, D97). `useLocale()` fetches only the chosen language, English only when that fails. The dialogs' strings are `locales/dialogs/<lang>.json`, loaded with `useStrings('dialogs')` by `ui/dialogs.js`, which every module showing a dialog imports. A capability whose strings would weigh on the first load has its own part, `locales/<id>/<lang>.json`, loaded with `useStrings(id)` and cached with it. The first-load budget counts the largest first part; each part has the per-file budget.
- **Instant switching.** The locale is a signal, so every bound text re-renders; `<html lang dir>` flips, and CSS uses logical properties only, so right-to-left mirrors at once.
- **Details:** every message element gets `dir="auto"`; Enter never sends while an IME composes; `Intl.Segmenter` counts and cuts Chinese, Japanese, Korean and Thai; the system font covers every script, plus the display face where it applies ([design.md](design.md)).
- **Translation** (D44). A brain translates from English, about 680 strings per language, with no review language by language; anyone can fix one. Sentences are written so nothing agrees with `{name}`. `test/locales.test.js` checks that every catalogue has the same keys and placeholders as English, part by part, that each plural covers the categories the language uses, that the menu matches the catalogues, that every string is used, and that a part's strings are used only where it loads.
- **The 33 languages** (`LOCALES` in `ui/state.js`): am, ar, bn, de, en, es, fa, fr, ha, he, hi, id, it, ja, ko, mr, ms, nl, pl, pt, ru, sw, ta, te, th, tl, tr, uk, ur, vi, yo, zh-Hans, zh-Hant.
- **Conversations.** The prompt stays in English with a `<language>` section; changing the UI language mid-conversation appends a note, and the next reply follows.

## Prompt, tools and caching

Four mechanisms from pi 1.0, fitted to Jean, share one idea: what the brain has read never changes, so providers can cache it and the device's runtime can keep it in memory.

**A frozen prefix** (D46). When a conversation starts, Jean fixes the system prompt and the declared tools, and neither changes until it ends. Providers cache by prefix (Anthropic reads tools, then system, then messages), so one changed byte at the front re-bills the whole conversation; on the device, the same rule keeps the KV cache between turns.

**System notes** (D46, D81). A change mid-conversation (language, rules, instructions, memory, skills, the project, new tools, the date) is a note appended to the transcript where it happens.

- **Sections.** The project, instructions, memory, skills, connections (`<connections>`, D89), the folder (`<folder>`: its name, top level and four tools, and its `AGENTS.md` when the user took it, D152) and the page on show (`<page>`, D140) are sections of the frozen prompt; each has a fingerprint, and one that changed arrives whole in a note ("The <memory> section is now: …").
- **Notes a message comes with:** "Since last time" starts with when the user was last here (D101); the terminal's commands, with their exit codes and output (D166); what / and @ named in it, a skill with its steps, an earlier task as it went (D199).
- **Recorded:** a note is an ACP extension update (`_system_note`) in the conversation's JSONL, holding the English the brain sees and data for the UI's label, so replaying the file rebuilds what the brain was told, and when.
- **Rendered per adapter:** for Anthropic, a `system` message after the next user message, on models that take one; for OpenAI and OpenRouter, a `system` message where the note falls; for other servers and the device's brain, whose templates allow a system message only at the start, a tagged block at the top of the next user turn.
- **Never deleted:** removing a note is an edit, which breaks the cache from there on.

**Deferred tools** (D47, D63, D64, D104). A conversation declares the tools unlocked when it started; anything later is deferred, including every connection's tools.

- `find_tools` and `offer` come from the `discovery` capability, always loaded, so every conversation declares them. `find_tools(query)` ranks undeclared tools by name and description with BM25 and returns up to five signatures (`name({ file: string, pages?: string }): what it does`).
- A capability turned on mid-conversation adds the note "New tools can be found with find_tools: …" (`data: { kind: 'tools', added }`).
- With `javascript` declared, deferred tools are called from a script and the declared list never changes. Otherwise `find_tools`, or an accepted offer, declares them from the next request on, recorded as `_meta.declare` on the call, at the cost of one cache miss. A tool called by its exact name, as `<connections>` gives it, runs under the rules without being declared; a missing argument gets the signature back.
- A provider's native deferral (Anthropic's `defer_loading`) may replace this later, with the same behaviour. The next conversation declares a newly unlocked capability's tools directly; connections' stay deferred.

**Codemode** (D48). `javascript` runs a snippet in QuickJS on the conversation's computer; top-level `await` works, and the result is what the script returns or its last expression. Inside, Jean exposes what the user has granted, and nothing else:

| Global | What it does |
|---|---|
| `file(name)` | A shared file's whole text (spreadsheets as tab-separated rows), or a file of the conversation's folder, through the hidden `file` tool |
| `csv(text)` | CSV or tab-separated text as rows: objects keyed by the header, numbers as numbers |
| `tools.<name>(args)` | Any granted tool, deferred and connection tools included; not `bash`, `javascript`, `python`, `offer`, `delegate` or `ask_user` |
| `fs.readFile`, `fs.writeFile`, `fs.readdir` | The computer's files: /workspace, kept after the run (D162) |
| `fetch(url, init)` | The internet, through Jean, as Settings › Computer allow |
| `searchTools(query)` | `find_tools`, from a script |
| `models.decide(state, questions)` | Kev on the device when Intuition is on, through the hidden `decide` tool |

Every nested call goes through the rules (`ctx.call` in `core/loop.js`); a call that needs approval pauses the script, and the wait doesn't count against its time. Nested calls carry `_meta.parent`, show under their call, and stay out of the brain's context, since the script's result holds what matters. Each crosses to Jean as a message and Jean makes it with its own keys, so the sandbox never sees a secret. Declared tools stay callable directly, because small brains call tools more reliably than they write scripts.

**Thinking blocks are kept** (D54) on each step's brain entry and replayed unchanged to the model that wrote them.

**Caching and warming on Anthropic** (D49). One `cache_control` breakpoint on the system prompt's last block, plus top-level automatic caching for the conversation. When the user starts typing after about 5 minutes without a request, Jean sends the same prefix with `max_tokens: 0`, unstreamed, with the real request's thinking and effort, its breakpoint on the last message already there; skipped below the model's minimum cacheable size. OpenAI caches by itself; local servers keep their KV cache, which the frozen prefix keeps valid; the device's brain reads only what follows the text it already read (D58).

## Retrieval and extraction

- **Extraction:** DOCX, XLSX and PPTX through the tag scanner; PDFs with pdf.js, on demand. Pictures (PNG, JPEG, WebP, GIF), dropped, pasted, picked or captured from the screen, are kept no larger than 1,568 pixels a side and go to brains that can see, right after their `<document>` tag (`image_url` for Chat Completions, an `image` block for Anthropic); a brain that can't is told there is one (D105).
- **Retrieval without a vector database** (D24, D55): a document that fits in about 25% of the brain's context goes in whole; otherwise its first pages do, and `read(file, pages)` reaches the rest. The choice is made once, when the message is sent, and recorded on the file's link. Past conversations are searched with BM25 (`recall`); a `search(query)` over a long document's page-aware chunks comes when one is needed, the brain writing its query in the document's language.
- **Source numbers** (D71, D90): each shared file gets a number on its link (`_meta.source`), kept if it is shared again. The brain sees `<document source="n" name="…">`, and `read` starts with "Source [n]:". Connections' and Wikipedia's results list their pages as "Source [n]: …", and the brain's own search cites pages. `[n]` becomes a chip only for a known source; a web page's chip is a link (into the browser once it is on), and a "Sources" list follows the answer.

## Activity events

Jean's event format is ACP's `session/update`: `user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update`, `plan`, plus `session/request_permission`; the types come from ACP's published schema as JSDoc.

```jsonl
{"at":"2026-10-01T10:02:11Z","by":"jean","update":{"sessionUpdate":"plan","entries":[{"content":"Read the invoices","priority":"high","status":"completed"},{"content":"Total per client","priority":"high","status":"in_progress"}]}}
{"at":"2026-10-01T10:02:12Z","by":"jean","update":{"sessionUpdate":"tool_call","toolCallId":"t3","title":"Read invoices.csv","kind":"read","status":"completed","locations":[{"path":"files/invoices.csv"}]}}
```

- **One stream, one record.** The core emits the events, the UI renders them live, and the conversation's JSONL stores them, each wrapped in an envelope with a time and an author. Text chunks merge into one record when a message finishes; a tool call is stored as it starts and again in its final state, which takes its place when the file is read (D216). The brain's context is derived from the same file.
- **Translated labels.** Each line's label is rendered from `kind` and `locations`, so switching language relabels history; ACP's `title` is kept as a fallback.
- **Approvals map onto rules:** `allow_always` writes Do it, `reject_always` writes Never, the "once" options keep Ask me first. A connection's tools that change something use `kind: "other"`, read-only ones `fetch` (D89). A declined call carries `_meta.declined` (D216).
- **Every line opens** on what went in and came back (D103): a call's tool, arguments, result and duration; a brain step's thought and text, how it stopped, its duration and usage (`_meta.ms`). A script's calls nest under their call (`_meta.parent`); helpers' turns nest under theirs (D98). Auto's choice is on the brain entry (`rawInput.auto: { level, reason }`), shown in plain words (D70), and so is whether the brain runs on this device (`rawInput.local`, from `isLocal`, D252).
- **The decision inbox** (D99, D146, D147): approvals and questions, Jean's or its helpers' (`ask_user`), queue as cards under the live answer, answered in any order; "Always" or "Never" settles the other cards of that kind. Each card waits in its own conversation. Before Jean's own call waits for the user (an approval, or a tool with `asks`), the loop appends it as `pending` with `_meta.waiting`, and the step's later calls as `pending`; `unanswered()` (`core/events.js`) finds a last step whose first unended call waited, `openConversation()` then runs the conversation again, and `runTurn({ resume })` runs those calls in their step before the next one, `toChatMessages()` leaving their results out (D212). Elsewhere, a pending call reads as cut short, and the conversation shows only the live answer's; a call the file keeps as running, which the page closed on, reads as cut short to the brain and shows so in the activity (D216).
- **Answers go on out of sight** (D147): a run is kept by its conversation's path, a call finds its conversation by its run's signal (`conversationOf` in `ui/state.js`), and the list marks each conversation being answered with a small light.

## Connections (MCP)

A connection is an address and, when the service asks, a key or a sign-in (D87–D89, D95).

- **The directory** (`caps/connections/directory.js`) lists the services Jean knows, those people at work use most (D192), a tile each with its logo (D159): reached from the browser (`ready`), through the gateway once it relays to the service and its sign-in's hosts (`signIn`) and holds the app a sign-in that registers none takes (`app`, its issuer, D214), or not yet, and then disabled, after the others. - **Signing in** (`auth.js`) follows MCP authorization from the browser: protected resource and authorization server metadata (an issuer compared as an address, so `https://otter.ai/` is `https://otter.ai`; with no resource metadata, the server's at the service's own origin, and no `resource` sent; a service that names itself, whose metadata there names its origin, as ServiceNow's does, has it at that origin, D283), dynamic registration as a public client, PKCE with a `resource` indicator, the `iss` check. - **The browser's limits:** a service must answer with CORS and expose `Mcp-Session-Id` (2025 sessions) and, ideally, `WWW-Authenticate`. When it doesn't, and no gateway reaches it, Jean says it couldn't connect.

Its configuration, in `GATEWAY_CONFIG` and never in a file beside it (Jean's folder is served as it is), names Jean's origins, the hosts it relays to (a name covers its subdomains; none named, `SERVICES`: those of every service in the directory that isn't ready), and the apps it holds: issuer, token endpoint, client id and secret, sent in the form or as Basic; and the witnesses and logs that date and record certificates (`timestamps`, `logs`, D276), whose hosts it relays to. `GET <gateway>` answers `{ format: 1, hosts, clients: { <issuer>: <client id> } }`, with `timestamps` and `logs` when it has them; `<gateway>?url=<address>` relays: only from those origins, only to HTTPS on those hosts (HTTP on this computer), redirects followed only to them, the request's `Accept`, `Content-Type`, `Authorization` and `Mcp-*` headers alone, at most 10 MB in and the answer streamed back with CORS that exposes `Mcp-Session-Id` and `WWW-Authenticate`. A token request to a configured endpoint that names its app gets the secret. A connection made through it is marked `gateway` and every request it makes, discovery, registration, tokens and MCP, takes the gateway's address at that moment (`urls.gateway`). `npm run dev:gateway` mounts it at `/gateway` in the development server (`scripts/serve.js --gateway`), for whichever address Jean is opened at there, and adds the policy that sets it to `index.html`, Connections still found as anywhere else (D281); a same-origin GET carries no `Origin`, so `gateway/serve.js`'s listener names the page's own, from `Sec-Fetch-Site`.

- **The package** (`npm run cli`, `scripts/cli.js`): every module `main.js` reaches, statically or through the `import()`s it lists, copied as written and where they are (Jean's own under `app/`) into `dist/cli/` with `cli/locales/`, `app/brand.js`, `LICENSE`, `cli/README.md` and a `package.json` (`bin: jean-cli`; `@preact/signals-core` and `marked`).

## Voice

- **Speech to text** (D56, D61, D110, D205): the browser's on-device recognition where it works, otherwise a worker: Whistle in English, German, French, Spanish, Italian and Dutch, Whisper base through Transformers.js in the other languages.
- **Text to speech** (D109, D114): `speechSynthesis` with local voices only, each answer in its own language, by the voice `rankVoices()` in `ui/language.js` puts first. Natural voices (Kokoro) are a possible later option.
- **Live conversation** (D93): an AudioWorklet feeds 16 kHz audio to Silero voice detection (~2 MB) in dictation's worker → Whistle or Whisper → the brain, streamed → the system's voices, sentence by sentence. A turn starts after 250 ms of speech and ends after 800 ms of silence; speaking over Jean for half a second interrupts it. `caps/live/turns.js` holds the turn-taking, tested under `node --test`.
- **Real-time speech models** from providers (OpenAI Realtime over WebRTC, Gemini Live) could come later; `wss:` is already in `connect-src`.
