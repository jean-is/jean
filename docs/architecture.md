# Architecture

How Jean is built, as it is now. Why each choice was made, and what was rejected, is in [decisions.md](decisions.md), cited here as `Dnnn`.

## Principles as rules

| Principle | Rule that can be enforced |
|---|---|
| KISS | Hard limits in [budgets.json](../budgets.json), checked in CI. Going over means deleting something first. |
| Portable | All data is plain files: Markdown, JSONL, `SKILL.md` folders, sealed at rest on the device (D371). Export is a zip; import is dropping a folder. |
| Universal | Standards, not adapters: OpenAI-compatible and Anthropic Messages, MCP, Agent Skills, ACP events, the Jev-style Decisions API. |
| Browser-ready | Static files, offline after the first load, opened from a link. |
| System-agnostic | `core/` uses only standard web APIs and runs unchanged in a browser, a worker, Node, Deno or Bun; its tests run under `node --test`. |
| Incremental | Capabilities are discovered as situations call for them, offered by Jean, granted by the user, and only then loaded. |

## Stack

**No build step** (D9). Plain ES modules and an import map; types in JSDoc, checked by `tsc --noEmit`. Development serves `app/` as written (D243), and view-source is the source; a web deploy copies `dist/web/`, the same files with Jean's own code minified and each file compressed beside itself (D318).

**A first load without a bundle.** `npm run manifest` writes a `<link rel="modulepreload">` into `index.html` for every module the first load imports, so the browser fetches the graph in one round trip, and stamps `sw.js`'s `VERSION` line; `npm run manifest -- --check`, in CI, fails if either is stale. The first screen loads only what it draws (D76, D94, D148): the desktop app's host, the dialogs, the adapters, the loop, Auto and what a message needs on its way (`ui/send.js`, loaded as the user starts typing) all load when first needed, and stay in the shell's precache for offline use.

`vendor/`, `capabilities.json`, `manifest.webmanifest`, one per language in `manifests/` (D396) and a copy of `LICENSE`, all in `app/`, are made by `npm run dev`, `start`, `build` and `check` from Jean's own `node_modules` and the root's licence, and never committed (D43, D51, D52, D74, D243). The development server writes all but `vendor/` again after each change, so the hashes a share or a page saved there carries are those of the files it serves.

**Vendoring** (`scripts/vendor.js`). The three upfront libraries and the on-demand runtimes (`optionalDependencies`) are copied, as `package-lock.json` pins them, from Jean's own `node_modules` into `app/vendor/`, their bare specifiers rewritten where import maps don't reach (workers), and what Trusted Types and the CSP refuse patched, each patch found exactly as often as expected or the copy stops. A runtime is listed under the capabilities that use it, never in the shell, and nothing comes from a CDN (Transformers.js gets `wasmPaths`).

**The web's copy** (D318, `scripts/web.js`). `npm run build:web` copies `app/` into `dist/web/`, minifies Jean's own modules, workers and style sheets with esbuild, and writes each file of a kilobyte or more that compresses beside itself in brotli and gzip at their best, which the server sends as they are. Minifying takes out comments, whitespace and local names, nothing else: a classic script keeps its global names, no syntax is lowered and no prefix added (for the browser floor, esbuild would turn `\p{…}` regexes into `new RegExp` strings, un-nest `@starting-style` and add `-webkit-` prefixes), and a style sheet loses only whitespace and comments. The first load is about 40% less than what Caddy compressed on the fly (zstd), a second on a slow connection, and ONNX Runtime's wasm 3.8 MB rather than 6.2. The service worker, the bridge, the pages, `ui/touches.css` (shown as it is, D111) and third-party code stay as written. Each compressed copy is kept in `node_modules/.cache/web/` (or `WEB_CACHE`), named by the hash of the file it was made from and by how it was made, and used again only when it reads back as that file, so no kept copy can change what ships.

**Budgets** ([budgets.json](../budgets.json), D86). `scripts/budgets.js` measures them in `npm run check`, and the dev servers run it as Jean starts, then after each change, in a process of its own: every budget over is said on the error stream until all are met again; the server still serves. The line budgets (`loc.core`, `loc.app`, `loc.cli`, D246) count lines of code, by `scripts/loc.js`: a line counts when it holds anything but comments and white space, so a comment after code leaves its line counted, and what a string, a template or a regular expression holds is code, whatever it looks like.

**Built on the browser, no dependency:** text from DOCX, XLSX and PPTX (zip through `DecompressionStream` and a small tag scanner, not `DOMParser`, so it runs in workers and under `node --test`); BM25 search with `Intl.Segmenter` over an index made once, which ranks deferred tools, past conversations and the passages of documents, and matching as people type over a fold of the text as long as the text (`core/search.js`).

**Routing is one hash** (D59, D137, D220, D582), read by `ui/router.js`: `#/c/<ulid>`, `#/p/<project ulid>/c/<ulid>` in a project other than home, `…/settings/<section>` with Settings open over either, or `…/settings/<section>/<page>` on one of its pages, and after a `?` the windows beside it, in the order they opened, each `name` or `name=state`, as in `?flow=task&terminal&browser=https://example.com/` (`browser=<address>`, `terminal`, `flow=<flow ulid>`, `creations` and `split=<layout>`, how the dock lays them out with the conversation, D497, D635, D640). `ui/windows.js` keeps them: each window's module calls `keep(name, { get, set })` as it loads, `get()` saying what it shows (null closed), `set()` showing a state again after checking it. Following an address, it waits for every capability found to come back, since what a window shows may need another's, then closes the windows not named and sets each named one, giving the keys back where they were. The router waits for that before the room first shows, a second at most (D582), so that its first frame holds the windows as they will stay: nothing moves as they come. The router writes the windows into the entry it is on rather than adding one, and follows them only when an address leads to another place. A name Jean doesn't know, or one whose capability isn't found yet, is passed over, so an address stays good as windows come and go. The unsent draft is kept per conversation in `sessionStorage`, and so is where each file's view was scrolled to (`app.scrolled`, D582), never in the file; other dialogs stay out of the address.

**Components are custom elements** (light DOM, prefix `app-`). Each capability is one module that defines its elements and registers its tools, hooks and slots ([Events and slots](#events-and-slots)); unlocking it is an `import()`, and any of its elements already on the page upgrade. `:not(:defined)` styles what isn't discovered yet. One the user turns off once found (D433) goes into settings' `off`, which `ui/app.js` adds to policy's `deny` as the page begins, so nothing unlocks it until its page turns it on; `ui/update.js` sees a capability loaded that is now off, here or in another tab, and opens the page afresh where it was once nothing is under way, as for a new version (D138), since a module can't be unloaded.

**Long lists draw only what is in view** (D627, `ui/virtual.js`). `virtual()` is a lit-html directive, the only content of a list's element: it draws those in view and a screen's worth either side, between two empty elements as long as the rows left out (never the element's padding, which a scroller's parent grows to hold), so that the scroll bar is as long as all of them. While the rows change, each keeps the greater of its old and new length, taking its own in a microtask once they are in: a layout in between (Chromium's, as the row with the keyboard is taken out) would find the list shorter and pull the scroll back; and a redraw from a scroll puts back where its scroller was, which WebKit moved by the rows taken out above at the drawer's end. Nothing about the items is told to it: the step from one row to the next and the lanes a row holds are read from the first one drawn, to the fraction of a pixel (`getBoundingClientRect()`, since rounding adds up over hundreds of rows), so CSS alone lays them out, at any width.

## Brand

```js
// brand.js — the only place the name lives
export const BRAND = Object.freeze({ name: 'Jean', domain: 'jean.is' })
```

- **For display only** (D4): UI strings (`{name}`), the system prompt, the page title and the web-app manifest.
- **Never in anything that persists:** storage keys, OPFS paths, cache names, element prefixes, CSS classes, the desktop app's identifiers. Renaming changes one line and moves no data.
- **The assistant's name is a setting:** `settings.assistantName ?? BRAND.name`, which a project can override.
- **Grammar:** translations never make a word agree with the name; in conversation, the brain handles grammar itself.
- **The origin is not a variable.** Storage belongs to the domain, so it is settled before the public launch (D27).

## Core

- **`loop.js`**: stream the reply, run tool calls, feed results back, repeat. Rules (Do it / Ask me first / Never) are checked before each tool runs, calls from scripts included. The prompt and declared tools are frozen for the conversation; changes arrive as notes ([below](#prompt-tools-and-caching)).
  - `tools` is every tool that can be called, and may be a function read again at each step, so a capability turned on mid-turn can be called at once. `declared` is what the brain sees; `hidden` tools are never declared (D64).
  - A tool's `check` runs before a call the rules don't refuse: it can ask even where they allow (a change in the user's folder) and give the card what it shows (ACP `diff` content).
  - Sources are numbered from `firstSource`: tools call `ctx.cite()`, the brain's own search sends `cite` events that become ` [n]`, and both are recorded as `_meta.sources` (D90). A provider's `pause` (Anthropic's `pause_turn`) is sent back and resumed.
  - `ctx.turn()` runs a helper's child turn (`delegate` splits a task into up to five parts, run three at a time as hidden `helper` calls) with the same brain, rules, approvals and source numbers, its own prompt, history and tools; its records nest under the calling tool's (ids prefixed, `_meta.parent`, no thinking blocks) and its text is the call's result (D98).
  - Steps go in blocks of `maxSteps` (12, or 40 in a folder; after `resume`, counted from the step after it). At the end of one, `turn.limit` may give the turn another; and a turn that stops there keeps its last brain entry again with `_meta.stopped: 'max_turn_requests'`, ACP's stop reason, which the room shows as a pause (D364).
  - `steer()` gives what the user sent while the turn works, as their records (`user_message_chunk` with `_meta.steer`), read at the top of each step, before compaction: kept, then read by the brain as the user's message after the last step's results. A helper's turn reads none (D365).
  - A request that fails before anything of its answer came is asked again after 1, 2 and 4 s, or after the provider's `Retry-After` when longer, up to 30 s, if the error may pass (`LLMError.retryable`: the connection, the provider busy or its server failing, and the browser offline, which looks the same as a refused cross-origin request; never the device's brain).
- **`llm.js`** and **`anthropic.js`**: the OpenAI-compatible Chat Completions and Anthropic Messages adapters, over fetch and SSE (`sse.js`); together they reach almost every model. Anthropic from the browser needs the `anthropic-dangerous-direct-browser-access: true` header; OpenRouter's PKCE sign-in (`oauth.js`) runs entirely in the browser. A `claudecode` or `copilot` brain is an Anthropic one, and a `chatgpt` brain an OpenAI-compatible one, whose address is This computer's bridge (D235 · D262). OpenRouter weighs the credits left against the longest answer a brain may give, which Jean leaves unsaid; when they fall short it answers 402 with how many tokens they cover, and Jean asks again for that many. Any other 402, or Anthropic's 400 that says the credit balance is too low, is `credits`, and isn't tried again by itself.
- **`hooks.js`**: Jean's events, which hooks watch, change or answer ([Events and slots](#events-and-slots), D293).
- **`prompt.js`**: the base prompt, the frozen sections and the notes that change them (D46, D81), and `toChatMessages()`, the records as the messages the brain reads after it.
- **`deferred.js`**: `find_tools`, tool signatures, and `reach`, which says how to call a tool that isn't declared (D63, D104).
- **`rules.js`**, **`settings.js`**: the rules and their defaults, and guards as `tool.check` hooks (`guardHooks()`, D295): each, the person's in `settings.json` (`guards`) and the organisation's in `policy.json`, outermost and locked, only tightens what the rules and the tool's check decided, and, when it has one, only if Intuition, else the room's brain in a word, answers yes to its question, one it can't answer counting as yes; its reason is what the brain reads, and a guarded call that asks keeps asking ("Always allow" sets no rule); settings resolved as defaults ← user ← policy, `DEFAULT_URLS`, `PROVIDERS`, projects. Every third-party address (providers' endpoints, OpenRouter's sign-in, Wikipedia, the model weights host, the package registries, the site icons) is what the user picked or a default there, resolved when read and never written into `settings.json` (D33).
- **`search.js`**: BM25 over an index of texts, `alike()`, which tells requests of the same kind apart, `restated()`, which finds a clause of four words or more alike at 0.8 to one in an earlier task's request (D286), and matching as people type.
- **`decide.js`**: Kev's input and answers in the Decisions API's shape; the questions themselves are in `caps/reflexes/questions.js` (D62).
- **`memory.js`**, **`skills.js`**: the `memory.md` format and the lines that fit (D79); `SKILL.md` folders, of which only names and descriptions go into the prompt (D83, D121).

## Events and slots

What Jean does passes through named events, and what the room draws for a capability goes through named slots that the capability fills (D293), the points extensions reach too.

**Hooks.** `fire(hooks, name, e, behaviour)` (`core/hooks.js`) runs the hooks on that event whose `match` the event holds (a value, one of a list, or a pattern its text matches), outermost tier first (`policy`, `user`, `jean`), in the order given within one. Each `run(e, next)` calls `next(e)` to go on, with the event or a changed copy, the last `next` reaching Jean's behaviour; returning without it answers the event. One that throws is passed over, or answers `{ refuse }` when it is a guard (`refuse` set); once it went on, what came back stands, and what Jean's behaviour throws goes through as it is. An answer a hook gave of its own, a plain object other than the one the chain gave it, carries `by`, whose it is (D299). A capability lists its `hooks`, which `contributions()` gathers, read again at each event as tools are, each by the capability's id unless it says whose it is.

No hook makes a reserved action (passwords, payments) less guarded than the rules left it. A refusal's reason is what the brain reads; without one, "The user declined this action." A call whose decision a hook gave keeps whose it was as `_meta.by` (a guard's id, an extension's name, a capability's id) and what it was as `_meta.decision`, so the records say who refused, asked or allowed.

**Slots.** `slots(name)` (`ui/caps.js`) gives what each loaded capability has in a slot, `{ at, draw }`, lowest `at` first: `views`, the header's end; `main`, in place of a new task's welcome, one at a time, each with its `leave()`; `above`, above the box; `task` and `kept`, a task's and a pinned creation's ⋮ menu in the drawer; `add`, the + menu; `modes`, the box's foot, a mode + turned on, whose `notes(records, signals, { text, brain })` come before each message (Visual answers, D300; a child's danger, D390, D661); `activity`, under a task's activity; `settings`, a section of Settings placed among Jean's own by `at`; `general` and `brains`, parts of those sections; `data` and `organization`, parts of Your data; `allowed`, what a capability keeps of an Always allow outside the rules, each `{ what, name, stop }`, which Approvals › Exceptions lists with Stop, and `approvals`, a part of its Certificates page; `by`, the name of whose rule decided a call, given its id (extensions); `profiles`, the top of the person's menu (Profiles, D228); `person`, what the drawer's foot calls the person when they set no first name.

**Extensions** (`caps/extensions/`, D296, D552) reach the same points from outside. An extension is a folder, `extensions/<name>/` at the root, kept as it came: Jean's own `extension.json`, after Claude Code's `plugin.json` for what both need, with `format`, `title-<lang>` and `description-<lang>` as skills give theirs (D222), `main`, its module beside it, `rights`, and `icon`, one of Jean's glyphs by name but none that stands for safety or for Jean's own controls (a shield, a lock, a check, a trash…). It is read from a folder's address or a repository's page on GitHub, or from the ready-made ones policy names (`extensions.ready`), and its page shows who made it, where from, its maker's words apart from what Jean will let it do, Loosening marked, and its code, before Add it. Each one turned on (`extensions` in settings, on this device) runs in a frame of `sandbox.html` of its own (`sandbox="allow-scripts"`, no network), where `caps/extensions/extension-worker.js` imports its module, sent as text, from a blob and calls its `register(on, $)`: `on(event, match?, run)` hooks `task.start`, `file.add`, `tool.check`, `turn.end` and `record`, and `$.slot(name, draw)` draws in `above`, `answer` and `settings`; `notify` shows its short messages under its name, and `$.redraw()` asks Jean to draw it again. Its rights: `watch` to hook at all, `change` to go on with a changed event or answer otherwise, `refuse` to make a call more careful, `loosen` to let one go ahead without asking (never a reserved action, nor past a rule the organisation set). What it draws is a tree of Jean's elements (text, a button whose press goes back to it, a row, Markdown as answers have it), drawn by Jean in the room's look. Messages are all it has:

| Jean sends | The app answers |
|---|---|
| `start` (its code) | `started`, with what it hooks and the slots it draws in, or `failed` |
| `event` (a hook's index, the event as plain data) | `next`, as often as it goes on, each answered with the rest of the chain's result; then `done` with its own, or `threw` |
| `draw` (a slot, its props) | `drawn`, a tree |
| `press` (a button's action) | — |
| `answer` (to `next` or `store`) | `store` (a key, and a value to keep), `notify`, `redraw`, at any time |

`proxy()` in `extensions.js` makes each of its hooks one of Jean's, in the user's tier: it sends the event, passes a changed one on only with `change`, and keeps an answer only within the extension's rights (`allowed()`: on `tool.check`, more careful is `refuse`'s, looser `loosen`'s, unless the organisation set the kind's rule; elsewhere, `change`'s or, a refusal, `refuse`'s). It waits 5 s of the extension's own time (`call()`, held still while `next` runs). A hook or a drawing that fails or goes unanswered counts against the extension (`failing()`): at the third in a visit, its switch is turned off with `failed`, which its row says until it is turned on again, and a toast says so (D309). With `?safe` in the address, no extension starts, for Open Jean once with no extension. `examples/extensions/` holds four to try (an activity log, quiet hours, trusted sites, and a glance at each long answer), which `npm run dev` serves at `/examples/` to any page.

## Brain ladder

1. **On this device:** Gemma 4 E2B, q4f16, through Transformers.js on WebGPU: native tool calling, 140+ languages, image and audio input. About 3.1 GB for text, downloaded once with consent at the revision `caps/brain-local/watermark.js` pins (`REVISION`), which answers' certificates name; the image and audio encoders follow when first needed. Offered only where it runs: WebGPU with `shader-f16`, enough free storage, and a computer of 12 GB, never a phone or a tablet (D42 · D319): 8 as a browser says it (a power of two, the nearest, ties down, so 12 GB says 8, as 8 GB does), 12 GB where the desktop app knows it exactly. Loaded, it holds about 7 GB between the tab and the browser's GPU process (measured in Chromium on a Mac), and 9 GB while it loads: the worker writes its two weights files (embeddings and decoder) to Transformers.js's cache as they come, and each ONNX Runtime session reads only its own from there while it is made, one after the other, the file's stream writing straight into one buffer of its size (D408), which WebKit allows where it won't read a Blob that large. A load under way is marked in `localStorage` and holds a Web Lock; its page takes the mark away once loaded or failed, or as it leaves (`pagehide`: a reload, a closed tab). A mark left with no lock held means the load took its page down: that browser no longer offers the brain and deletes its download, unless it is one of the user's brains, which Settings › Brains says once. A run that fails, but for a stop or a conversation too long, leaves ONNX Runtime broken in its worker, every run after it failing too: `stream()` ends the worker (`stop()` in `ui/model.js`) and sets the download back to `idle`, so the next request starts another, which loads the brain again from the cache, its progress shown as at the first load, while the failed answer says its error once, never asked again (D350).
2. **One click:** OpenRouter sign-in, no key to paste. Every request to OpenRouter asks for providers that neither keep nor train on it (`provider: UNKEPT`).
3. **Advanced:** the user's own key (OpenAI, Anthropic, Google Gemini, Vertex AI, Mistral AI, Meta, OpenRouter, Vercel AI Gateway, Hugging Face, Groq, Cerebras, Together AI, Fireworks AI, xAI), Vertex AI's being a service account's key file, from which `core/vertex.js` signs a token for each request, or an hour-long access token; or a local server (Ollama, LM Studio, any OpenAI-compatible endpoint).

Not used: the browsers' built-in models (too experimental) and native OS models.

**The device's brain's watermark** (D402, `caps/brain-local/watermark.js`): the worker hands `generate()` a logits processor and decodes greedily, so the processor decides each word. Among Gemma's 64 likeliest at a temperature of 1, the fewest whose chances reach 95%, the one whose `ln(u)/p` is highest wins, `u` from a keyed MurmurHash3 of the four tokens before and the candidate: each is picked as often as sampling would pick it, and the same each time. Between `<|channel>` and `<channel|>`, and `<|tool_call>` and `<tool_call|>`, the logits pass untouched, greedy. `lean()` counts a text, which sums to n on average over n by chance, with a standard deviation of √n; `said()` calls 4 deviations above marked, and anything else none found, which proves nothing: on E2B half of the answers of 500 tokens show it.

**The first brain** (D329): with no brain in the room's project, `send()` and the chip import `caps/first/first.js`, which draws `<app-first>` under the box in place of the ideas (D366), or Settings › Brains when there are brains kept to other projects or set by policy. It is not a capability of the catalogue, never offered, and brings its own part of the catalogue, `locales/first/`, which loads only then. The box beside Start for free leaves `app.private` in the tab's `sessionStorage`, and `finishSignIn()`, back with the key, puts back the box's words and files, then downloads the device's brain while OpenRouter's answers, so Auto has both.

**Beside the page** (D285): a model on this device works on the GPU that draws the window, where each frame waits behind what was sent before it. `holdStill()` in `ui/model.js` holds the page still while the device's brain answers or a picture is made or checked here: it sets `--loops` on the root to `paused`, through CSSOM as `--warmth` is, and every infinite animation takes its play state from it (`var(--loops, running)`), so only what changes is drawn, and an entrance still plays. `test/looks.test.js` checks that every loop does. Measured with Z-Image-Turbo in a Chrome window 5,120 pixels wide, a key took 48–56 ms to show at the median, then 16 ms, and Settings opened in 84 ms, then 49; the worst wait, about the length of one batch of the model's work, stays 100–150 ms.

**One runtime, kept compiled** (D287): every model's worker imports `ui/model-worker.js`, which turns off Transformers.js's own copy of ONNX Runtime's wasm (`useWasmCache`), so it streams from the file: Chrome keeps WebAssembly compiled only when it was compiled as it streamed from a response it keeps, and a picture made here starts a worker for each stage (D263). Served from the service worker's copy, Chrome keeps what it compiled and optimized beside it, and the next worker, in this visit or a later one, starts from that. On `npm run dev` it keeps nothing (`no-cache`, no validators), so each worker compiles it, and a trace there shows a first visit's cost each time. Measured with Z-Image-Turbo on an M3 Max: a first visit took 14–30 s of processor time optimizing it, and its first step came 0.5 s later than on the next visits, every worker starting from what Chrome kept.

**Auto** (D70, D269, D307): `ui/auto.js` turns Intuition's demand into a tier and steps up when the user seems unhappy, never down within a conversation; personal content goes to the device's brain or a local server when there is one, and so does every message while the browser is offline. Tier ids (`TIERS`, which policy replaces) are used only when the provider's live model list has them. **Keep on this device** (`cloud: false`) allows only the device's brain and local servers: while it is on, or the room's project is kept on this device, the picker and a routine's own brain offer no brain in the cloud, and turning it on while one is picked by hand goes back to Auto.

**How much it thinks** (D414): `chooseEffort()` in `ui/auto.js` gives each message low, medium or high: the brain's own `effort`, or Intuition's demand, a step more when the user seems unhappy, never less than the most a brain entry of the conversation records (`rawInput.effort`); without Intuition, and before any, nothing, so each brain keeps its default. `core/anthropic.js` sends it as `output_config.effort` to the models that take it (`EFFORT`); `core/llm.js` as OpenRouter's `reasoning.effort`, and `reasoning_effort` everywhere else, local servers included. ## Reflexes

`decide(state, questions)` takes typed questions (`noul`, `choice`, `score`) and returns calibrated probabilities, in the Jev/Decisions API shape that Jev, Clef, Strands Decider, Laya, Kev, Ollaya and OpenRouter's `/api/alpha/decisions` share, so backends can be swapped. In the UI, reflexes are **Intuition**.

```js
// ui/discovery.js, with the questions from caps/reflexes/questions.js
const { demand, personal, capability } = await decide(message, {
  demand:     { type: 'score',  instructions: 'How demanding is this request?', criteria: ['a quick chat or a simple fact', 'reading, writing or summarising', 'several steps of work or analysis', 'expert reasoning'] },
  personal:   { type: 'noul',   instructions: 'Does the message share personal, health, financial or confidential information?' },
  capability: { type: 'choice', instructions: 'Which of these would help with this message, if any?', criteria: { compute: 'exact numbers, maths, or analysing a table of data', none: 'nothing new is needed' } },
})
```

There is always a default project, hidden until Projects is discovered, so one code path handles everything.

- **Writes.** One storage worker writes with `createSyncAccessHandle` (Safari 16.4+, Chrome 108+, Firefox 114+, which has module workers; D12). Conversations are append-only, so a crash costs at most a half-written last line, ignored on read (going back to a request rewrites one whole, D188); files rewritten whole go to a temporary file first, then are swapped in.
- **Several tabs.** Web Locks serialise writes per file; BroadcastChannel tells other tabs to refresh.
- **Sealed at rest** (D371, [encryption.md](encryption.md)). The storage worker seals every file it writes in OPFS and opens every one it reads (`ui/seal.js`), so nothing above `FS` knows: a 32-byte header and records of AES-256-GCM of 64 KiB at most, the file's key derived from the vault key and its salt by HKDF, each record bound to the header and the file's path. The vault, a profile's, opens at the first `ping`: a first run makes its key and seals it under this device's (a non-extractable key in IndexedDB's `app-keys`), and with a lock the worker waits for the key the lock screen hands it, or another tab. Files with no vault that opens them answer `sealed`, with only starting afresh offered. A folder of the user's, and `.secrets/vault.json`, stay plain.
- **Folders of the user's** (D141, D149, D152). A project or a conversation opened on a folder of the computer gets an `FS` of its own (`folderFS` in `ui/opfs.js`): a storage worker started on the folder's handle, writing in place with `createWritable`, without the temporary copy and without telling other tabs. `stat` gives a file's size and `lastModified`, which a change checks against what the conversation read. Handles live in IndexedDB's `app-folders`, under the project's or conversation's ULID; the folder's name is in `project.md` and `<folder>`, so a missing handle is asked for again by name. Outside Chromium, a folder is a read-only copy for the visit (`caps/folders/copy.js`), and what Jean changed is saved as one zip. Nothing of Jean's is written there.
- **Profiles** (D228). ## Service worker

- **On install:** cache the shell (`sandbox.html` and `preview.html` included) and every locale file, so switching language is instant and offline. Files come through the HTTP cache and are checked against the integrity hashes in `capabilities.json`; a stale copy is fetched again. The install icons and screenshots stay out (D131, D168).
- **On unlock:** cache the capability's files, listed in `capabilities.json` with content hashes, with the modules of other capabilities it imports (the Computer's from Folders and Files), so it works offline on its own. The cache is the record of what has been unlocked.
- **On update:** the browser looks for a new `sw.js` as a page loads, and `ui/update.js` asks it again whenever the page comes back on screen, at most every quarter of an hour (D138). Then download the new shell and new versions of unlocked capabilities only, then delete old caches. When the user lets it in, the new version takes the page's place where it was (`ui/update.js`, D138).
- **Which version runs**: `npm run manifest` writes `release` into `capabilities.json`, `package.json`'s version and when the files it lists were made (`SOURCE_DATE_EPOCH` for a deploy's commit). Settings › General reads it from the shell's cache, so it names the code running, not the newest on the server; `about` gives the brain the same line.
- **Model weights** live in their own cache, so an update never downloads 3 GB again.
- **A notification the page can't show itself** (Android's browsers refuse `new Notification()`) is shown by the service worker, and a tap on it focuses Jean's window at the task's address, or opens one there.
- **Offline:** history, files and the device's brain keep working; with only a cloud brain, Jean says so. The site's policy holds as last read: `ui/app.js` keeps a copy in the `app-policy` cache, read whenever `policy.json` can't be, so an organisation's brains, locks and denied capabilities never lift with the network. The Computer and pages in answers need the site to start their frame, which Chromium loads past the service worker, sandboxed as it is: offline, the sandbox says so within 5 s of its frame loading.

## Security

Every HTML document has its own CSP in a `<meta>`, which works on any static host. Each is checked in every engine by the browser's own reports (D326): `scripts/serve.js --csp-reports` serves each page's `<meta>` policy again as a `Content-Security-Policy-Report-Only` header whose reports it keeps, by the `csp` cookie that names whose they are, so a browser says what its policy refused, Trusted Types and workers made from blobs included, with no hook into the page. `test/csp.spec.js` takes Jean through an answer, a page in it, the sandbox, Python, Settings and the check page, after a refusal made on purpose that shows the browser reports at all, and fails on any other: with the smoke tests in Chromium and WebKit, and in Firefox, Chrome, Edge and Safari themselves with `npm run csp` (`scripts/csp.js`). Two refusals are expected. Pyodide asks whether its worker is a classic one by importing an empty `data:` script, which the sandbox's policy refuses, Python working either way. Safari makes a Trusted Types policy of its own in the room, so its report names the page and no file of Jean's. Playwright's WebKit refuses every `<select>` a style attribute it doesn't have, since build 2370, where macOS 27's WebKit says nothing.

**`index.html`** runs only Jean's own code:

```text
default-src 'self'; script-src 'self' 'wasm-unsafe-eval' 'sha256-<import map>' 'sha256-<first paint>'; style-src 'self';
img-src 'self' blob: data: https:; media-src 'self' blob:; font-src 'self';
connect-src 'self' https: wss: http:;
worker-src 'self' blob:; manifest-src 'self'; frame-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none';
require-trusted-types-for 'script'; trusted-types lit-html app-urls
```

- **`connect-src` is broad** because users add any OpenAI-compatible endpoint, and untrusted code never runs in this document. Organisations tighten it with an HTTP header ([enterprise.md](enterprise.md)).
- **Plain HTTP reaches this computer alone** (D260). Before it reads anything Jean keeps, `start()` in `ui/app.js` adds a second policy, which holds as well: `connect-src 'self' https: wss:` and `http://<name>:*` for `localhost`, `127.0.0.1` and, in the desktop app, each of the computer's own IPv4 addresses; Settings › Web search reads that policy to tell what it can reach (`insecure()`). A policy can only narrow, so an address the computer takes later (another network) holds from the next load.
- **`img-src` allows `https:`** for the site icons on web sources' chips, whose address is replaceable (D210), and the pictures sources give (D35): an answer draws a Markdown image only when its address is a source's picture, then loads the address the source gave, and shows any other as its words.
- **A source's picture** (D35, D336). Wikipedia's and Vikidia's search bring each page's lead picture, and so does `browse` for an article of their sites, through MediaWiki's API at the source's address (`readWiki()`). Any other page `browse` reads gives its own (`og:image`, else `twitter:image`, https alone). Each is told to the brain on a `Picture:` line under the source and recorded with it in `_meta.sources`. `ui/markdown.js` hands an image to the layouts capability, which draws it only when its address is one of those, then loads the source's own address, never the one written, without a referrer; its site is among those About this answer says the answer reached (D252). Compare and choose browses an option's own Wikipedia article when no source gave a picture: the brain's own search brings no pictures, and shops' pages refuse other sites' reads.
- **A runtime that needs `'unsafe-eval'`** gets a worker document of its own, never a looser `index.html`.

**`sandbox.html`**, framed with `sandbox="allow-scripts"` and never `allow-same-origin` (D65, D162):

```text
default-src 'none'; script-src 'sha256-<relay>' blob: 'wasm-unsafe-eval' 'unsafe-eval'; worker-src blob:;
connect-src 'none'; base-uri 'none'; form-action 'none'
```

- **No access to Jean's storage** (its origin is opaque) **and no network at all.** It holds only a small inline relay, allowed by its hash. `test/html.test.js` checks the hash and that the frame never gets `allow-same-origin`.
- **The parent sends everything in.** `ui/sandbox.js` fetches the worker's source and, when a run first needs them, an engine's files (listed in `capabilities.json`), and posts them to the relay.
- **Untrusted code runs only in a Worker** made from a `blob:` URL, so it inherits the sandbox's CSP; workers have no navigation, no WebRTC and no `sendBeacon`. It is a classic worker, since browsers refuse module workers from `blob:` in an opaque origin; it can still `import()` blob modules and compile wasm, and Emscripten gets `wasmBinary` and `wasmLocation` so nothing resolves against a `blob:` base.
- **QuickJS:** 64 MB of memory, 20 s of computing time (waiting on Jean or the user doesn't count), 20 s to start, 8,000 characters of output; a script reaches only what Jean hands it ([Codemode](#prompt-tools-and-caching)).
- **Pyodide** needs `'unsafe-eval'` as it starts (Emscripten builds some functions with `eval`); with nothing to steal and nowhere to send it, that costs nothing. Its files are Jean's own pinned copy (D43), sent in like QuickJS's; its `fetch` serves only those, under an address that never resolves. `import js` reaches only Jean's `fetch` and what pyfetch needs. Its memory and time can't be capped without cross-origin isolation, so the parent's watchdog stops a run that goes quiet; 60 s to start.
- **The internet goes through Jean** (D162): a request crosses to Jean, which judges it by Settings › Computer (`caps/computer/net.js`), asks first for a new site, and makes it with no cookies and no referrer, through the relay when there is one, adding a registry's key there. Approvals' Using the internet is the most it may do (`computerRights()`): Never there turns its internet off; a rule an organisation or a parent locked short of Do it takes Any site away, and `*` among the sites, and in a child's profile the sites the child added count for nothing, only policy's. See [Computer](#computer).

**A file's pane** (D126, D143, D158) shows a web page in `preview.html`, framed with `sandbox="allow-scripts allow-forms"` and nothing more (`PAGE_SANDBOX` in `ui/csp.js`), given nothing but the page and its policy. Forms, because Chromium fires a form's `submit`, and closes a dialog by its form (`method="dialog"`), only where forms are allowed; both policies' `form-action 'none'` sends none. `preview.html`'s own policy is the most Settings can allow:

```text
default-src 'none'; script-src 'unsafe-inline' data: blob: 'wasm-unsafe-eval' https:; style-src 'unsafe-inline' https:; img-src data: blob: https:; media-src data: https:;
font-src data: https:; connect-src https: http://localhost:* http://127.0.0.1:*; frame-src 'none'; base-uri 'none'; form-action 'none'
```

Its relay, inline under `'unsafe-inline'` (a hash would turn that keyword off), writes a doctype, then the policy Jean sent as a `<meta>`, then the page, which keeps the document's policy and adds that one. `ui/csp.js` makes it, and the frame's `allow`, from five switches in Settings › Approvals, which `pages` in `policy.json` can set and lock:

| Switch | Default | Adds |
|---|---|---|
| Run its code | on | `script-src 'unsafe-inline'`; for a page whose scripts are data (the user's folder, the workspace, an Office file), also `data:`, `blob:` workers and pictures, and `'wasm-unsafe-eval'` |
| Go full screen | on | `fullscreen *` in the frame's `allow` (`*`: WebKit doesn't match an opaque origin to `'src'`) |
| Save files | on | Jean saves a file the page hands it, after a click |
| Load things from the internet | off | `https:` for pictures, sounds, fonts, styles and, when they run, scripts |
| Send and receive over the internet | off | `connect-src`: any https site (`*`), or only the sites listed, each added with Enter: `example.com`, `*.example.com`, `*.com`, and this computer over http (`localhost:3000`, `localhost:*`) |

- **A map** (D291) asks Jean, through the relay's frame, for MapLibre and for every address it needs, which Jean fetches from the map service alone, once maps are allowed; the page's own policy stays as it was.
- **A page in an answer** (D289) is framed the same way, under the policy of a page whose scripts are data. ## The room

- **Looks** (D111, D120, D125, D132, D174, D373): `ui/style.css` is the room; each other theme (a "look" in code) is `ui/looks/<id>.css`, loaded when chosen, every rule under `:root[data-look='<id>']`, with light and dark palettes and system typefaces, and `test/looks.test.js` checks AA contrast. ## Languages (i18n)

- **Strings** live in `locales/<lang>.json`, English the source, with `{name}` placeholders. Plurals use `Intl.PluralRules` (Arabic has six forms); dates, numbers, lists and relative times use `Intl`; language names come from `Intl.DisplayNames`, each in its own language.
- **Choosing.** `preferredLocales` matches `navigator.languages` to the catalogues by language and likely script (`Intl.Locale.maximize`), so `zh-TW` finds `zh-Hant`, `pt-BR` finds `pt` and `iw` finds `he`; an exact tag wins first, so `fr-CA` finds Canadian French and `fr-BE` French. The menu lists those matches first, under "Your languages".
- **Where browsers lack a language** (D496). Chromium has Breton's plurals but not its dates or its name, and WebKit answers for Corsican with blank root data ("2026 M10 22", plurals with only *other*). So every Intl call that formats for the reader (dates, numbers, lists, durations, plurals, language names) takes `intlLocales()`, which is `['br', 'fr']` for Breton, `['fr']` for Corsican and the language itself otherwise: French is how Corsica and Brittany write their numbers and dates, and what the browser lacks in Breton it takes from French.
- **One catalogue per person, in parts** (D76, D97). `useLocale()` fetches only the chosen language, English only when that fails. The dialogs' strings are `locales/dialogs/<lang>.json`, loaded with `useStrings('dialogs')` by `ui/dialogs.js`. A capability whose strings would weigh on the first load has its own part, `locales/<id>/<lang>.json`, loaded with `useStrings(id)` and cached with it.
- **Instant switching.** The locale is a signal, so every bound text re-renders; `<html lang dir>` flips, and CSS uses logical properties only, so right-to-left mirrors at once.
- **Translation** (D44). A brain translates from English, about 680 strings per language, with no review language by language; anyone can fix one. Sentences are written so nothing agrees with `{name}`.
- **The 46 languages** (`LOCALES` in `core/i18n.js`): am, ar, bg, bn, br, co, cs, da, de, el, en, es, fa, fi, fr, fr-CA, ha, he, hi, hr, hu, id, it, ja, ko, mr, ms, nl, pl, pt, ro, ru, sk, sv, sw, ta, te, th, tl, tr, uk, ur, vi, yo, zh-Hans, zh-Hant. Canadian French is French's catalogue with Canada's words and spacing. Greek asks with ; and never ?, and Romanian writes ș and ț with a comma below, never a cedilla. Czech, Slovak, Croatian, Greek, Hungarian and Romanian put a noun before a name they would otherwise inflect, and Hungarian and Finnish never add a case ending to a placeholder, since its form follows the sound of what fills it. A plural form more than one number takes shows the number: Croatian's "one" is also 21's, Breton's "two" 22's, Filipino's "one" 2's.
- **Conversations.** The prompt stays in English with a `<language>` section; changing the UI language mid-conversation appends a note, and the next reply follows.

## Prompt, tools and caching

Four mechanisms from pi 1.0, fitted to Jean, share one idea: what the brain has read never changes, so providers can cache it and the device's runtime can keep it in memory.

**A frozen prefix** (D46). When a conversation starts, Jean fixes the system prompt and the declared tools, and neither changes until it ends. Providers cache by prefix (Anthropic reads tools, then system, then messages), so one changed byte at the front re-bills the whole conversation; on the device, the same rule keeps the KV cache between turns.

**System notes** (D46, D81). A change mid-conversation (language, rules, instructions, memory, skills, the project, new tools, the date) is a note appended to the transcript where it happens.

- **Sections.** The project, instructions, memory, skills, connections (`<connections>`, D89), the folder (`<folder>`: its name, top level and four tools, and its `AGENTS.md` when the user took it, D152) and the page on show (`<page>`, D140) are sections of the frozen prompt, each asked for the task the message goes to (`sections(task)`, null for a new one on screen: a task out of sight has its own folder and no page, D317); each has a fingerprint (FNV-1a), and one that changed arrives whole in a note ("The <memory> section is now: …").
- **Notes a message comes with:** "Since last time" starts with when the user was last here (D101); the terminal's commands, with their exit codes and output (D166); what / and @ named in it, a skill with its steps, an earlier task as it went (D199).
- **Recorded:** a note is an ACP extension update (`_system_note`) in the conversation's JSONL, holding the English the brain sees and data for the UI's label, so replaying the file rebuilds what the brain was told, and when.
- **Rendered per adapter:** for Anthropic, a `system` message after the next user message, on models that take one; for OpenAI and OpenRouter, a `system` message where the note falls; for other servers and the device's brain, whose templates allow a system message only at the start, a tagged block at the top of the next user turn.
- **Never deleted:** removing a note is an edit, which breaks the cache from there on.

**Deferred tools** (D47, D63, D64, D104). A conversation declares the tools unlocked when it started; anything later is deferred, including every connection's tools.

- `find_tools` and `offer` come from the `discovery` capability, always loaded, so every conversation declares them. `find_tools(query)` ranks undeclared tools by name and description with BM25 and returns up to five signatures (`name({ file: string, pages?: string }): what it does`).
- A capability turned on mid-conversation adds the note "New tools can be found with find_tools: …" (`data: { kind: 'tools', added }`).
- A tool the user turns off (`off`, Web search's switch, D304) is declared by no conversation started meanwhile, and stays declared where it was, so the prefix holds: that conversation is told it is off, then on again (`data: { kind: 'switch', off | on }`), the loop refuses its calls, and `find_tools` never offers it.
- With `javascript` declared, deferred tools are called from a script and the declared list never changes. Otherwise `find_tools`, or an accepted offer, declares them from the next request on, recorded as `_meta.declare` on the call, at the cost of one cache miss. A tool called by its exact name, as `<connections>` gives it, runs under the rules without being declared; a missing argument gets the signature back.
- The next conversation declares a newly unlocked capability's tools directly; connections' stay deferred.

**Codemode** (D48). `javascript` runs a snippet in QuickJS on the conversation's computer; top-level `await` works, and the result is what the script returns or its last expression. Inside, Jean exposes what the user has granted, and nothing else:

| Global | What it does |
|---|---|
| `file(name)` | A shared file's whole text (spreadsheets as tab-separated rows), or a file of the conversation's folder, through the hidden `file` tool |
| `csv(text)` | CSV or tab-separated text as rows: objects keyed by the header, numbers as numbers. The separator and quoted cells as `csvRows` reads them; the header is the first row of two filled cells or more, past a title line |
| `tools.<name>(args)` | Any granted tool, deferred and connection tools included; not `bash`, `javascript`, `python`, `offer`, `delegate` or `ask_user` |
| `fs.readFile`, `fs.writeFile`, `fs.readdir` | The computer's files: /workspace, kept after the run (D162) |
| `fetch(url, init)` | The internet, through Jean, as Settings › Computer allow |
| `searchTools(query)` | `find_tools`, from a script |
| `models.decide(state, questions)` | Kev on the device when Intuition is on, through the hidden `decide` tool |

Every nested call goes through the rules (`ctx.call` in `core/loop.js`); a call that needs approval pauses the script, and the wait doesn't count against its time. Nested calls carry `_meta.parent`, show under their call, and stay out of the brain's context, since the script's result holds what matters. Each crosses to Jean as a message and Jean makes it with its own keys, so the sandbox never sees a secret.

**Thinking blocks are kept** (D54) on each step's brain entry and replayed unchanged to the model that wrote them.

**A conversation near its window is summed up** (D359, `caps/compact/`), the way Anthropic's "simple compaction" does it, for every brain. `runAgent` gives the turn its brain's window (as files get theirs, D55) and what it last read and wrote; before each step, `turn.compact` asks Compaction, which loads the first time a conversation passes half its window (a local server's: half of 4,096, its smallest). Its size is the last request's usage plus Jean's estimate of what came since (a third of the bytes), or the estimate alone, and the larger of the two on a local server, which may count only what it kept; Ollama and LM Studio are asked the window they gave their brain, once past 3,072 tokens, and the answer is kept for the page's life. Past 75%, the same brain is asked, on the same system prompt, tools and history plus one request in English, for a summary in the conversation's language: a cache hit over the whole history, and local when the task is. The record is ACP's `compaction_update`, appended with the step it comes before: its `summary` is the brain's, for the user to read, and `_meta.text` holds what the brain reads from then on, as the user's message: the summary, then what Jean knows for sure, the sources and files by number, the latest note of each kind in force, the plan as it stood, and the request being worked on, word for word, with what the user said since to steer it (D71, D55, D364, D365). `toChatMessages()` starts at the last one, the loop replaces its history with it, and the turn goes on, so no thinking block is bound across it, nothing waits (D212), and the frozen prefix still holds: tools and system stay cached, the messages miss once. A request too long before anything came (`too_long`: each provider's own words) is summed up once and asked again. Helpers' and flow steps' turns have no window, so they never are.

**Caching and warming on Anthropic** (D49). One `cache_control` breakpoint on the system prompt's last block, plus top-level automatic caching for the conversation. When the user starts typing after about 5 minutes without a request, Jean sends the same prefix with `max_tokens: 0`, with the real request's thinking and effort. OpenAI caches by itself; local servers keep their KV cache, which the frozen prefix keeps valid; the device's brain reads only what follows the text it already read (D58), a long prompt 2,048 tokens at a time, each part going into the cache before the next (D350).

## Retrieval and extraction

- **Extraction:** DOCX, XLSX and PPTX through the tag scanner; PDFs with pdf.js, on demand. A Numbers spreadsheet (`caps/files/numbers.js`) is a zip of `.iwa` parts, each chunks of raw Snappy holding protobuf messages that point at each other by id; with no schema, it reads only the fields it needs, after Apple's messages. A PDF page's text is joined by `pageText` (`caps/files/extract.js`, which node runs too): a right-to-left line in reading order (pdf.js gives each word right but the words as drawn), Arabic presentation forms and Kangxi radicals as the letters they stand for, a line wrapped between Chinese or Japanese characters joined again, and lines set larger than the size most of the document is set in marked as headings. Pictures are kept no larger than 1,568 pixels a side and go to brains that can see, right after their `<document>` tag; a brain that can't is told there is one (D105). So is a scan, a PDF whose pages have no text: `pagesSeen` (`caps/files/pictures.js`) has pdf.js draw its first twenty pages as JPEGs of that size, and a brain that can't see is told it is a scan (D479).
- **A shared file in the message** (D24, D55, D301): a document that fits in about 25% of the brain's context goes in whole; otherwise its first pages do, or for a brain of 32k or less its page 1 and the pages that match the message, and `read(file, pages)` reaches the rest. The choice is made once, when the message is sent, and recorded on the file's link (`_meta.pages`, a list of page ranges). Tokens are estimated as UTF-8 bytes / 3. Past conversations are searched with BM25 (`recall`).
- **Searching inside documents** (D24, D301), in core: `passages()` cuts a document's pages into passages of about 100 tokens, never across a page, where a line ends or a heading starts; each carries the path of the headings above it and a table's column names. `lexicon()` indexes them once, in typed arrays, by folded words and codes kept whole (C-4471 as well as c and 4471); `lookup()` ranks across several files' indexes as if they were one. `preselect()` picks, for a brain too small for a file, the pages that best match the message instead of the first ones: a brain of 32k or less gets them, as page ranges in `_meta.pages` (D301). The files capability declares `search_files` (`caps/files/search.js`), which gives the best passages with their file, page and source number, or every place a phrase is (`every()`). A file's passages and index are made the first time it is searched and kept as `.cache/words/<file's hash>.idx`.
- **Search by meaning** (D302, `caps/meaning/`), a capability of its own, offered by the brain when `search_files` finds nothing by words (the tool's answer says it may). Turned on, it downloads EmbeddingGemma 2's text model, about 175 MB once, on WebGPU only: both graphs keep the vocabulary quantized with an operator ONNX Runtime's WebAssembly lacks (`GatherBlockQuantized`). In Chromium on an M-series Mac it reads about 80 passages a second (q4f16): an 800-page file in 2 to 3 minutes, a 4,200-page one in 11 to 18. Each file of the project is read, in the background, into a vector for each of the passages `search_files` cuts (prefixed `title: none | text:`), 768 numbers in a byte each, kept as `.cache/meaning/<dtype>/<file's hash>.i8`; a question's vector (`task: search result | query:`) is compared with every passage's, a flat scan, no index. `search_files` then fuses the best 200 by words with the best 200 by meaning by their ranks (reciprocal rank fusion, k = 60). On the document evals' L files, words and EmbeddingGemma 2 find 91% of the evidence within 32k tokens and 88% within 8k, the best of six, and words alone 73% and 62%.
- **What the document evals found** (D24, D301): `test/documents/results.md`, a fictional company's files up to a 4,196-page PDF of 4.3M tokens. For a 32k brain, the matching pages answered every lookup and the first pages none (H7); at that size the first pages hold 12% of the evidence within 32k tokens, lexical search 66%. Embeddings earn their place for meaning (H4 refuted: on paraphrases and other languages, lexical search answers 20 points below hybrid).
- **The document evals** (`test/documents/`, `npm run documents`): a fictional company's files made from a seed at five sizes, in every format Jean reads and four languages, with nine kinds of questions whose answers and evidence are known.
- **Source numbers** (D71, D90): each shared file gets a number on its link (`_meta.source`), kept if it is shared again. The brain sees `<document source="n" name="…">`, and `read` starts with "Source [n]:". A file's mark may say where in it (D481): `[n: "exact words"]`, which the files capability's rule asks for, `[n, p. 3]`, or `[n: x,y,w,h]`, an area of a picture in percent from its top left, in Media Fragments' order (`xywh=percent:`). `cite()` makes it a chip whose title is the words, and `openFile(link, at)` shows the file with what follows its number, a project's file that `search_files` found too (by its `files/` address, as the search cited it); a source that can't open keeps its chip, without the place. `anchor()` (`caps/files/search.js`) finds the words in the file's text as `every()` finds a phrase, whatever its case, accents, line breaks, quotation marks, apostrophes and dashes, and the view marks them (`ui/view.js`); words the file doesn't hold open it at the top, and Double-check counts them missing without asking. A web page's chip shows a tip with its site's icon, its domain and the page's title (D210), the icon from DuckDuckGo's icon service (`siteIcon` in `DEFAULT_URLS`, `''` shows none), loaded lazily, and never with a referrer.

## Documents

A document Jean keeps (D473, D474, D485) is a Markdown file of the project, `documents/<ulid>-<slug>.md`, named once and never renamed, its `format`, `name`, `author` and times in front matter. One the user makes from the Creations page has no `name`: it goes by its title, its first line when that is a heading of the first level (`nameOf()`). The brain makes one with `document` (`caps/documents/documents.js`), which writes it, puts it under the answer as a card (`_meta.files`) and opens it beside the task, and changes one with `suggest`, its whole new text.

- **In Jean's document.** The editor (`editor.js`) runs in Jean's own document, under `index.html`'s policy: ProseMirror is the one bundle `#prosemirror` names, loaded with the first document opened. Nothing in ProseMirror, its plugins or the schema needs a Trusted Types policy or a style attribute (a column's alignment is `data-align`) but ProseMirror's own reading of pasted HTML, with `innerHTML`: the HTML a paste or a drop brings is taken on the DOM's `paste` and `drop` events instead and read in a small sealed frame, `preview.html`'s relay under `pagePolicy(…, true)` with nothing from the web or to it, made at the first paste. It runs `clipboard.js` (`cleanTree`, Word's and Google Docs' lists made lists) and answers on a `MessageChannel` with a tree of only the elements, attributes and styles a document keeps; `fromTree` builds that in an inert document, where nothing loads, and ProseMirror reads it. Pictures pasted with words are drawn at once from their addresses, which join `brought`, then each is fetched with no cookies and no referrer and kept the same way, its address replaced. The addresses still in the document are written back to its front matter's `pictures`, separated by spaces, and read again as it opens. A picture is drawn (the image's `toDOM`) from a file of the project (`<app-shared>`) or from an address in `brought`, never any other, which is its words (D35), so nothing the brain writes loads.
- **The title.** A document's first line is always its title: a node of its own in the schema (`title`, `doc` being `title (block | columns)*`), written as a heading of the first level, holding text alone, where "/" doesn't open and Markdown typed at its start stays text; ProseMirror itself keeps anything from going before it or turning it into another kind, a paste's first line joining it, plain, and the rest going after it. `titled()` makes it as a file is read, and `serialize()` doesn't write an empty one, so a new document, or one emptied, stays empty in its file until something is typed.
- **Out** (D663, `caps/made/paper.js`, Save in the pane's top). `onPaper()` (`ui/kit.js`) gives what paper wears of the kits here, an answer's as a document's: colours for words deepened to read on white, the pale fill where its words read on it, its own fonts or voice, a logo that is a picture inside the kit, and its corner. **Word** (`makeFile()`) has them in its styles, the logo drawn as a PNG. A document's Markdown goes with its pictures from the project and the `picture()` of each block drawn on the page, by its code. **A print** of anything, by `dress()`: an adopted sheet for `.prose` under `@media print`, the logo in place of Jean's mark. **A document printed** (`printPage()`, or ⌘P from inside it): `view.dom` copied into `.paper-print`, what Jean suggests left out, each `app-` element emptied to draw itself again, out of sight at the width of A4's text for up to 3 s, then the only thing on paper until `afterprint`.
- **On screen** (D664, `dress()` in `paper.js`). A document's or a collection's pane wears the look in the same adopted sheet, under `@media screen`, as `onScreen()` (`ui/kit.js`) gives it for the room's theme, by setting the room's variables (`--ink`, `--flame`, `--line`, `--room-2`, `--sans`, `--display`…) so that all inside follows, the pane's head and what floats over it staying Jean's.
- **Saving and telling.** The editor writes the file 0.3 s after a change, on ⌘S, when the keyboard leaves it and as the page goes, through `app.fs` with its front matter's `changed`.
- **What an answer draws** (`drawn.js`). A top-level list, quote, table, code block or formula set apart is a node view that holds, beside ProseMirror's own drawing of it, the answer's form: `ui/markdown.js`'s `blocks()` of the block's Markdown, drawn again as the block changes or what draws it loads. The form shows while the caret is elsewhere, the block's text once the caret is in it (a click on the form, the arrows from the block before or after) or a selection of text crosses it (`inPlace`): always editable, with no modes. Jean's suggestions draw such a block too (`forms`, `suggest.js`).
- **What the brain reads.** While documents show, each message comes with a note for each (`kind: 'document'`, the `modes` slot) of its place and its text as it is now, unless the last note in the task said the same. Which documents the project keeps is the prompt's `<documents>` section (D488): the latest 20 made, read from their front matter each time. `suggest` with a document not on show changes nothing: it opens it and answers with its text, which the brain changes with its next call, so it never rewrites a document it hasn't read.
- **The editor** (`editor.js`): marked's lexer reads the file into ProseMirror's document (`markdown.js`), with Jean's formulas; a block the user didn't touch is written back byte for byte, its blank lines with it, a changed one with the markers it was written with, escaped no more than reading it back needs, and a list of a kind right after another with its marker is written with the other marker (`-` and `*`, `.` and `)`), so the two stay two. ## Activity events

Jean's event format is ACP's `session/update`: `user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update`, `plan`, `compaction_update` (D359), plus `session/request_permission`; the types come from ACP's published schema as JSDoc.

```jsonl
{"at":"2026-10-01T10:02:11Z","by":"jean","update":{"sessionUpdate":"plan","entries":[{"content":"Read the invoices","priority":"high","status":"completed"},{"content":"Total per client","priority":"high","status":"in_progress"}]}}
```

- **One stream, one record.** The core emits the events, the UI renders them live, and the conversation's JSONL stores them, each wrapped in an envelope with a time and an author. - **Every line opens** on what went in and came back (D103): a call's tool, arguments, result and duration; a brain step's thought and text, how it stopped, its duration and usage (`_meta.ms`). ## About this answer

The `receipt` capability (D252) loads with the first message, never offered, so that the browser's record of the page's requests covers the first answer, and stays. The certificate comes last, folded under *Certificate*, the card being a glance; the witnesses' choices (D276) are folded again under *More options*, open as the card opens when a witness was chosen, so that nothing goes out unseen. `<app-receipt>`, among an answer's buttons, reads everything from the conversation's records (`caps/receipt/certificate.js`, pure):

- **Time:** from when the answer was last asked for to its last record (`Turn.end`).
- **Brains:** every brain entry of the turn, its helpers' included, with whether it runs on this device (`rawInput.local`) and when it was asked, which its id holds (`brain-<step>-<ms in base 36>`).
- **Makers** (D264): each picture's and film's call records who made it (`_meta.made`: `{ kind, provider, model, local }`, a provider's model, or one of this device's by its name, `NAMES` in `caps/pictures/device.js`, with its weights' `revision`, D274); the card lists them under Made by, and the certificate keeps them as `made`.

- **The certificate** (D274), saved as a JWS in flattened JSON (RFC 7515 7.2.2, `application/jose+json`): `{ payload, protected, signature }`, which `caps/receipt/certificate.schema.json` describes (JSON Schema 2020-12, its `$id` the tag URI `tag:jean.is,2026:answer-certificate`). **The seal:** `makeSeal()` makes a non-extractable ECDSA P-256 key pair and, with `der.js`, the X.509 v3 certificate that key issues itself, named by its RFC 7638 thumbprint (D324). **The header** is JAdES's baseline B-B: `alg` ES256, `typ` `vc+sd-jwt`, `iat` in whole seconds, `x5c` the certificate, `x5t#S256` its SHA-256, no `kid` or `cty`. **The payload,** a W3C VC 2.0 (`certificate()`): an `id` (`urn:uuid:`), the `issuer` (`urn:ietf:params:oauth:jwk-thumbprint:sha-256:<thumbprint>`, an RFC 9278 URI, so no other key speaks for the device), `validFrom`, `_sd_alg` (`sha-256`); in `credentialSubject`, the conversation's id, `where`, `ms`, the request's and the answer's times with salted digests of their words and files, the brains with their usage, the makers with theirs; and in `evidence`, the browser's records (`ResourceTimingRecord`), their hosts salted. Save the proof writes the SD-JWT, `<jws>~<disclosure>~…~` (`application/vc+sd-jwt`, `.sd-jwt`), the disclosures made again from the kept salts (`disclosuresOf()`), then the places. **`check({ certificate, proof })`** reads the certificate in `x5c` (`readCertificate()`) and says it is `intact` when the signature over `protected.payload` holds by its key, `x5t#S256` is its, the issuer is its key's thumbprint and `iat` falls within its time.

For a certificate, once `vouched()` is done, `lasting()` (`ee/lasting.js`) appends `xVals` for the chain and `rVals` (OCSP responses and CRLs) that `revocation()` asked for, of the chain and of each witness's. `check()` takes `trust` where policy names anchors: `verdict()` (`ee/trust.js`) follows the chain from `x5c` and `xVals` to the first that is an anchor or that one issued, each valid at `iat`, then reads `rVals` for each.
- **The organisation's qualified seal** (D436, [enterprise.md](enterprise.md#the-organisations-seal)): with `seal.csc`, `ee/authority.js` goes on with a seal for a key a provider holds: `keys.publicKey` that key, no private half, and `sign`, which `signOf()` (`caps/receipt/der.js`) calls in place of Web Crypto, for `seal()` and for `c2pa.js`, which signs once, after its loop, since an ES256 signature is always 64 bytes. `ee/csc.js`'s `credentialAt()` asks `<csc>/credentials/info`, and refuses any key but P-256, a disabled key, a certificate not valid now, or an `auth.mode` but `implicit`; `sign()` posts the SHA-256 of the bytes to `credentials/authorize` for a SAD, then to `signatures/signHash`, and checks the signature by the key.
- **The EU's trusted lists** (D439, [enterprise.md](enterprise.md#the-organisations-seal)): an item of policy's `trust` with `lotl` and `signers` has `trust()` in `ee/ee.js` ask `anchorsFor()` (`ee/listed.js`), for each sealed certificate, for the anchors of the countries its certificates' names give. A picture the user shares is kept as given, with whatever marks it carries; brains see a copy no side of which passes 1568 pixels, made as the message is sent (`seenBy()` in `caps/files/pictures.js`, `seen()` in `ui/send.js`).
- **Files Jean makes say so** (D324, `makeFile()` in `caps/made/formats.js`): a `.docx` and an `.xlsx` get `docProps/custom.xml` (`DigitalSourceType` IPTC's `trainedAlgorithmicMedia`, `AISystemUsed` the brand's name).

## Web search

1. **The brain's own search** (D91): `web_search` is marked `native`, and the adapter declares the provider's tool instead: Anthropic's `web_search_20260209` from Claude 4.6 on (`web_search_20250305` before), or OpenRouter's `openrouter:web_search`. Anthropic's search blocks are kept on the brain entry and replayed as received; an organisation that turned search off gets Wikipedia. It is so only while Wikipedia from the web is the one source on, or none is (D271).
2. **The sources built into Jean** (D271, `caps/search/sources.js`), for every other brain, the device's included: **Wikipedia,** in the user's language, on unless turned off (`urls.wikipedia`); **Vikidia,** the encyclopedia for 8 to 13 year olds, off until turned on (`urls.vikidia`; its editions are `VIKIDIA`, and a language it lacks is told to the brain with those it has); and **the offline library,** a Kiwix server (`urls.kiwix`, none by default). Which are on is `searches` in settings (Wikipedia alone until the user changes it), or policy's, which locks the switches. `web_search` searches every source on at once, five pages from one, three from each of several; one that doesn't answer is named to the brain, and when none does, the call fails. Any source but Wikipedia from the web takes `native` away, so every brain searches what the user chose. Wikipedia and Vikidia are MediaWiki's API, or **a Kiwix server** named in their place (D254), any address but `api.php`, whose books of their category alone are searched (`books.filter.category`); the library searches every book. Vikidia's site refuses to show inside another page (`X-Frame-Options: SAMEORIGIN`), so the browser opens its pages in a tab at once (`OWN_TAB`). `caps/search/kiwix.js` reads the languages of its books from its catalogue, searches the books in the one asked (`/search?books.filter.lang=…&format=xml`; a library in a single language whatever the one asked), and puts each page's first paragraphs in place of its snippet, outside its tables, whose infobox holds a caption's or a note's own. Jean reaches a Kiwix server on this computer, or anywhere over HTTPS: its policy allows plain HTTP only to this computer (D260), whose own network addresses only the desktop app knows, and a page served over HTTPS couldn't fetch plain HTTP from the network anyway. So a Kiwix Hotspot, which serves plain HTTP at the computer's Wi-Fi address, is reached from the desktop app alone.
3. **A search service connected like any other** (D192): Exa's needs no key and no sign-in, and is one of the services Jean knows; an organisation adds its own to the directory by policy. Search speaks MCP like every connection, so there is no search endpoint of its own in settings. Settings › Web search lists the connections that search the web, as each capability loaded says (its `searches`, D271); it decides nothing itself. Connections gives each connection whose tools say they search the web, by `searchesWeb()` in `caps/connections/mcp.js`: a name with *search* in it, *web* or *internet* in the name or the description, and annotations that neither close its world (`openWorldHint: false`; a web search is MCP's own example of an open one) nor say it changes anything (`readOnlyHint: false`). Exa's `web_search_exa` is listed, its `web_fetch_exa` and a mailbox's `search_emails` are not. The list is only shown: the brain finds those tools as it finds any connection's, and they ask first as reading through a connection does.

**+ turns it off** (D304): once found, its row in + is a switch (`search: false` in settings). Off, `web_search` is an `off` tool with no line in the prompt, so a task started meanwhile has no web search, the brain's own included; one that has it keeps it declared and is told (see [Prompt, tools and caching](#prompt-tools-and-caching)).

There is no Jean proxy. Fetching an arbitrary address meets the same CORS wall.

## Connections (MCP)

A connection is an address and, when the service asks, a key or a sign-in (D87–D89, D95).

- **The directory** (`caps/connections/directory.js`) lists the services Jean knows, those people at work use most, from the public lists of remote MCP servers (D192), among them GitHub (D468), GitLab (D469), Qonto (whose server sends no money: a transfer it prepares waits for approval in Qonto's own app, D352) and Exa, with no key and no sign-in. Each has its brand's logo (`caps/connections/logos/`, D159, several against their terms, at the owner's call), and is reached from the browser (`ready`), through the gateway once it relays to the service and its sign-in's hosts (`signIn`) and holds the app a sign-in that registers none takes (`app`, its issuer, D214), or not yet. An entry may reach further servers with its one sign-in (`servers`), and name what that sign-in asks for (`scopes`): Google is one entry, its eight servers behind one sign-in (D344). An entry may also be an API that answers browsers rather than an MCP server (`api`), called by Jean's own tools, whose sign-in server is its `app`, so that only that sign-in needs the gateway: Gmail, Google Calendar and Google Drive (D349); or none, its sign-in answering browsers too: Microsoft 365 (D382). ServiceNow has no address of its own, each company having its instance: its tile has none until policy gives the instance's MCP server, reached through the gateway alone, since instances answer no browser (D283).
- **Accounts and projects** (D191): a tile stays once its service is connected, ticked, its page saying that another sign-in adds an account, whose sign-in asks which (`prompt=select_account`). Two connections whose names start alike are each called by who signed in, or else by number (`called()`); the first made, by its ULID, keeps its tools' names, and the next take `_2`, `_3` (`mail_2_search_emails`). A connection's `projects` keeps it to those projects; without it, it is in every one.
- **A service's own rules**: the user's choice for a connection's reading or acting is `settings.services[<id>][<kind>]`, unset where it follows the kind's rule. The capability's `tool.check` hook, on every call that names a service, puts it over the rule (`chosen()`), never freer than a rule the organisation set, the guards still coming after; and marks the call `_meta.service`, so a card's Always allow or Never on it is kept to that service (`service` among send.js's `SCOPES`, `keep()`), with a toast leading to its page, not written for every service's kind.
- **The client** (`mcp.js`) speaks Streamable HTTP: the stateless 2026-07-28 revision first, then the `initialize` handshake and session of 2025-03-26 to 2025-11-25 when a server answers like an earlier one.
- **Signing in** (`auth.js`) follows MCP authorization from the browser: protected resource and authorization server metadata (an issuer compared as an address, so `https://otter.ai/` is `https://otter.ai`; with no resource metadata, the server's at the service's own origin, and no `resource` sent; a service that names itself, whose metadata there names its origin, as ServiceNow's does, has it at that origin, held to what the origin's own metadata says, D283; Atlassian at its `/v2/mcp`, which names its sign-in server, as its guide says to use, `/v1` ending on 1 March 2027: its CORS allows any header with `*`, which the standard says leaves out `Authorization` but Chromium and WebKit let through, as `npm run directory` does, Firefox unchecked), dynamic registration as a public client, PKCE with a `resource` indicator, the `iss` check; a known service's `scopes` replace the metadata's, and its `authorize` parameters are added, `prompt` joined with `select_account` for another account; `openid`, `email` and `offline_access` are asked for too where the sign-in server lists them, within the scopes a registration answers with, where it says (GitLab's gives `mcp` alone, D469), and the ID token's email, or else its login, is the connection's `account`, kept only when it looks like one, since the brain reads it. The redirect comes back to Jean's own address with `?state=`. Keys and tokens are encrypted in `.secrets/`, never backed up, and renewed before they expire; a refused renewal (not a network lost) marks the connection `error: 'auth'`, so Settings › Connections asks to sign in again, and the brain reads that the user has to (D344).
- **Tools** are `<service>_<tool>`, made JavaScript identifiers (D106), deferred and listed in `<connections>`; both kinds ask first by default. A connection with `servers` (D344) has a client for each, all with its one credential: `toolsOf()` keeps the tools of each that answered, each with its server (`at`), a name an earlier one took left out, and fails only when none answered; a tool is called at its own server.
- **A refused call** (D193): a service whose tools were listed without a sign-in may still refuse to run them (Exa publishes some and needs none); a known service that names its `scopes` signs in at once instead (D344). A call of a connection with no key or tokens that comes back 401 or 403 marks it `error: 'auth'`, keeping its tools and the refusal's challenge, so Settings › Connections offers to sign in (`signIn(connection, challenge)`), and the call's result tells the brain the user has to sign in first. An OAuth connection's 401 renews its token once instead, unless renewing was refused; its 403 tells the brain the sign-in doesn't allow that call.
- **Google Workspace** (D344) has a server a product (Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, and People for Contacts), all a developer preview for Workspace accounts that answers no browser, behind a sign-in that takes only apps registered with Google: it is one entry, whose one sign-in reaches all eight. Its scopes are the fewest that let every tool run, read from each tool's own resource metadata, asked with `access_type=offline` and `prompt=consent`, since Google gives a refresh token only then.
- **Google's own APIs** (`apis.js`, D349) serve any Google account, Workspace's or not: Gmail, Google Calendar and Google Drive are a tile each, with the same app and sign-in as Google Workspace, each asking only for its own scopes.
- **Google's data and brains that may train** (D440): Google's Limited Use bars its users' data, raw or derived, from training models. A connection with an address at `*.googleapis.com` (`limited()` in `connections.js`: Google Workspace's servers and Google's APIs) marks each of its calls `_meta.limitedUse`, and runs it only when the brain the call is made for (`ctx.brain`, the loop's) may not train: `mayTrain()` in `core/llm.js` is false for a provider marked `trains: false` there, for a brain that never leaves this computer (`isLocal`), and for one of policy's that says `trains: false`; a person's own settings can't say it. `mayRead()` says whether a brain may read a task's records, and the capability's `turn.step` hook refuses a request that would send a marked task to another.
- **Microsoft 365** (`apis.js`, D382) is one tile for any Microsoft account, personal (Outlook.com, OneDrive) or work and school: Outlook's mail and calendar, OneDrive and SharePoint, through Microsoft Graph (`graph.microsoft.com/v1.0/`), called from the browser as Google's APIs are, and signed in from the browser too. Microsoft's sign-in for every account (`login.microsoftonline.com/common/v2.0`, whose document names its issuer with `{tenantid}` in place of `common`, which `discover()` reads as the tenant asked about) answers a page for an app registered in Entra as a single-page app, Jean's address its redirect, whose client id policy gives (`directory: [{ id: 'microsoft-365', clientId }]`, jean.is's in its site policy); until then the tile is disabled. A gateway that holds a web app registered there (`clients`, issuer `https://login.microsoftonline.com/common/v2.0`) renews for 90 days instead, the tile reached through it when policy names no client id. In most organisations an admin consents once for everyone: Microsoft's default policy keeps mail, calendars and all files from a person's own consent. OneDrive finds files through Microsoft Search, which reaches SharePoint, and reads one from its signed download address, which takes no token (`/content` redirects there, which a request that needed a preflight can't follow).
- **GitHub** (D468) is its official server (`api.githubcopilot.com/mcp/`, its default tools: repositories, issues, pull requests and people), which answers browsers, behind GitHub's sign-in (`github.com/login/oauth`), which neither answers browsers nor registers apps: a gateway that relays to both and holds an app registered at GitHub, an OAuth app or a GitHub App with Jean's address as its redirect, reaches it. The sign-in asks at once for `repo` and `read:org`, all its default tools need, since its server asks for more mid-task with a challenge Jean doesn't follow: a call that needs another scope (`workflow`, to change a workflow file) is refused as one the sign-in doesn't allow.
- **GitLab** (D469) is its official server (`gitlab.com/api/v4/mcp`, on every tier, where a top-level group, or an instance's admin, allows MCP access; its default tools: projects, issues and work items, merge requests, files and pipelines, while wikis and security findings are toolsets a header asks for, which Jean doesn't send). It answers browsers, and so do its token endpoint and its OpenID Connect metadata, but not its registration, nor the metadata that names its scope, so its entry names it (`scopes: ['mcp']`): a gateway that relays to `gitlab.com` reaches it, Jean registering there as a public client, which GitLab allows only `mcp`, so the sign-in asks for `mcp` alone and gets no ID token (two accounts are GitLab 1 and GitLab 2).
- **The browser's limits:** a service must answer with CORS and expose `Mcp-Session-Id` (2025 sessions) and, ideally, `WWW-Authenticate`. When it doesn't, and no gateway reaches it, Jean says it couldn't connect.
- **The gateway** (`gateway/gateway.js`, D191) is for the services a browser can't reach (Google's sign-in, Slack and the rest refuse browsers or unregistered apps): whoever serves Jean, an organisation or a person, runs it and names it (`urls.gateway` in settings or policy; none by default), and a service typed by its address is tried through it when the browser can't reach it. It keeps nothing, and tokens stay encrypted on the device; what passes through is seen by whoever runs it, so it is the organisation's or the person's own. Its configuration, in `GATEWAY_CONFIG` and never in a file beside it (Jean's folder is served as it is), names Jean's origins, the hosts it relays to (none named, `SERVICES`: those of every service in the directory that isn't ready), the apps it holds, and the witnesses and logs that date and record certificates (`timestamps`, `logs`, D276). `GET <gateway>` answers `{ format: 1, hosts, clients: { <issuer>: <client id> } }`, with `timestamps` and `logs` when it has them; `<gateway>?url=<address>` relays: only from those origins, only to HTTPS on those hosts (HTTP on this computer, and an origin `hosts` names whole, such as an authority's OCSP responder, D434), redirects followed only to them, the request's `Accept`, `Content-Type`, `Authorization` and `Mcp-*` headers alone, at most 10 MB in and the answer streamed back with CORS that exposes `Mcp-Session-Id` and `WWW-Authenticate`. A token request to a configured endpoint that names its app gets the secret. A connection made through it is marked `gateway` and every request it makes, discovery, registration, tokens and MCP, takes the gateway's address at that moment (`urls.gateway`).

## Meetings

`meet`, in the projects capability (D224, `caps/projects/meeting.js`), has the assistants of the room's other projects, or of those named (a part of a name is enough), five at most, speak on a topic in up to three rounds (two by default), three at a time; from the second round each hears the minutes so far, so they answer one another. Each speaker is a hidden `speak` call, a child turn with no tools and one step, told who it is (its name, how to be), its project's instructions, the newest lines of its memory and its eight latest tasks with the start of each one's last answer, never another project's. The room's assistant chairs, reads the minutes and tells the user what came of it. A project kept on this device doesn't join when the brain is in the cloud, nor one the brain isn't used in (D194), and the minutes say who was left out and why. A meeting asks first, naming its projects; Always allow holds for those projects only (`meet` in settings), so a routine that holds one runs on its own. `speak` refuses a project with no meeting under way, so a script can't reach one.

## Flows

A flow's steps are each a text, a file of the project by its name (its newest version), instructions for the brain (an Ask, done as a helper's turn is, D98, following one of the room's skills when it names one) or one of the room's tools with its arguments, and wires say whose results a step takes: `{{Step name}}` puts a result where it is written, and an Ask gets the others after its instructions. A step can run once for each item of the list it takes (a JSON array, or its lines; 50 at most), three at a time, and a step that gives nothing stops the steps after it; a circle is refused.

SD-Turbo's worker squashes it whole into two squares, 448 pixels for Freepik's classifier and 224 for SigLIP's image encoder, on WebGPU, else WebAssembly, and answers Freepik's four logits and the areas SigLIP's view is close to (`check.js`). Nudity, then suggestive pictures when refused, then the areas: `make()` hides a glimpse that shows one, and throws for the picture, so the next engine is never asked; a check that can't run hides the glimpse and refuses the picture. A picture that passes gets its XMP from `marked()` in `mark.js`, then its Content Credentials from `credentialed()` in `receipt.js` (D324, above), before `addFile()` names it by its hash.
- **The law it keeps** (D275): Regulation (EU) 2026/1744 (the Digital Omnibus on AI, OJ L of 24 July 2026, in force since 27 July) inserts points (ba) and (bb) in the AI Act's Article 5(1), with 5(1a) and (1b), applying from 2 December 2026: no AI system may be placed on the market, put into service or used that generates or manipulates realistic images, video or audio of an identifiable person's intimate parts, or of them in sexually explicit activity, without their explicit consent, nor child sexual abuse material (Directive 2011/93/EU, Article 2(c) and (e)). A provider breaches it when that is the system's intended purpose, or a reasonably foreseeable and reproducible outcome without significant technical modification, and the system lacks reasonable and adequate technical safeguards to reliably prevent it, given foreseeable misuse, and to correct misuse observed or reported (recital 12 names prompt guardrails, output classification and filtering, abuse detection, notice and action). The open-source exemption (Article 2(12)) never covers Article 5. Cloud providers filter what they make; nothing filtered what SD-Turbo, FLUX.2 [klein] and Z-Image-Turbo make here, or Ollama and other servers on this computer.
- **The laws behind the other areas** (D280): none is a legal floor as nudity's is. Germany's §86a and §130 StGB, Austria's Verbotsgesetz and the EU framework decision on racism punish showing symbols of hate in public, with art, teaching, research and reporting excepted; Germany's §131 and youth-protection laws cover cruel violence; the WHO's media guidelines warn against showing self-harm.
- **What the check is, and what it was measured on** (D275, D280). Nudity: Freepik's NSFW classifier (MIT, an EVA-02 base, trained on pictures AI made too), at 4 bits, 60 MB; of its four levels, medium and high together at half or more, Freepik's own threshold, refuse the picture, and Refuse suggestive pictures too (`pictureCheck.suggestive`) counts from low on. The other areas: `caps/pictures/concepts.json` holds a few English words for each, read into vectors by SigLIP's text encoder (Google, Apache 2.0), and each area's limit; on the device, SigLIP's image encoder at 4 bits (63 MB) sees the picture at 224 pixels, and the picture shows an area when it is as close as that area's limit to any of its words. Measured on 158 pictures from Wikimedia Commons, look-alikes among them (Hindu swastikas, butchers, razors): symbols of hate at 0.07, 14 of 17 refused and 3 look-alikes of 134; graphic violence at 0.10, every colour photograph of injuries refused and 8 of 16 overall, with 2 look-alikes of 131; self-harm at 0.12, its one photograph refused and no look-alike. A refused picture isn't kept or shown, and the brain hears which area it was for, that it mustn't try in other words, and, for an area the user may allow, that Settings › Brains can.
- **The mark** (D279): `marked()` in `caps/pictures/mark.js` writes an XMP packet into the PNG, in an `iTXt` chunk right after its header, or into a film made on this device, an MP4, as a top-level `uuid` box at its end, XMP's own (D585), which alone marks it, without watermark or Content Credentials: IPTC's Digital Source Type, `trainedAlgorithmicMedia`, with IPTC 2025.1's AI System Used (the maker's name, or the model a server on this computer named) and AI System Version Used (the maker's pinned revision, D274). Nothing of the description or the person goes in. A picture from a provider is left as it comes (OpenAI and Google mark theirs, with C2PA and SynthID, and a changed byte would break a C2PA signature), and one from this computer that isn't a PNG isn't marked. The answer's certificate names the same type for every picture and film (D274).
- **In the conversation:** a picture or film is a file Jean made, so its versions, `from`, its pane and search find it. The film's approval carries `_meta.film`, so Always allow and Never write no rule for its kind (`SCOPES` in `ui/send.js`), and the tool keeps Always allow as `films` in settings.

## Deploying

- **A server reached over SSH** (D320, D321): `npm run deploy` (`scripts/deploy.js`) builds a commit from `git archive`, never the working tree, with `npm ci --ignore-scripts` and `npm run build:web`. Before the server, when npm lacks the render package's version that build names, it publishes it from the same build, `scripts/render.js` then `npm publish ./dist/render`, under the npm login on this computer, which asks for its one-time code; a failure leaves the server as it was. It then rsyncs all of `dist/web/` with `--checksum --delete` into `releases/<time in UTC>-<commit>/`, made first as hard links to the current release, so only what changed is written and an unchanged file keeps its time, and with it its ETag; `mv -T` swaps the `current` link, which the server serves, and the five latest releases stay, with any `tenants/pinned` lists (D456).
- **Bunny CDN** (D634, `scripts/bunny.js`, `deploy/bunny/`), where jean.is is served: `DEPLOY_TO=bunny:<storage zone>` builds and publishes as above, then uploads `dist/web/` but its `.br` and `.gz` copies, which Bunny makes itself, into `releases/<time in UTC>-<commit>/`, each with its type sent as `Override-Content-Type`, the only header the Storage API keeps a type from, and its SHA-256. The deploy refuses a pull zone that serves another storage zone or has no script, sets it, then writes three edge rules: `*/releases/*` blocked, the header set with its `Cache-Control` left out, since an edge keeps no file whose rule says `no-cache`, and every other address served from the new release's folder. It purges, waits 15 seconds for the rule to reach every edge, purges again, and keeps the five latest releases.
- **Jean's services** (D634, `deploy/server/`): one Compose file on a server in the EU that runs nothing else, Caddy in front of the gateway (`gateway.jean.is`), the share host (`hst.ing`), the request service (`keys.jean.is`) and the hosted copies' files. `/srv/jean/update` brings them to a commit: it takes a tar on standard input holding exactly `gateway/`, `requests/` and `host/`, keeps the code in place as `code.previous/`, asks each service for its `{"format":1}` within ten seconds, and puts the previous code back if one doesn't answer.
- **Continuous deployment** (D659, `.github/workflows/ci.yml`): every push to main, once `check` and `audit` pass, runs a `deploy` job in the GitHub environment `jean.is`, which only main can use and which holds every address and key as variables and secrets, never the repository. It runs `npm run deploy` with `DEPLOY_TO=bunny:…`, and npm 11's trusted publishing publishes the render package with the job's identity (`id-token: write`), which npm checks against the package's trusted publisher (this workflow, this environment) and records as the version's provenance. Then the commit's gateway, key service and share host go to Jean's server as a tar over SSH, to a key `authorized_keys` restricts (`command="sudo -n /srv/jean/update",restrict`), the server's host key pinned from `SERVER_HOST_KEYS`.
- **A search engine in the browser's bar**: `ADDRESS` has `build:web` write `opensearch.xml` and `index.html` name it with `<link rel="search">`. A search opens `?q=<words>`; `ui/app.js` takes the words out of the address and sends them as a new task, as Enter would. A link anyone can write opens the same address and is sent the same way; what its words make Jean do still follows the rules (D20), so sending, sharing, deleting and anything outside Jean's own files wait for an approval.
- **What search engines and shared links read** (`scripts/seo.js`): `ADDRESS` also has `build:web` fill `index.html`'s title and description and add its canonical address, Open Graph's card (`screenshots/share.jpg`), and JSON-LD. On the brand's own site alone (`ownSite()`), the `WebSite` also has `BRAND.domain` as its `alternateName`, a site name Google can take where the name alone reads as the first name, and both name their `publisher`; an organisation's copy names no publisher. Every page of `app/` but the site's (D438) says `noindex`. `sitemap.xml` is read from the pages as `build:web` writes them, the build stopping on a page with neither `noindex` nor a canonical address, on two pages with one address, and on language versions that don't each name the same set.
- **A container image** (D232, `deploy/docker/`, MIT): a multi-stage Dockerfile builds with `npm ci --ignore-scripts` and `npm run build:web`, and copies `dist/web/` into nginx's unprivileged slim image (user 101, port 8080, Jean's files read-only). `index.html` gets `<meta name="app-policy">` and an empty `policy.json` beside it, which the organisation's own replaces as a mounted file; empty, Jean is the open version, and no 404 shows in the console. Every file is sent with `no-cache`, `nosniff` and `frame-ancestors 'self'`, and `CONTENT_SECURITY_POLICY` adds the organisation's own policy, which can only tighten. GitHub's CI publishes both to `ghcr.io/jean-is/jean` and `ghcr.io/jean-is/jean-gateway` (`edge` and `sha-<commit>` from `main`, a version's number and `latest` from its `v` tag), for amd64 and arm64, with provenance and an SPDX bill of materials as attestations.
- **The pilot kit** (D415, `deploy/`, MIT): [deploy/README.md](../deploy/README.md) lists the header set, the type of every ending a deploy holds, the pages without `.html`, and a recipe for each host (IIS, Azure Static Web Apps, S3 behind CloudFront, Intune). On S3, ONNX Runtime's 27 MB WebAssembly goes as its brotli copy, CloudFront compressing only up to 10 MB.
- **The page that checks a site** (D415, `policy.html`, `caps/policy/`), for IT, in their language, not precached. It reads the policy as `ui/app.js` does, or a `policy.json` chosen there before it goes up. `checkPolicy()` walks `SCHEMA`, what this version reads, which `test/policy.test.js` holds to every `policy.…` the code reads: a part not read, with a name one edit away as a guess; a wrong type or value, a missing part, an address not https, a capability `capabilities.json` doesn't list.
- **A signed release** (D419, `scripts/release.js`): `npm run release` builds a commit as `npm run deploy` does (`build()` in `scripts/deploy.js`), refusing `POLICY` and `ADDRESS`, so a release is every organisation's. `dist/release/` gets `dist/web/` as a zip written by `core/zip.js` with every file in order and dated by the commit, so the same build makes the same zip; `npm sbom --omit=dev`'s CycloneDX beside it, `SHA256SUMS`, and `SHA256SUMS.sig`, `ssh-keygen -Y sign` with `RELEASE_KEY` in the namespace `file`.

## jean-cli

`cli/` is Jean outside the browser, on Node 22 or later, published as `jean-cli` (D241), for the editors that speak ACP (Zed, JetBrains, Neovim, Emacs).

## Voice

- **Speech to text** (D56, D61, D110, D205, D374): the browser's on-device recognition where it works, never its cloud recognition, otherwise a worker: Whistle (Cactus Compute, Apache-2.0, ~18 MB) in English, German, French, Spanish, Italian and Dutch, Whisper base (~80 MB) through Transformers.js in the other languages. Measured on 24 test recordings per language, Whistle made as few errors as Whisper base or fewer in those six and more in Polish (35% against 28%), was 3 to 10 times faster, and gave no words for silence where Whisper invented some. Clips over 30 s are cut at their quietest moment. Both write as the user speaks (`caps/voice/passes.js`): the microphone comes through an AudioWorklet in a context at its own rate, since Firefox connects it to no context at another, which brings it to 16 kHz in frames of 96 ms. Whisper reads a padded 30 s each pass, about 2.5 s on WebAssembly, so its words come in steps, Whistle's every half second.
- **Text to speech** (D109, D114): `speechSynthesis` with local voices only, each answer in its own language, by the voice the user picked for that language, which reads ahead of the natural voice in answers and Live, else the one `rankVoices()` in `ui/language.js` puts first: their variety, natural voices before compact ones, novelty voices last; `ui/language.js` guesses the language offline, and with no voice for it, Jean says so.
- **The natural voice** (D455, `caps/reader/`): Kyutai's Pocket TTS (its weights CC BY 4.0, each voice's recording CC BY 4.0 or CC0), read through ONNX Runtime on one WebAssembly thread, in the six languages Kyutai documents (`NATURAL` in `ui/voices.js`). A manifest pinned by SHA-256 pins the rest: one binary for the decoder every language shares (about 11 MB), one per language (about 97 MB), their large weights as 8-bit numbers with an fp32 scale per output channel. Its text first has its numbers in words (`words.js`, under `node --test`), as the model learnt to read them: in digits, or beside a symbol such as €, it stumbles and loops. Then it goes as pocket-tts 4.0.0 sends it (`pocket.js`, the same ids as Kyutai's for every round-trip sentence), sentences cut at the tokenizer's marks, those over 100 tokens at their commas, joined up to 100. pocket-tts joins up to 50, but each chunk is read afresh from the voice's state and ends as a sentence does, so its cuts at commas were heard as stops. The page plays the pieces back to back in an `AudioContext` made in the click, or for Live conversation in Live's own. On an M3 Max, a language loaded from the cache in 0.7 s in Chromium and 1.9 s in WebKit, the first sound came 0.18 to 0.26 s after the click, and it was made 2.1 times faster than it lasts in Chromium and 2.3 in WebKit. The cache holds each file by its address, which names the pin: `download()` (`ui/weights.js`) files a file whose SHA-256 is unchanged under its new address rather than downloading it.
- **Live conversation** (D93, D374): dictation's AudioWorklet feeds 16 kHz frames of 96 ms, three of Silero's 32 ms, made from the microphone at its own rate, to Silero voice detection (~2 MB), in a worker of its own so that a turn's end is heard on time rather than behind a pass of Whisper → Whistle or Whisper, written in the box as the user speaks through dictation's passes, the box showing only the turn being said → the brain once the turn ends, streamed → read sentence by sentence, by the natural voice where it is on and reads the answer's language, else by the system's voices. `caps/live/turns.js` holds the turn-taking, tested under `node --test`.
- **Real-time speech models** from providers (OpenAI Realtime over WebRTC, Gemini Live) could come later; `wss:` is already in `connect-src`.

## Camera

The camera (D645, `caps/camera/`) is never streamed to a brain: each time Jean looks, the look is a picture shared in the task, as any other (D105), so it works with every brain that can see, and the task keeps what was seen.

- **Opening it.** From its row in +, or its button beside the microphone, both drawn by the capability, so the first load holds none of it. With no brain that can see (`seesPictures()` in `ui/send.js`), it says so and opens the picker.
- **Its view** always says that a camera is on, and whether Jean watches.
- **Frames.** Four times a second, the picture drawn 160 pixels wide gives its sharpness (the variance of its Laplacian), and 32 × 24 its scene; the last four frames are kept as bitmaps 1,024 pixels long at most (`frames.js`, under `node --test`). A message sent while the camera is on, typed or said, shares the sharpest of them, as a JPEG kept by its hash, or the picture Look closely kept. A note tells the brain when the camera comes, in full the first time in a task (briefly, a step at a time, as aloud; what it sees when unsure; never who someone is from their face), and when it goes.
- **Watching.** The `watch` tool, or the Watch button, has Jean look on its own (`watch.js`): once the scene has moved by 4% and kept still for 0.75 s, else after a minute, for 10 minutes at most; a look that says nothing leaves no record, so the frozen prompt and the provider's cache are untouched. A look waits while an answer is at work, or the user speaks or types.
- **The window.** Every picture since the last summary goes with every request, each counted as about 1,600 tokens, and compaction (D359) sums a task up past 60 pictures whatever its window, Anthropic taking 100 in a request.
- **Stopping.** Closing it, another task or project, ten minutes with nothing said and no watching, or the page hidden, where it waits for a tap to go on and never resumes on its own.
