# Architecture

How Jean is built, as it is now. Why each choice was made, and what was rejected, is in [decisions.md](decisions.md), cited here as `Dnnn`.

## Principles as rules

| Principle | Rule that can be enforced |
|---|---|
| KISS | Hard limits in [budgets.json](../budgets.json), checked in CI. Going over means deleting something first. |
| Portable | All data is plain files: Markdown, JSONL, `SKILL.md` folders. Export is a zip; import is dropping a folder. |
| Universal | Standards, not adapters: OpenAI-compatible and Anthropic Messages, MCP, Agent Skills, ACP events, the Jev-style Decisions API. |
| Browser-ready | Static files, offline after the first load, opened from a link. |
| System-agnostic | `core/` uses only standard web APIs and runs unchanged in a browser, a worker, Node, Deno or Bun; its tests run under `node --test`. |
| Incremental | Capabilities are discovered as situations call for them, offered by Jean, granted by the user, and only then loaded. |

## Stack

**No build step** (D9). Plain ES modules and an import map; types in JSDoc, checked by `tsc --noEmit`. Development serves `app/` as written (D243), and view-source is the source; a web deploy copies `dist/web/`, the same files with Jean's own code minified and each file compressed beside itself (D318).

**A first load without a bundle.** `npm run manifest` writes a `<link rel="modulepreload">` into `index.html` for every module the first load imports, so the browser fetches the graph in one round trip, and stamps `sw.js`'s `VERSION` line; `npm run manifest -- --check`, in CI, fails if either is stale. The first screen loads only what it draws (D76, D94, D148): the desktop app's host (`ui/host.js`, imported as Jean opens on 127.0.0.1 alone), the dialogs (`ui/dialogs.js`), the Anthropic adapter (imported by `core/llm.js`), the loop and the other adapters (with the first message), Auto, and what a message needs on its way (`ui/send.js`: the prompt, what the brain reads of the files, the run and its approvals, cache warming, loaded as the user starts typing) all load when first needed, and stay in the shell's precache for offline use. A web deploy sends them minified, each in brotli as `npm run build:web` wrote it (`scripts/web.js`, D318).

`vendor/`, `capabilities.json`, `manifest.webmanifest` and a copy of `LICENSE`, all in `app/`, are made by `npm run dev`, `start`, `build` and `check` from Jean's own `node_modules` and the root's licence, and never committed (D43, D51, D52, D74, D243).

**Vendoring** (`scripts/vendor.js`). The three upfront libraries (only the lit-html files Jean imports) and the on-demand runtimes (`optionalDependencies`) are copied, as `package-lock.json` pins them, from Jean's own `node_modules` into `app/vendor/`, their bare specifiers rewritten where import maps don't reach (workers), and what Trusted Types and the CSP refuse patched, each patch found exactly as often as expected or the copy stops. A runtime is listed under the capabilities that use it, never in the shell, and nothing comes from a CDN (Transformers.js gets `wasmPaths`). `npm install` also fetches Transformers.js's Node backends (~300 MB), which never ship.

**The web's copy** (D318, `scripts/web.js`). `npm run build:web` copies `app/` into `dist/web/`, minifies Jean's own modules, workers and style sheets with esbuild (a dev dependency, pinned), and writes each file that compresses beside itself in brotli and gzip at their best, which the server sends as they are (Caddy's `precompressed br gzip`, nginx's `gzip_static`). Minifying takes out comments, whitespace and local names, nothing else: a classic script keeps its global names, no syntax is lowered and no prefix added (for the browser floor, esbuild would turn `\p{…}` regexes into `new RegExp` strings, un-nest `@starting-style` and add `-webkit-` prefixes), and a style sheet loses only whitespace and comments. The first load is about 40% less than what Caddy compressed on the fly (zstd), a second on a slow connection, and ONNX Runtime's wasm 3.8 MB rather than 6.2. The service worker, the bridge, the pages, `ui/touches.css` (shown as it is, D111) and third-party code stay as written. `capabilities.json` then lists the minified files' hashes and the version they make, which `sw.js` carries, while its render listing keeps the package's own hashes (D305). The budgets measure `app/` as written, and development, the desktop app and the render package use it as it is. Deploying is `npm ci && npm run build:web`, then copying `dist/web/`; the build takes about a minute, most of it brotli on ONNX Runtime's wasm.

**Budgets** ([budgets.json](../budgets.json), D86). `scripts/budgets.js` measures them in `npm run check`, and `npm run dev`, `dev:gateway` and `start` run `scripts/budgets.js --short` as Jean starts, then after each change to `app/`, `cli/` or `budgets.json`, each time in a process of its own (D244): every budget over is said, a line each on the error stream, until all are met again, and as Jean starts those within 2% of their limit are named too; the server still serves. The line budgets (`loc.core`, `loc.app`, `loc.cli`, D246) count lines of code, by `scripts/loc.js`: a line counts when it holds anything but comments and white space, so a comment after code leaves its line counted, and what a string, a template or a regular expression holds is code, whatever it looks like. Modules are read as a browser reads them, style sheets by their comments, and a page by its own and those of its scripts and styles. `loc.cli` counts `cli/`'s modules (D240); `bridge/` and `gateway/` have no limit.

**Built on the browser, no dependency:** text from DOCX, XLSX and PPTX (zip through `DecompressionStream` and a small tag scanner, not `DOMParser`, so it runs in workers and under `node --test`); the backup zip (`CompressionStream`); BM25 search with `Intl.Segmenter` over an index made once, which ranks deferred tools, past conversations and the passages of documents, and `alike()`, which tells requests of the same kind apart (`core/search.js`), plus matching as people type over a fold of the text as long as the text (`fold()`, which drops accents, hamza and Arabic vowel marks and keeps marks that make letters, and `ranges()`, D133); ULIDs from `crypto.getRandomValues`; the system's voices; Web Locks and BroadcastChannel between tabs.

**Routing is one hash** (D59, D137, D220), read by `ui/router.js`: `#/c/<ulid>`, `#/p/<project ulid>/c/<ulid>` in a project other than home, `…/settings/<section>` with Settings open over either, and after a `?` the windows beside it, in the order they opened, each `name` or `name=state` (its slashes and colons as they are), as in `?flow=task&terminal&browser=https://example.com/`: `preview=files/<file>`, `browser=<address>` (`folder:`, `workspace:` and `made:` for Jean's own pages), `terminal`, `flow=<flow ulid>` (flow mode on a new task, the pane beside a task) or `flow=task`. `ui/windows.js` keeps them: each window's module calls `keep(name, { get, set })` as it loads, `get()` saying what it shows (null closed), `set()` showing a state again after checking it. Following an address, it waits for `app.ready`, closes the windows not named and those out of order, then loads each named window's module (once its capability is found) and sets it, giving the keys back where they were. The router writes the windows into the entry it is on rather than adding one, and follows them only when an address leads to another place: a reload, a link, or Back and Forward to another place shows its windows, while Back and Forward within a place (a site's own pages, Settings closing) leave them as they are, and a window shown again doesn't take the keys. A name Jean doesn't know, or one whose capability isn't found yet, is passed over, so an address stays good as windows come and go. Opening Settings adds one history entry, so Back closes it; another section takes the same entry, and Settings closed where it opened goes back. The unsent draft is kept per conversation in `sessionStorage`; other dialogs stay out of the address.

**Components are custom elements** (light DOM, prefix `app-`). Each capability is one module that defines its elements and registers its tools, hooks and slots ([Events and slots](#events-and-slots)); unlocking it is an `import()`, and any of its elements already on the page upgrade. `:not(:defined)` styles what isn't discovered yet.

## Brand

```js
// brand.js — the only place the name lives
export const BRAND = Object.freeze({ name: 'Jean', domain: 'jean.is' })
```

- **For display only** (D4): UI strings (`{name}`), the system prompt, the page title and the web-app manifest. The wordmark is the name set in the display face, so there is no logo file to redo.
- **Never in anything that persists:** storage keys, OPFS paths, cache names, element prefixes, CSS classes, the desktop app's identifiers. Renaming changes one line and moves no data.
- **The assistant's name is a setting:** `settings.assistantName ?? BRAND.name`, which a project can override (D102).
- **Grammar:** translations never make a word agree with the name; in conversation, the brain handles grammar itself.
- **The origin is not a variable.** Storage belongs to the domain, so it is settled before the public launch (D27).

## Core

- **`loop.js`**: stream the reply, run tool calls, feed results back, repeat. Rules (Do it / Ask me first / Never) are checked before each tool runs, calls from scripts included. The prompt and declared tools are frozen for the conversation; changes arrive as notes ([below](#prompt-tools-and-caching)).
  - `tools` is every tool that can be called, and may be a function read again at each step, so a capability turned on mid-turn can be called at once. `declared` is what the brain sees; `hidden` tools are never declared (D64).
  - A tool's `check` runs before a call the rules don't refuse: it can ask even where they allow (a change in the user's folder) and give the card what it shows (ACP `diff` content). `ctx.content` is kept on the call's record before its result; `ctx.answer` is what the user answered (D152).
  - Sources are numbered from `firstSource`: tools call `ctx.cite()`, the brain's own search sends `cite` events that become ` [n]`, and both are recorded as `_meta.sources` (D90). `ctx.meta` records more (a picture). `ctx.progress()` says how a call is coming while it runs, a `tool_call_update` with `content` and `_meta` (the call's own, and more) that is shown and never kept (a picture as it forms, D265). A provider's `pause` (Anthropic's `pause_turn`) is sent back and resumed.
  - `ctx.turn()` runs a helper's child turn (`delegate` splits a task into up to five parts, run three at a time as hidden `helper` calls) with the same brain, rules, approvals and source numbers, its own prompt, history and tools; its records nest under the calling tool's (ids prefixed, `_meta.parent`, no thinking blocks) and its text is the call's result (D98).
  - `meta` on the brain entry says why Auto chose it (D70).
  - A request that fails before anything of its answer came is asked again after 1, 2 and 4 s, or after the provider's `Retry-After` when longer, up to 30 s, if the error may pass (`LLMError.retryable`: the connection, the provider busy or its server failing, and the browser offline, which looks the same as a refused cross-origin request; never the device's brain). Meanwhile the brain entry has `_meta.retrying` and the activity says "Trying again…". Once part of an answer came, or after the last wait, the error shows with Try again (D202).
- **`llm.js`** and **`anthropic.js`**: the OpenAI-compatible Chat Completions and Anthropic Messages adapters, over fetch and SSE (`sse.js`); together they reach almost every model. `llm.js` imports `anthropic.js` when an Anthropic brain is first used. Anthropic from the browser needs the `anthropic-dangerous-direct-browser-access: true` header; OpenRouter's PKCE sign-in (`oauth.js`) runs entirely in the browser. A `claudecode` or `copilot` brain is an Anthropic one, and a `chatgpt` brain an OpenAI-compatible one, whose address is This computer's bridge, which runs the user's own Claude Code or Copilot, or signs in to ChatGPT (D235 · D262). OpenRouter weighs the credits left against the longest answer a brain may give, which Jean leaves unsaid; when they fall short it answers 402 with how many tokens they cover, and Jean asks again for that many. Any other 402, or Anthropic's 400 that says the credit balance is too low, is `credits`: the error says the brain is out of credits, to add some or choose another brain, with Check the brain beside Try again, and isn't tried again by itself.
- **`hooks.js`**: Jean's events, which hooks watch, change or answer ([Events and slots](#events-and-slots), D293).
- **`events.js`**: the ACP records and their envelopes ([Activity events](#activity-events)), `splitSuggestions()` (D69), `versionsOf()` (D164), `isPicture`.
- **`prompt.js`**: the base prompt, the frozen sections and the notes that change them (D46, D81), and `toChatMessages()`, the records as the messages the brain reads after it.
- **`deferred.js`**: `find_tools`, tool signatures, and `reach`, which says how to call a tool that isn't declared (D63, D104).
- **`rules.js`**, **`settings.js`**: the rules and their defaults, and guards as `tool.check` hooks (`guardHooks()`, D295): each, the person's in `settings.json` (`guards`, each with an id) and the organisation's in `policy.json`, outermost and locked, only tightens what the rules and the tool's check decided, for a kind of action or a connected service (its tools carry its id, `service`), and, when it has one, only if Intuition, else the room's brain in a word, answers yes to its question, one it can't answer counting as yes; its reason is what the brain reads, and a guarded call that asks keeps asking ("Always allow" sets no rule); settings resolved as defaults ← user ← policy, `DEFAULT_URLS`, `PROVIDERS`, projects. Every third-party address (providers' endpoints, OpenRouter's sign-in, Wikipedia, the model weights host, the package registries, the site icons) is what the user picked or a default there, resolved when read and never written into `settings.json` (D33).
- **`fs.js`**, **`files.js`**, **`conversations.js`**: storage, shared files (original, text and metadata, source numbers, passages, the pages a small brain reads, `read` and `search_files`), transcripts.
- **`search.js`**: BM25 over an index of texts (`lexicon`, `lookup`), every place of a phrase (`every`), `alike()`, `restated()`, which finds a clause of four words or more, between punctuation of any script, alike at 0.8 to one in an earlier task's request (D286), and matching as people type (D133).
- **`decide.js`**: Kev's input and answers in the Decisions API's shape; the questions themselves are in `caps/reflexes/questions.js` (D62).
- **`memory.js`**, **`skills.js`**: the `memory.md` format and the lines that fit (D79); `SKILL.md` folders, of which only names and descriptions go into the prompt (D83, D121), the kinds of block each declares (D196), and the metadata each came with, kept when it is saved (D222).

## Events and slots

What Jean does passes through named events, and what the room draws for a capability goes through named slots that the capability fills (D293), the points plugins will reach too.

**Hooks.** `fire(hooks, name, e, behaviour)` (`core/hooks.js`) runs the hooks on that event whose `match` the event holds (a value, one of a list, or a pattern its text matches), outermost tier first (`policy`, `user`, `jean`), in the order given within one. Each `run(e, next)` calls `next(e)` to go on, with the event or a changed copy, the last `next` reaching Jean's behaviour; returning without it answers the event. One that throws is passed over, or answers `{ refuse }` when it is a guard (`refuse` set); once it went on, what came back stands, and what Jean's behaviour throws goes through as it is. An answer a hook gave of its own, a plain object other than the one the chain gave it, carries `by`, whose it is (D299). A capability lists its `hooks`, which `contributions()` gathers, read again at each event as tools are, each by the capability's id unless it says whose it is.

| Event | Fired | Holds | A hook answers | Used by |
|---|---|---|---|---|

**Plugins** (`caps/plugins/`, D296) reach the same points from outside. A plugin is a folder, `plugins/<name>/` at the root, kept as it came: Jean's own `plugin.json`, after Claude Code's for what both need (`name`, `version`, `description`, `author`, `homepage`), with `format`, `title-<lang>` and `description-<lang>` as skills give theirs (D222), `main`, its module beside it, and `rights`; and `data.json`, what it keeps for itself (`$.store`), read and written one request at a time, since a stream of records made two `$.store.set` calls at once lose one. It is read from a folder's address or a repository's page on GitHub (read as raw files), and its card shows who made it, where from, what it asks in plain words, Loosening named apart, and its code, before Add it; added again, it takes the earlier one's place, with the rights granted then, and keeps its data. It is offered by the brain, or turned on from its trophy, and `capabilities.deny` keeps it out. Each one turned on (`plugins` in settings, on this device) runs in a frame of `sandbox.html` of its own (`sandbox="allow-scripts"`, no network), where `caps/plugins/plugin-worker.js` imports its module, sent as text, from a blob and calls its `register(on, $)`: `on(event, match?, run)` hooks `task.start`, `file.add`, `tool.check`, `turn.end` and `record`, and `$.slot(name, draw)` draws in `above`, `answer` and its row of Settings › Plugins; `notify` shows its short messages under its name, and `$.redraw()` asks Jean to draw it again. Its rights: `watch` to hook at all, `change` to go on with a changed event or answer otherwise, `refuse` to make a call more careful, `loosen` to let one go ahead without asking (never a reserved action, nor past a rule the organisation set). What it draws is a tree of Jean's elements (text, a button whose press goes back to it, a row, Markdown as answers have it), drawn by Jean in the room's look. Messages are all it has:

| Jean sends | The plugin answers |
|---|---|
| `start` (its code) | `started`, with what it hooks and the slots it draws in, or `failed` |
| `event` (a hook's index, the event as plain data) | `next`, as often as it goes on, each answered with the rest of the chain's result; then `done` with its own, or `threw` |
| `draw` (a slot, its props) | `drawn`, a tree |
| `press` (a button's action) | — |
| `answer` (to `next` or `store`) | `store` (a key, and a value to keep), `notify`, `redraw`, at any time |

`proxy()` in `plugins.js` makes each of its hooks one of Jean's, in the user's tier: it sends the event, passes a changed one on only with `change`, and keeps an answer only within the plugin's rights (`allowed()`: on `tool.check`, more careful is `refuse`'s, looser `loosen`'s, unless the organisation set the kind's rule; elsewhere, `change`'s or, a refusal, `refuse`'s). It waits 5 s of the plugin's own time (`call()`, held still while `next` runs). A hook or a drawing that fails or goes unanswered counts against the plugin (`failing()`): at the third in a visit, its switch is turned off with `failed`, which its row says until it is turned on again, and a toast says so (D309). `element()` draws a tree as text (with a `label`, text standing for a picture, said in its place), buttons, rows and Markdown, at most 8 deep, 50 wide and 500 elements in all; the trees are kept by plugin, slot and key until it asks to `redraw`. Settings › Plugins lists them as Settings' other lists are (D134): a row each, its switch at the end of its first line, which opens on what the plugin draws there, what it may do, its version and maker, and Remove; the one just added opens. With `?safe` in the address, no plugin starts, and Settings › Plugins says so, with Leave safe mode, which takes `safe` out of the address and starts them without a reload. `manifest.js`, pure, reads `plugin.json` and the address it comes from. `examples/plugins/` holds four to try (an activity log, quiet hours, trusted sites, and a glance at each long answer), which `npm run dev` serves at `/examples/` to any page.

## Reflexes

`decide(state, questions)` takes typed questions (`noul`, `choice`, `score`) and returns calibrated probabilities, in the Jev/Decisions API shape that Jev, Clef, Strands Decider, Laya, Kev, Ollaya and OpenRouter's `/api/alpha/decisions` share, so backends can be swapped. In the UI, reflexes are **Intuition**.

```js
// ui/discovery.js, with the questions from caps/reflexes/questions.js
const { demand, personal, capability } = await decide(message, {
  demand:     { type: 'score',  instructions: 'How demanding is this request?', criteria: ['a quick chat or a simple fact', 'reading, writing or summarising', 'several steps of work or analysis', 'expert reasoning'] },
  personal:   { type: 'noul',   instructions: 'Does the message share personal, health, financial or confidential information?' },
  capability: { type: 'choice', instructions: 'Which of these would help with this message, if any?', criteria: { compute: 'exact numbers, maths, or analysing a table of data', none: 'nothing new is needed' } },
})
```

|---|---|
| **Kev-0.6B**, fine-tuned on Jean's questions (D328), through Transformers.js | The default (D41, D67): q4f16 on WebGPU with `shader-f16`, otherwise q4 on WebAssembly; about 345 MB once, with consent; about 60 ms a message on WebGPU after warm-up |
| Jev through OpenRouter | Later, when a cloud brain is connected |

**How Kev is asked** (D67): all of a state's questions in one forward pass, each with its options between Kev's delimiters (ids from its `config.json`: the model card's sample escapes them, which flattens every score); each option's score softmaxed within its question; a score read as its most likely level, since Kev hedges toward the middle; a yes, or an offer, at 0.6. Each message gets one pass for demand, personal and capability, and a second for "unhappy" with the previous answer, both capped at 2.5 s.

**Measuring Kev** (D68, D84): `test/reflexes/<lang>.json` holds 44 labelled examples per launch language, machine-translated; `npm run reflexes` runs Kev on the CPU under Node with Jean's own questions and thresholds, and writes [test/reflexes/results.md](../test/reflexes/results.md) (`--model <dir>` measures a checkpoint on this computer). Kev-0.6B made 66%: tables reliable, "personal" and "unhappy" ranked right but never sure enough for a yes at 0.6, "lasting" at chance, the low-resource languages lowest. The test set is the lasting asset.

**Kev fine-tuned** (D328): about 190 labelled requests per language, written natively in each to one specification, every label balanced and with hard negatives (a sensitive topic that discloses nothing, a one-off instruction that looks like a preference), none close to the test set, with 2,172 of Kev's own training records replayed, trained from Kev-0.6B's adapter and head (`kev.train --init_from`), two epochs on a Mac. The LoRA is merged and quantized as the published graphs were and written over their weights, so the graphs, and Jean's code, stay as they are, but for the q4 graph's word lookup, rebuilt from core ONNX operators with the same 4-bit table and the same numbers out: the published `GatherBlockQuantized` isn't in ONNX Runtime's WebAssembly build, which had kept Intuition off every browser without WebGPU's fp16. `jean-is/kev-0.6b-reflexes-ONNX` holds it, under Apache 2.0, with its data, recipe and adapter. It makes 96% on the test set (every question at 91% or more; Yoruba 80%, Swahili 82%, Hausa 84% lowest), 97% on a held-out part of its own data, and Kev's own test as before (0.817 against 0.808), a little more often confidently wrong outside these questions.

**Measuring offers** (D284): `test/offers/<lang>.json` holds 43 requests in eight languages (English, Arabic, Spanish, French, Hindi, Japanese, Swahili, Simplified Chinese), each labelled with the capability the brain's `offer` should name, or none. `npm run offers` reads the frozen prompt and declared tools a first conversation sends, from the page in headless Chromium, then sends each request through core's loop to the brain `BRAIN` names (as jean-cli's `--brain`, its key in `<PROVIDER>_API_KEY`), `BRAIN_BODY` is added to each request, so the device's Gemma answers without thinking, as in the tab. Jean's first tools answer as they do, the user taking each recommended answer, and a reply counts if it calls `offer`. It writes a section per brain into [test/offers/results.md](../test/offers/results.md): per capability, how often it was offered when needed, what came instead, and how often it was offered when not; it stays out of `npm run check`, needing a brain. There is always a default project, hidden until Projects is discovered, so one code path handles everything.

- **Writes.** One storage worker writes with `createSyncAccessHandle` (Safari 16.4+, Chrome 108+, Firefox 111+; D12). Conversations are append-only, so a crash costs at most a half-written last line, ignored on read (going back to a request rewrites one whole, D188); files rewritten whole go to a temporary file first, then are swapped in.
- **Several tabs.** Web Locks serialise writes per file; BroadcastChannel tells other tabs to refresh.
- **Folders of the user's** (D141, D149, D152). A project or a conversation opened on a folder of the computer gets an `FS` of its own (`folderFS` in `ui/opfs.js`): a storage worker started on the folder's handle, writing in place with `createWritable`, without the temporary copy and without telling other tabs. `stat` gives a file's size and `lastModified`, which a change checks against what the conversation read. Handles live in IndexedDB's `app-folders` under the project's or conversation's ULID (a conversation duplicated from another gets that one's, D230), with the folders "Always allow" was given for; the folder's name is in `project.md` and `<folder>`, so a missing handle is asked for again by name. Tools work in the folder of the conversation that asked (D147). Outside Chromium, a folder is a read-only copy for the visit (`caps/folders/copy.js`), and what Jean changed is saved as one zip. Nothing of Jean's is written there.
- **Profiles** (not built, D228): a profile would be a whole Jean, its settings (brains and keys, rules, look, language), its own secrets' key, the person's instructions and memory, its projects, connections, sync places (D227) and routines, in `profiles/<ulid>-<slug>/`, behind a rooted view of the FS that `core/fs.js` gives, so no other module knows of profiles. Folder handles and `localStorage` keys would be kept per profile, and nothing would cross between profiles (memory, search, @, meetings, Since last time): a project moves by export and import, or through a sync place. The first run makes one, unseen until a second is made, as the home project is; the user's menu lists them and adds one; switching opens the other afresh, as a new version comes in (D138), and an address finds its profile by its task's or project's ULID. A work profile may take an organisation's policy from a signed file or the identity provider's groups, in `ee/`; the open version keeps one `policy.json` per origin.
- **Format changes.** Every file carries a `format` version, to be upgraded lazily when read once Jean has users; until the public launch nothing is kept for earlier shapes (D173).
- **Preventing loss:** `navigator.storage.persist()`; installing the app (Safari can wipe a site not visited for 7 days); backup offered early; Sync (D157) as a continuous copy in Chrome and Edge; usage shown in plain words; model weights evicted first, never user data.
- **What takes up space** (D177, Settings › Your data): `weigh()` in `core/files.js` totals Jean's files by kind (the projects' conversations, files and workspaces, and the rest); `ui/dialogs.js` adds the browser's caches by name, `transformers-cache` as the brains on this device, `app-cap-…-computer` with the Computer's workspace, the other `app-shell-` and `app-cap-` caches and `app-sounds`, a score's instruments, as the offline copy, each response by its `Content-Length` unless it came compressed. What `estimate()` counts beyond them is everything else's.
- **Secrets.** API keys and tokens are encrypted with a non-extractable `CryptoKey` kept in IndexedDB, and never exported, synced or shared. The key that seals certificates (D252) is kept there too (`deviceKey` in `ui/secrets.js`). Folder handles can't be encrypted or kept in a file; IndexedDB keeps them, never in a backup.

## Service worker

- **On install:** cache the shell (`sandbox.html` and `preview.html` included) and every locale file, so switching language is instant and offline. Files come through the HTTP cache and are checked against the integrity hashes in `capabilities.json`; a stale copy is fetched again. The install icons and screenshots stay out (D131, D168).
- **On unlock:** cache the capability's files, listed in `capabilities.json` with content hashes, with the modules of other capabilities it imports (the Computer's from Folders and Files), so it works offline on its own. The cache is the record of what has been unlocked.
- **On update:** download the new shell and new versions of unlocked capabilities only, then delete old caches. When the user lets it in, the new version takes the page's place where it was (`ui/update.js`, D138).
- **Model weights** live in their own cache, so an update never downloads 3 GB again.
- **A notification the page can't show itself** (Android's browsers refuse `new Notification()`) is shown by the service worker, and a tap on it focuses Jean's window at the task's address, or opens one there (D334).
- **Offline:** history, files and the device's brain keep working; with only a cloud brain, Jean says so.

## Security

Every HTML document has its own CSP in a `<meta>`, which works on any static host. Each is checked in every engine by the browser's own reports (D326): `scripts/serve.js --csp-reports` serves each page's `<meta>` policy again as a `Content-Security-Policy-Report-Only` header whose reports it keeps, by the `csp` cookie that names whose they are, so a browser says what its policy refused, Trusted Types and workers made from blobs included, with no hook into the page. `test/csp.spec.js` takes Jean through an answer drawn from Markdown, a page in it charting with the ECharts Jean lends, the sandbox's script and its page beside the conversation, Python, Settings and the check page, after a refusal made on purpose that shows the browser reports at all, and fails on any other: with the smoke tests in Chromium and WebKit, and in Firefox, Chrome and Edge themselves, where installed, with `npm run csp` (`test/browsers.config.js`), which then drives Safari and Firefox themselves over WebDriver (`scripts/csp.js`: `safaridriver` once Safari's Allow remote automation is on, `geckodriver`). Two refusals are expected. Pyodide asks whether its worker is a classic one by importing an empty `data:` script, which the sandbox's policy refuses, and goes on as a module worker would, Python working either way. Safari makes a Trusted Types policy of its own in the room, from a script it puts in the page and not through the page's `trustedTypes` (a hook on it saw Jean make only `lit-html` and `app-urls`), so its report names the page and no file of Jean's; an empty page, or one with a form, gets none.

**`index.html`** runs only Jean's own code:

```text
default-src 'self'; script-src 'self' 'wasm-unsafe-eval' 'sha256-<import map>' 'sha256-<first paint>'; style-src 'self';
img-src 'self' blob: data: https:; media-src 'self' blob:; font-src 'self';
connect-src 'self' https: wss: http:;
worker-src 'self' blob:; manifest-src 'self'; frame-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none';
require-trusted-types-for 'script'; trusted-types lit-html app-urls
```

- **`connect-src` is broad** because users add any OpenAI-compatible endpoint, and untrusted code never runs in this document. Organisations tighten it with an HTTP header ([enterprise.md](enterprise.md)).
- **Plain HTTP reaches this computer alone** (D260). Before it reads anything Jean keeps, `start()` in `ui/app.js` adds a second policy, which holds as well: `connect-src 'self' https: wss:` and `http://<name>:*` for `localhost`, `127.0.0.1` and, in the desktop app, each of the computer's own IPv4 addresses; Settings › Web search reads that policy to tell what it can reach (`insecure()`). `addresses()` in `ui/host.js` reads them from what `ifconfig` writes (`ip` where there is none, `ipconfig` on Windows), run with `os.spawnProcess` and heard through its `spawnedProcess` events, waiting 2 s at most. A policy can only narrow, so an address the computer takes later (another network) holds from the next load.
- **`img-src` allows `https:`** for the site icons on web sources' chips, whose address is replaceable (D210), and the pictures sources give (D35): an answer draws a Markdown image only when its address is a source's picture, then loads the address the source gave, and shows any other as its words.
- **A source's picture** (D35, D336). Wikipedia's and Vikidia's search bring each page's lead picture (`pageimages`, 500 pixels, without the `utm_` words Wikipedia adds), and so does `browse` for an article of their sites, whose pages refuse other sites' reads: it reads the article, whole and redirects followed, through MediaWiki's API at the source's address (`readWiki()`). Any other page `browse` reads gives its own (`og:image`, else `twitter:image`, https alone). Each is told to the brain on a `Picture:` line under the source and recorded with it in `_meta.sources`; a shared picture goes by its name. `ui/markdown.js` hands an image to the layouts capability, which draws it only when its address, escaped or not, is one of those, and then loads the source's own address, never the one written, without a referrer, dropping one that doesn't load; its site is among those About this answer says the answer reached (D252). At the head of a comparison's card it shows above the option's name, as tall in every card and on white, as shops show what they sell. Compare and choose puts one there for each option when they are things one looks at, or none, and browses an option's own Wikipedia article when no source gave one: the brain's own search (Anthropic, OpenRouter) brings no pictures, and shops' pages refuse other sites' reads, so with it an option without an article, or with the browser off, has none.
- **A runtime that needs `'unsafe-eval'`** gets a worker document of its own, never a looser `index.html`.

**`sandbox.html`**, framed with `sandbox="allow-scripts"` and never `allow-same-origin` (D65, D162):

```text
default-src 'none'; script-src 'sha256-<relay>' blob: 'wasm-unsafe-eval' 'unsafe-eval'; worker-src blob:;
connect-src 'none'; base-uri 'none'; form-action 'none'
```

- **No access to Jean's storage** (its origin is opaque) **and no network at all.** It holds only a small inline relay, allowed by its hash. `test/html.test.js` checks the hash and that the frame never gets `allow-same-origin`.
- **The parent sends everything in.** `ui/sandbox.js` fetches the worker's source and, when a run first needs them, an engine's files (listed in `capabilities.json`), and posts them to the relay.
- **Untrusted code runs only in a Worker** made from a `blob:` URL, so it inherits the sandbox's CSP; workers have no navigation, no WebRTC and no `sendBeacon`. It is a classic worker, since browsers refuse module workers from `blob:` in an opaque origin; it can still `import()` blob modules and compile wasm, and Emscripten gets `wasmBinary` and `wasmLocation` so nothing resolves against a `blob:` base.
- **QuickJS:** 64 MB of memory, 20 s of computing time (waiting on Jean or the user doesn't count), 20 s to start, 8,000 characters of output; a script reaches only what Jean hands it ([Codemode](#prompt-tools-and-caching)).
- **Pyodide** needs `'unsafe-eval'` as it starts (Emscripten builds some functions with `eval`); with nothing to steal and nowhere to send it, that costs nothing. Its files are Jean's own pinned copy (D43), sent in like QuickJS's; its `fetch` serves only those, under an address that never resolves. `import js` reaches only Jean's `fetch` and what pyfetch needs. Its memory and time can't be capped without cross-origin isolation, so the parent's watchdog stops a run that goes quiet; 60 s to start.

See [Computer](#computer).

|---|---|---|

| Load things from the internet | off | `https:` for pictures, sounds, fonts, styles and, when they run, scripts |
| Send and receive over the internet | off | `connect-src`: any https site (`*`), or only the sites listed, each added with Enter: `example.com`, `*.example.com`, `*.com`, and this computer over http (`localhost:3000`, `localhost:*`) |

## Prompt, tools and caching

Four mechanisms from pi 1.0, fitted to Jean, share one idea: what the brain has read never changes, so providers can cache it and the device's runtime can keep it in memory.

**A frozen prefix** (D46). When a conversation starts, Jean fixes the system prompt and the declared tools, and neither changes until it ends. Providers cache by prefix (Anthropic reads tools, then system, then messages), so one changed byte at the front re-bills the whole conversation; on the device, the same rule keeps the KV cache between turns.

**System notes** (D46, D81). A change mid-conversation (language, rules, instructions, memory, skills, the project, new tools, the date) is a note appended to the transcript where it happens.

- **Sections.** The project, instructions, memory, skills, connections (`<connections>`, D89), the folder (`<folder>`: its name, top level and four tools, and its `AGENTS.md` when the user took it, D152) and the page on show (`<page>`, D140) are sections of the frozen prompt, each asked for the task the message goes to (`sections(task)`, null for a new one on screen: a task out of sight has its own folder and no page, D317); each has a fingerprint (FNV-1a), and one that changed arrives whole in a note ("The <memory> section is now: …").
- **Notes a message comes with:** "Since last time" starts with when the user was last here (D101); the terminal's commands, with their exit codes and output (D166); what / and @ named in it, a skill with its steps, an earlier task as it went (D199).
- **Recorded:** a note is an ACP extension update (`_system_note`) in the conversation's JSONL, holding the English the brain sees and data for the UI's label, so replaying the file rebuilds what the brain was told, and when.
- **Rendered per adapter:** for Anthropic, a `system` message after the next user message, on models that take one; for OpenAI and OpenRouter, a `system` message where the note falls; for other servers and the device's brain, whose templates allow a system message only at the start, a tagged block at the top of the next user turn.
- **Never deleted:** removing a note is an edit, which breaks the cache from there on.

**Deferred tools** (D47, D63, D64, D104). A conversation declares the tools unlocked when it started; anything later is deferred, including every connection's tools.

- `find_tools` and `offer` come from the `discovery` capability, always loaded, so every conversation declares them. `find_tools(query)` ranks undeclared tools by name and description with BM25 and returns up to five signatures (`name({ file: string, pages?: string }): what it does`).
- A capability turned on mid-conversation adds the note "New tools can be found with find_tools: …" (`data: { kind: 'tools', added }`).
- A tool the user turns off (`off`, Web search's switch, D304) is declared by no conversation started meanwhile, and stays declared where it was, so the prefix holds: that conversation is told it is off, then on again (`data: { kind: 'switch', off | on }`), the loop refuses its calls, and `find_tools` never offers it.
- With `javascript` declared, deferred tools are called from a script and the declared list never changes. Otherwise `find_tools`, or an accepted offer, declares them from the next request on, recorded as `_meta.declare` on the call, at the cost of one cache miss. A tool called by its exact name, as `<connections>` gives it, runs under the rules without being declared; a missing argument gets the signature back.
- A provider's native deferral (Anthropic's `defer_loading`) may replace this later, with the same behaviour. The next conversation declares a newly unlocked capability's tools directly; connections' stay deferred.

**Codemode** (D48). `javascript` runs a snippet in QuickJS on the conversation's computer; top-level `await` works, and the result is what the script returns or its last expression. Inside, Jean exposes what the user has granted, and nothing else:

| Global | What it does |
|---|---|
| `file(name)` | A shared file's whole text (spreadsheets as tab-separated rows), or a file of the conversation's folder, through the hidden `file` tool |
| `csv(text)` | CSV or tab-separated text as rows: objects keyed by the header, numbers as numbers. The separator and quoted cells as `csvRows` reads them; the header is the first row of two filled cells or more, past a title line |
| `tools.<name>(args)` | Any granted tool, deferred and connection tools included; not `bash`, `javascript`, `python`, `offer`, `delegate` or `ask_user` |
| `fs.readFile`, `fs.writeFile`, `fs.readdir` | The computer's files: /workspace, kept after the run (D162) |
| `fetch(url, init)` | The internet, through Jean, as Settings › Computer allow |
| `searchTools(query)` | `find_tools`, from a script |
| `models.decide(state, questions)` | Kev on the device when Intuition is on, through the hidden `decide` tool |

Every nested call goes through the rules (`ctx.call` in `core/loop.js`); a call that needs approval pauses the script, and the wait doesn't count against its time. Nested calls carry `_meta.parent`, show under their call, and stay out of the brain's context, since the script's result holds what matters. Each crosses to Jean as a message and Jean makes it with its own keys, so the sandbox never sees a secret. Declared tools stay callable directly, because small brains call tools more reliably than they write scripts.

**Thinking blocks are kept** (D54) on each step's brain entry and replayed unchanged to the model that wrote them.

**Caching and warming on Anthropic** (D49). One `cache_control` breakpoint on the system prompt's last block, plus top-level automatic caching for the conversation. When the user starts typing after about 5 minutes without a request, Jean sends the same prefix with `max_tokens: 0`, unstreamed, with the real request's thinking and effort, its breakpoint on the last message already there; skipped below the model's minimum cacheable size. OpenAI caches by itself; local servers keep their KV cache, which the frozen prefix keeps valid; the device's brain reads only what follows the text it already read (D58), a long prompt 2,048 tokens at a time, each part going into the cache before the next (D350).

## Retrieval and extraction

- **Extraction:** DOCX, XLSX and PPTX through the tag scanner; PDFs with pdf.js, on demand. A spreadsheet's date cells read as dates (`dateStyles`), and each page of a long sheet names its columns. A PDF page's text is joined by `pageText` (`caps/files/extract.js`, which node runs too): a right-to-left line in reading order (pdf.js gives each word right but the words as drawn), Arabic presentation forms, Kangxi radicals and compatibility ideographs as the letters and characters they stand for, a line wrapped between Chinese or Japanese characters or a code cut at its hyphen joined again, and lines set larger than the size most of the document is set in marked as headings (`#` to `###`), a heading wrapped over two lines as one. Pictures (PNG, JPEG, WebP, GIF), dropped, pasted, picked or captured from the screen (one frame of a shared screen, window or tab), show themselves in the request, read from the project's files only once on the page (`ui/shown.js`, as Pictures reads those Jean made), are kept no larger than 1,568 pixels a side and go to brains that can see, right after their `<document>` tag (`image_url` for Chat Completions, an `image` block for Anthropic); a brain that can't is told there is one (D105). Scanned PDFs, with no text layer, are not read.
- **A shared file in the message** (D24, D55, D301): a document that fits in about 25% of the brain's context goes in whole; otherwise its first pages do, or for a brain of 32k or less its page 1 and the pages that match the message, and `read(file, pages)` reaches the rest. The choice is made once, when the message is sent, and recorded on the file's link (`_meta.pages`, a list of page ranges). Tokens are estimated as UTF-8 bytes / 3. Past conversations are searched with BM25 (`recall`).
- **Searching inside documents** (D24, D301), in core: `passages()` cuts a document's pages into passages of about 100 tokens, never across a page, where a line ends or a heading starts; each carries the path of the headings above it (or its page's first line that reads like a heading and isn't a running header) and a table's column names. `lexicon()` indexes them once, in typed arrays, by folded words and codes kept whole (C-4471 as well as c and 4471); `lookup()` ranks across several files' indexes as if they were one. `preselect()` picks, for a brain too small for a file, the pages that best match the message instead of the first ones: a brain of 32k or less gets them, as page ranges in `_meta.pages` (D301). The files capability declares `search_files` (`caps/files/search.js`), which gives the best passages with their file, page and source number, or every place a phrase is, case, accents and line breaks aside, counted (`every()`). A file's passages and index are made the first time it is searched and kept as `.cache/words/<file's hash>.idx` (`indexed()`): a JSON header with the format, the terms and the headings, then the numbers; one in another format is made again. Search by meaning reads its passages there too. It and `read` reach every file of the project, the conversation's own first on a name: the capability keeps the library's list as @ lists it (`library()` in `ui/complete.js`), again when the project changes or files are added.
- **Search by meaning** (D302, `caps/meaning/`), a capability of its own, offered by the brain when `search_files` finds nothing by words (the tool's answer says it may). Turned on, it downloads EmbeddingGemma 2's text model, about 175 MB once, on WebGPU only (q4f16 with `shader-f16`, else q4): both graphs keep the vocabulary quantized with an operator ONNX Runtime's WebAssembly lacks (`GatherBlockQuantized`), so where there is no WebGPU it isn't offered or in the house. In Chromium on an M-series Mac it reads about 80 passages a second (q4f16), 49 in q4: an 800-page file in 2 to 3 minutes, a 4,200-page one in 11 to 18, and its worker (`embed-worker.js`) leaves the vision and audio encoders out. Each file of the project is read, in the background, into a vector for each of the passages `search_files` cuts (prefixed `title: none | text:`), 768 numbers in a byte each, kept as `.cache/meaning/<dtype>/<file's hash>.i8`; a question's vector (`task: search result | query:`) is compared with every passage's, a flat scan, no index. `search_files` then fuses the best 200 by words with the best 200 by meaning by their ranks (reciprocal rank fusion, k = 60). A search waits up to 3 s for files still being read, then goes on without them. On the document evals' L files (506 questions, three seeds), words and EmbeddingGemma 2 find 91% of the evidence within 32k tokens and 88% within 8k, multilingual-e5-small 88% and 81%, harrier-oss-v1-270m 91% and 80%, Qwen3-Embedding-0.6B 87% and 80%, granite-embedding-97m-multilingual-r2 84% and 72%, and words alone 73% and 62%; on questions in another language 94%, e5 83%; at the 4,200-page size, 89% and 84%, e5 81% and 75%. It ties EmbeddingGemma 300m, whose terms are Gemma's where its are Apache 2.0, and 4 bits cost it nothing measured.
- **What the document evals found** (D24, D301): `test/documents/results.md`, a fictional company's files up to a 4,196-page PDF of 4.3M tokens. For a 32k brain, the matching pages answered every lookup and the first pages none (H7); at that size the first pages hold 12% of the evidence within 32k tokens, lexical search 66%. A large brain searching for itself is right on 79% of ten questions of each kind, wrong as if true on 4%, and says so on every question about something absent. A flat scan of vectors stays fast up to 5–8 times that size (H1). That file's index takes 2.5 s to make in Chromium and 10.9 s on a computer four times slower, and 60 ms and 0.3 s to read back from `.cache/`, for 22.5 MB (H6). Embeddings earn their place for meaning (H4 refuted: on paraphrases and other languages, lexical search answers 20 points below hybrid).
- **The document evals** (`test/documents/`, `npm run documents`): a fictional company's files made from a seed at five sizes, the largest a 4,196-page PDF of 4.6 million tokens printed by Chromium, in every format Jean reads and four languages, with nine kinds of questions whose answers and evidence are known. `npm test` checks the corpus itself (each answer's evidence found once in the text Jean extracts, in every format); the runner scores each strategy on the evidence it hands over within a budget, and OpenRouter's brains answer through Jean's own loop and tools (a paid Nemotron 3 Super held to one provider, a free small one), graded without a brain. The hypotheses were registered in `hypotheses.json` before the results; `results.md` marks each and `strategies.json` says what each strategy is for.
- **Source numbers** (D71, D90): each shared file gets a number on its link (`_meta.source`), kept if it is shared again. The brain sees `<document source="n" name="…">`, and `read` starts with "Source [n]:". Connections' and Wikipedia's results list their pages as "Source [n]: …", and the brain's own search cites pages. `[n]` becomes a chip only for a known source; a web page's chip is a link (into the browser once it is on), and a "Sources" list follows the answer. A web page's chip shows, while the pointer is on it or it has focus, a tip with its site's icon, its domain and the page's title (D210), in CSS: rendered with the chip, placed above it by anchor positioning (below when there is no room), at its start where anchors aren't known. The icon comes from DuckDuckGo's icon service (`siteIcon` in `DEFAULT_URLS`; `''` shows none), loaded lazily, so only on hover, and never with a referrer. Messages arrive with an animation that isn't held once over, so no message keeps a `translate` that would hold the tip under the bar.

## Activity events

Jean's event format is ACP's `session/update`: `user_message_chunk`, `agent_message_chunk`, `agent_thought_chunk`, `tool_call`, `tool_call_update`, `plan`, plus `session/request_permission`; the types come from ACP's published schema as JSDoc.

```jsonl
{"at":"2026-10-01T10:02:11Z","by":"jean","update":{"sessionUpdate":"plan","entries":[{"content":"Read the invoices","priority":"high","status":"completed"},{"content":"Total per client","priority":"high","status":"in_progress"}]}}
{"at":"2026-10-01T10:02:12Z","by":"jean","update":{"sessionUpdate":"tool_call","toolCallId":"t3","title":"Read invoices.csv","kind":"read","status":"completed","locations":[{"path":"files/invoices.csv"}]}}
```

- **One stream, one record.** The core emits the events, the UI renders them live, and the conversation's JSONL stores them, each wrapped in an envelope with a time and an author. Text chunks merge into one record when a message finishes; a tool call is stored as it starts and again in its final state, which takes its place when the file is read (D216). The brain's context is derived from the same file.
- **Translated labels.** Each line's label is rendered from `kind` and `locations`, so switching language relabels history; ACP's `title` is kept as a fallback.
- **Approvals map onto rules:** `allow_always` writes Do it, `reject_always` writes Never, the "once" options keep Ask me first. A connection's tools that change something use `kind: "other"`, read-only ones `fetch` (D89). A declined call carries `_meta.declined` (D216).
- **Every line opens** on what went in and came back (D103): a call's tool, arguments, result and duration; a brain step's thought and text, how it stopped, its duration and usage (`_meta.ms`). A script's calls nest under their call (`_meta.parent`); helpers' turns nest under theirs (D98). Auto's choice is on the brain entry (`rawInput.auto: { level, reason }`), shown in plain words (D70), and so is whether the brain runs on this device (`rawInput.local`, from `isLocal`, D252).
- **The decision inbox** (D99, D146, D147, D343): approvals, Jean's or its helpers', queue as cards under the live answer, and questions (`ask_user`) at the top of the box, answered in any order; "Always" or "Never" settles the other cards of that kind. 2. **The sources built into Jean** (D271, `caps/search/sources.js`), for every other brain, the device's included: **Wikipedia,** in the user's language, on unless turned off (`urls.wikipedia`); **Vikidia,** the encyclopedia for 8 to 13 year olds, off until turned on (`urls.vikidia`; its editions are `VIKIDIA`, and a language it lacks is told to the brain with those it has); and **the offline library,** a Kiwix server (`urls.kiwix`, none by default). Any source but Wikipedia from the web takes `native` away, so every brain searches what the user chose. Wikipedia and Vikidia are MediaWiki's API, or **a Kiwix server** named in their place (D254), any address but `api.php`, whose books of their category alone are searched (`books.filter.category`); the library searches every book. Vikidia's site refuses to show inside another page (`X-Frame-Options: SAMEORIGIN`, on every address, its API's too), so the search capability's `ownTab` says so of its pages (`OWN_TAB`, `onSite()` in `sources.js`: any language's host, read from the web, never a Kiwix server standing for it), and the browser opens them in a tab at once, as a site the user sent there (`visit()`), with no "Try here again". `caps/search/kiwix.js` reads the languages of its books from its catalogue (`/catalog/v2/languages`, three-letter codes that `Intl.getCanonicalLocales` turns into two), searches the books in the one asked (`/search?books.filter.lang=…&format=xml`; a library in a single language whatever the one asked, and when it has none of them, the brain hears which it has), keeps a page two books hold once, and puts each page's first paragraphs, read from the page with `pageText` (`caps/browser/pages.js`) outside its tables, whose infobox holds a caption's or a note's own, and with the tags that run inside a sentence (a link's, a pronunciation's) dropped without the space the scanner would leave, in place of its snippet. Jean reaches a Kiwix server on this computer, or anywhere over HTTPS: its policy allows plain HTTP only to this computer (D260), whose own network addresses only the desktop app knows, and a page served over HTTPS couldn't fetch plain HTTP from the network anyway. So a Kiwix Hotspot, which serves plain HTTP at the computer's Wi-Fi address, is reached from the desktop app alone. **Settings › Web search** (`panel()` in `caps/search/search.js`, its strings in `locales/search/`) lists, under Where to look, each source with its switch, then the connections that search the web and those Jean knows (3). The library, once on, asks for its server's address, and Wikipedia's may be one, under "Wikipedia from a Kiwix server", whose Remove takes Wikipedia back to the web. An address typed there is kept, as the server's root (`rootOf`: a page's or the reader's address leads there too), only once `library()` reads its catalogue (`/catalog/v2/entries`), and then lists its books, their languages and how many articles each holds; when nothing answers, it says so. An address over plain HTTP away from this computer is never tried (`insecure()`): the section says at once that only this computer or HTTPS can be reached, as it does for such an address policy set. Policy's address locks its form.
3. **A search service connected like any other** (D192): Exa's needs no key and no sign-in, and is one of the services Jean knows; an organisation adds its own to the directory by policy. Search speaks MCP like every connection, so there is no search endpoint of its own in settings. Settings › Web search lists the connections that search the web, as each capability loaded says (its `searches`, in the registry of `ui/caps.js`, D271); it decides nothing itself. Connections gives each connection whose tools say they search the web, by `searchesWeb()` in `caps/connections/mcp.js`: a name with *search* in it, *web* or *internet* in the name or the description, and annotations that neither close its world (`openWorldHint: false`; a web search is MCP's own example of an open one) nor say it changes anything (`readOnlyHint: false`). Exa's `web_search_exa` is listed, its `web_fetch_exa` and a mailbox's `search_emails` are not. The list is only shown: the brain finds those tools as it finds any connection's, and they ask first as reading through a connection does. Under them, the services Jean knows that search the web and aren't connected are offered (`searchers()` in `directory.js`: an entry that says `searches`, reached, its address not among the connections), each with Connect, which turns Connections on if it isn't and connects it as the box's / does (`connectService`, D199); its own row takes its place once its tools are listed.

**+ turns it off** (D304): once found, its row in + is a switch (`search: false` in settings). Off, `web_search` is an `off` tool with no line in the prompt, so a task started meanwhile has no web search, the brain's own included; one that has it keeps it declared and is told (see [Prompt, tools and caching](#prompt-tools-and-caching)).

There is no Jean proxy. Fetching an arbitrary address meets the same CORS wall.

## Connections (MCP)

A connection is an address and, when the service asks, a key or a sign-in (D87–D89, D95).

- **The directory** (`caps/connections/directory.js`) lists the services Jean knows, those people at work use most, from the public lists of remote MCP servers (D192): documents, tasks and projects, meetings and their notes, customers, sites, scheduling and automation, a business's account and invoices (Qonto, whose server sends no money: a transfer it prepares waits for approval in Qonto's own app, D352), and search (Exa, with no key and no sign-in). Each is a tile with its brand's logo (`caps/connections/logos/`, D159; several against their terms, at the owner's call), and is reached from the browser (`ready`), through the gateway once it relays to the service and its sign-in's hosts (`signIn`) and holds the app a sign-in that registers none takes (`app`, its issuer, D214), or not yet, and then disabled, after the others. An entry may reach further servers with its one sign-in (`servers`), name what that sign-in asks for (`scopes`), so that it signs in at once, and what more its address takes (`authorize`): Google is one entry, its eight servers behind one sign-in (D344). An entry may also be an API that answers browsers rather than an MCP server (`api`), called by Jean's own tools, whose sign-in server is its `app`, so that only that sign-in needs the gateway: Gmail, Google Calendar and Google Drive (D349). Policy merges into it by `id`: an address, a `clientId` instead of dynamic registration, `hidden`, `ready`. ServiceNow has no address of its own, each company having its instance: its tile has none until policy gives the instance's MCP server, with the app its admin registered there (an instance registers none itself; a client id, or the gateway's app for that issuer), and it is reached through the gateway alone, which relays to `service-now.com`, since instances answer no browser, so its `ready: false` holds whatever address policy gives, unless policy says otherwise (D283). `npm run directory` checks each entry from an unknown origin without registering anything, with Jean's own client: one whose tools a browser can list with no sign-in is connected without one, as Jean does. It checks each entry not ready through a gateway that relays to its `signIn` hosts and its servers' alone: each has to answer, and its sign-in to register Jean or be its `app`, and each of its `scopes` has to be one a server lists.
- **Accounts and projects** (D191): a tile stays once its service is connected, for another account, whose sign-in asks which (`prompt=select_account`). Two connections whose names start alike (their first 16 letters, as their tools' names do) are each called by who signed in, "Gmail (ana@example.com)", or else by number, "Notion 1" and "Notion 2", in Settings, the box's / and what the brain reads (`called()`); the first made, by its ULID, keeps its tools' names, and the next take `_2`, `_3` (`mail_2_search_emails`, D357). A connection renamed is called by its new name. A connection's `projects` keeps it to those projects; without it, it is in every one. The room's project decides which connections give their tools and `<connections>`. Another service is added by its address, behind the + at the top of the panel.
- **The client** (`mcp.js`) speaks Streamable HTTP: the stateless 2026-07-28 revision first, then the `initialize` handshake and session of 2025-03-26 to 2025-11-25 when a server answers like an earlier one.
- **Signing in** (`auth.js`) follows MCP authorization from the browser: protected resource and authorization server metadata (an issuer compared as an address, so `https://otter.ai/` is `https://otter.ai`; with no resource metadata, the server's at the service's own origin, and no `resource` sent; a service that names itself, whose metadata there names its origin, as ServiceNow's does, has it at that origin, held to what the origin's own metadata says, D283; Atlassian at its `/v2/mcp`, which names its sign-in server, as its guide says to use, `/v1` ending on 1 March 2027: its CORS allows any header with `*`, which the standard says leaves out `Authorization` but Chromium and WebKit let through, as `npm run directory` does, Firefox unchecked), dynamic registration as a public client, PKCE with a `resource` indicator, the `iss` check; a known service's `scopes` replace the metadata's, and its `authorize` parameters are added, `prompt` joined with `select_account` for another account; `openid`, `email` and `offline_access` are asked for too where the sign-in server lists them, and the ID token's email, or else its login, is the connection's `account`, kept only when it looks like one, since the brain reads it (`accountOf()`, D357). The redirect comes back to Jean's own address with `?state=`. Keys and tokens are encrypted in `.secrets/`, never backed up, and renewed before they expire, one renewal at a time for all of a connection's servers; a refused one (not a network lost) marks the connection `error: 'auth'`, so its row offers Connect, and the brain reads that the user has to sign in again (D344).
- **Tools** are `<service>_<tool>`, made JavaScript identifiers (D106), deferred and listed in `<connections>`; both kinds ask first by default. A connection with `servers` (D344) has a client for each, all with its one credential: `toolsOf()` keeps the tools of each that answered, each with its server (`at`), a name an earlier one took left out, and fails only when none answered; a tool is called at its own server.
- **A refused call** (D193): a service whose tools were listed without a sign-in may still refuse to run them (Exa publishes some and needs none); a known service that names its `scopes` signs in at once instead (D344). A call of a connection with no key or tokens that comes back 401 or 403 marks it `error: 'auth'`, keeping its tools and the refusal's challenge, so its row offers Connect (`signIn(connection, challenge)`), and the call's result tells the brain the user has to sign in first. An OAuth connection's 401 renews its token once instead, unless renewing was refused; its 403 tells the brain the sign-in doesn't allow that call. A connection's client is made again once its `auth` changes, so the tokens signed in for are sent.
- **Google Workspace** (D344) has a server a product (Gmail, Drive, Docs, Sheets, Slides, Calendar, Chat, and People for Contacts), all a developer preview for Workspace accounts that answers no browser, behind a sign-in that takes only apps registered with Google: it is one entry, whose one sign-in reaches all eight. Its scopes are the fewest that let every tool run, read from each tool's own resource metadata (`gmail.modify`; `drive.readonly` and `drive.file`; `documents`, `spreadsheets`, `presentations`; `calendar.events` and `calendar.calendarlist.readonly`; Chat's `messages.readonly`, `spaces.readonly` and `messages.create`; `contacts.readonly`, `directory.readonly` and `userinfo.profile`), asked with `access_type=offline` and `prompt=consent`, since Google gives a refresh token only then. A call refused once signed in tells the brain the sign-in doesn't allow it (a product left unticked on Google's screen). jean.is runs a gateway of its own, at `gateway.jean.is`, never on Jean's own origin, which the site's policy names: it relays to every service a browser can't reach (`SERVICES`), and holds Jean's app at Google once there is one.
- **Google's own APIs** (`google.js`, D349) serve any Google account, Workspace's or not: Gmail, Google Calendar and Google Drive are a tile each, with the same app and sign-in as Google Workspace, each asking only for its own scopes (`gmail.modify`; `calendar.events` and `calendar.calendarlist.readonly`; `drive.readonly` and `drive.file`). `apiClient()` stands where `mcpClient()` would, for the address an entry names: its tools are listed once a request says who is signed in (Gmail's profile, a calendar, Drive's user), so a token refused shows as it does for an MCP server; each is called at the API from the browser, never through the gateway, which only discovers Google's sign-in (`discover()` told the issuer, as the API names none), adds the app's secret and renews the tokens. A 401, or a 403 for a scope not given, is an `MCPError`, any other refusal Google's own message. Their names, which approvals and Settings show, are in `locales/connections/`, loaded when one lists its tools. Gmail searches as its search box does, reads an email's plain part in its charset or its HTML's text, with its files' names, and writes drafts or sends, a reply in its thread with `In-Reply-To` and `References`, each header on one line; Calendar lists calendars, lists events from a time on (a day starting where the user is) and adds, changes or removes one, guests told; Drive finds files by their words or those used last, reads a document in Markdown, a spreadsheet's first sheet in CSV, a presentation's words or a text file, and makes a Google Docs document from Markdown. What a call brings in is cited by the address of the email, the event or the file.
- **The browser's limits:** a service must answer with CORS and expose `Mcp-Session-Id` (2025 sessions) and, ideally, `WWW-Authenticate`. When it doesn't, and no gateway reaches it, Jean says it couldn't connect.
- **The gateway** (`gateway/gateway.js`, D191) is for the services a browser can't reach (Gmail, Microsoft 365, Slack and the rest refuse browsers or unregistered apps): whoever serves Jean, an organisation or a person, runs it and names it (`urls.gateway` in settings or policy; none by default), and a service typed by its address is tried through it when the browser can't reach it. It keeps nothing, and tokens stay encrypted on the device; what passes through is seen by whoever runs it, so it is the organisation's or the person's own. It is a fetch handler with nothing to install: `node gateway/serve.js` runs it on Node, and Cloudflare Workers, `deno serve` and Bun take the module as it is. Its configuration, in `GATEWAY_CONFIG` and never in a file beside it (Jean's folder is served as it is), names Jean's origins, the hosts it relays to (a name covers its subdomains; none named, `SERVICES`: those of every service in the directory that isn't ready), and the apps it holds: issuer, token endpoint, client id and secret, sent in the form or as Basic; and the witnesses and logs that date and record certificates (`timestamps`, `logs`, D276), whose hosts it relays to. `GET <gateway>` answers `{ format: 1, hosts, clients: { <issuer>: <client id> } }`, with `timestamps` and `logs` when it has them; `<gateway>?url=<address>` relays: only from those origins, only to HTTPS on those hosts (HTTP on this computer), redirects followed only to them, the request's `Accept`, `Content-Type`, `Authorization` and `Mcp-*` headers alone, at most 10 MB in and the answer streamed back with CORS that exposes `Mcp-Session-Id` and `WWW-Authenticate`. A token request to a configured endpoint that names its app gets the secret. A connection made through it is marked `gateway` and every request it makes, discovery, registration, tokens and MCP, takes the gateway's address at that moment (`urls.gateway`). `npm run dev:gateway` mounts it at `/gateway` in the development server (`scripts/serve.js --gateway`), for whichever address Jean is opened at there, and adds the policy that sets it to `index.html`, Connections still found as anywhere else (D281); a same-origin GET carries no `Origin`, so `gateway/serve.js`'s listener names the page's own, from `Sec-Fetch-Site`.

## Meetings

A project kept on this device doesn't join when the brain is in the cloud, nor one the brain isn't used in (D194), and the minutes say who was left out and why. A meeting asks first, naming its projects; Always allow holds for those projects only (`meet` in settings), so a routine that holds one runs on its own. `speak` refuses a project with no meeting under way, so a script can't reach one.

## Flows

A flow's steps are each a text, a file of the project by its name (its newest version), instructions for the brain (an Ask, done as a helper's turn is, D98, following one of the room's skills when it names one) or one of the room's tools with its arguments, and wires say whose results a step takes: `{{Step name}}` puts a result where it is written, and an Ask gets the others after its instructions. A step can run once for each item of the list it takes (a JSON array, or its lines; 50 at most), three at a time, and a step that gives nothing stops the steps after it; a circle is refused. Z-Image's (`zimage.js`): `encode` keeps the description's own tokens, and gets Qwen3's next to last hidden states (2560 halves a token); `denoise` makes a 16-channel latent an eighth of the picture's size from Gaussian noise in nine steps along `schedule()`, diffusers' flow-matching schedule shifted by 3, the transformer given 1 less each sigma (the last 1) and answering the velocity's opposite, as the export's demo drives it; `decode` unscales it (`SCALE`, `OFFSET`) for the decoder. Each graph's weights come in files under 2 GB, given to `InferenceSession.create` as `externalData`. `flux.js`'s and `zimage.js`'s arithmetic is tested under `node --test`.
- **As it is made** (D265): as soon as its call runs, the answer holds a frame as large as the picture will be (its maker's size: OpenAI's Images API's 3:2, the others' 16:9, films 720 high, SD-Turbo's 512 square, FLUX's and Z-Image's own), faint noise under a light passing over it, over the picture it starts from, blurred, when it changes one; then glimpses of it, each sharper, and a line of how far along it is, where its maker says; then the picture fades in from a blur over them, which go (without motion, it is simply there). It is a progress bar for screen readers, named Making the picture or the film. A GPT image model streams two glimpses, each about a tenth of its price; FLUX.2 [klein] and Z-Image-Turbo on this device send one after each step, what the latent would be with no noise left mixed into colours by the linear factors ComfyUI's previews use (Flux2's for FLUX, Flux's for Z-Image, whose VAE is FLUX.1's), an eighth of the picture's size, without the decoder; OpenAI's film jobs say how far along they are; SD-Turbo, in one step, Gemini, OpenRouter, Ollama and the others' films show the frame alone. `make()` sends `_meta.making` through `ctx.progress()` at once (its kind, `frame`, its size, `from`, the picture it starts from), then its maker's size (`frame()` in `cloud.js`, `size()` in `device.js`), and as they come `done`, 0 to 1, and each glimpse as an ACP image block, all of them each time. `picture()` asks GPT image models for a stream (`stream`, `partial_images: 2`) and reads its `…partial_image` and `…completed` events; `film()` passes on a job's `progress`. On this device, the denoising stage posts a `glimpse` after each step: the latent with no noise left (`x − σv`; Z-Image's transformer gives `−v`), mixed into colours by `glimpse()` in `flux.js` (each token's 2×2 patch of 32 channels) or `zimage.js` (16 channels a point) through `mix()`, as PNG. Chat renders `<app-picture>` for a call with `_meta.picture`, or `_meta.making` while it runs; the element keeps what it saw (`making`, the glimpses) once the answer's end replaces the call, draws the frame in its size (`--w`, `--h`, `--done`, set through the CSSOM), with `<app-shared>` for `from`, and once the picture is here takes its size and lets it develop (`.develops`), dropping the rest at its `animationend`, or at once when nothing animates. `Shown` reads its file again when `uri` changes, letting the one before go.
- **Checked** (D275, D280) **and marked** (D279): a picture made on this device or by a server on this computer (`isLocal`), and each glimpse of it, shows only once `refused()` in `device.js` finds nothing in it to refuse. SD-Turbo's worker (`device-worker.js`, a `check` request) squashes it whole into two squares on `OffscreenCanvas`es, 448 pixels for Freepik's classifier and 224 for SigLIP's image encoder, on WebGPU, else WebAssembly, the sessions and `concepts.json` kept for the next, and answers Freepik's four logits and the areas SigLIP's view is close to (`check.js`: the files, the normalizations in `planes()`, `explicit()`, the share of the levels from medium on, or from low on, and `shown()`, each area whose limit a word of it reaches). Each maker's files end with the check's, so `look()`, `prepare()` and `BYTES` count them; a picture from this computer downloads them when first needed. `refuses()` reads each area of `pictureCheck`, `{ suggestive, hate, violence, selfHarm }` in settings and policy, each true when refused, from policy, which locks its switch in Settings › Brains, else from settings (not `selfHarm`), else `REFUSED`. Nudity, then suggestive pictures when refused, then the areas: `make()` hides a glimpse that shows one and those after it, and throws for the picture after its loop, naming what it showed, so the next engine is never asked; a check that can't run hides the glimpse and refuses the picture. A picture that passes gets its XMP from `marked()` in `mark.js` before `addFile()` names it by its hash. `npm run concepts` (`scripts/concepts.js`) reads each area's words into `concepts.json` with SigLIP's text encoder, at its pinned revision.
- **The law it keeps** (D275): Regulation (EU) 2026/1744 (the Digital Omnibus on AI, OJ L of 24 July 2026, in force since 27 July) inserts points (ba) and (bb) in the AI Act's Article 5(1), with 5(1a) and (1b), applying from 2 December 2026: no AI system may be placed on the market, put into service or used that generates or manipulates realistic images, video or audio of an identifiable person's intimate parts, or of them in sexually explicit activity, without their explicit consent, nor child sexual abuse material (Directive 2011/93/EU, Article 2(c) and (e)). A provider breaches it when that is the system's intended purpose, or a reasonably foreseeable and reproducible outcome without significant technical modification, and the system lacks reasonable and adequate technical safeguards to reliably prevent it, given foreseeable misuse, and to correct misuse observed or reported (recital 12 names prompt guardrails, output classification and filtering, abuse detection, notice and action). The open-source exemption (Article 2(12)) never covers Article 5. Cloud providers filter what they make; nothing filtered what SD-Turbo, FLUX.2 [klein] and Z-Image-Turbo make here, or Ollama and other servers on this computer.
- **The laws behind the other areas** (D280): none is a legal floor as nudity's is. Germany's §86a and §130 StGB, Austria's Verbotsgesetz and the EU framework decision on racism punish showing symbols of hate in public, with art, teaching, research and reporting excepted; Germany's §131 and youth-protection laws cover cruel violence; the WHO's media guidelines warn against showing self-harm.
- **What the check is, and what it was measured on** (D275, D280). Nudity: Freepik's NSFW classifier (MIT, an EVA-02 base seeing 448 pixels square, trained on pictures AI made too), as onnx-community's converter exports it at 4 bits, 60 MB; of its four levels, medium and high together at half or more, Freepik's own threshold, refuse the picture, and Refuse suggestive pictures too (`pictureCheck.suggestive`) counts from low on. On a sanity set (37 photographs and paintings of people, babies, swimmers and anatomy plates, and six classical nudes), it passed every one of the first and refused five nudes of six (Botticelli's Venus, her hair over her, passed); bikini contest photographs it refuses. High alone let bare breasts through (Manet's Olympia scored 0.46 there, Ingres's Odalisque 0.43), and a bikini and a bare breast share medium. The other areas: `caps/pictures/concepts.json` holds a few English words for each (a Nazi swastika flag, the black flag of the Islamic State, a Ku Klux Klan robe and hood…; a photo of a dead body, a severed limb, a severe burn injury…; self-harm cuts on a forearm, a person hanging from a noose…), read into vectors by SigLIP's text encoder (Google, Apache 2.0), and each area's limit; on the device, SigLIP's image encoder at 4 bits (63 MB) sees the picture at 224 pixels, and the picture shows an area when it is as close as that area's limit to any of its words. Measured on 158 pictures from Wikimedia Commons (historical photographs and posters, war and clinical injury photographs; look-alikes: Hindu swastikas, Celtic crosses, the Holocaust memorial, Soviet stamps, battle paintings, butchers, tomato sauce, knives, razors, wrist supports, and the nudity set): symbols of hate at 0.07, 14 of 17 refused (a distant rally, a museum armband and a hooded Klansman passed) and 3 look-alikes of 134 (two Hindu swastikas and the German federal police's eagle); graphic violence at 0.10, every colour photograph of injuries refused and 8 of 16 overall (sepia portraits and distant battlefields passed), with 2 look-alikes of 131 (a prosthetic arm in a museum, a drawing of a fracture); self-harm at 0.12, its one photograph refused and no look-alike. No other picture of the set was refused, nudes and swimwear included, and SigLIP did better than CLIP ViT-B/32 (OpenAI) on both measured areas. Both models are pinned and checked as the makers' files are and downloaded with each maker (their size in theirs, kept until the last maker that shares them goes) or with the first picture from this computer. A refused picture isn't kept or shown, and the brain hears which area it was for, that it mustn't try in other words, and, for an area the user may allow, that Settings › Brains can; no other maker is asked instead. A picture reported to have got through is corrected in Jean's next version, by the threshold or the classifier, both pinned in `caps/pictures/check.js`.
- **The mark** (D279): `marked()` in `caps/pictures/mark.js` writes an XMP packet into the PNG, in an `iTXt` chunk right after its header: IPTC's Digital Source Type, `trainedAlgorithmicMedia`, with IPTC 2025.1's AI System Used (the maker's name, or the model a server on this computer named) and AI System Version Used (the maker's pinned revision, D274). Nothing of the description or the person goes in. A picture from a provider is left as it comes (OpenAI and Google mark theirs, with C2PA and SynthID, and a changed byte would break a C2PA signature), and one from this computer that isn't a PNG isn't marked. The answer's certificate names the same type for every picture and film (D274).
- **In the conversation:** a picture or film is a file Jean made (`filesMade()` reads `_meta.picture` too), so its versions, `from`, the preview and search find it. Its call's title says what it is (`A film · 8 seconds · …`), which the film's approval shows; the approval carries `_meta.film`, so Always allow and Never write no rule for its kind (`SCOPES` in `ui/send.js`, as for a folder, a site or a meeting), and the tool keeps Always allow as `films` in settings.

## Desktop app

`npm run build:desktop` (`scripts/desktop.js`, D155) embeds the files a deploy serves in Neutralino's binary, which serves them on 127.0.0.1:24601 (fixed, since the origin holds the data) to a window of the system's own web view: `Jean.app` (bundle id `is.jean.desktop`), `jean-win_x64.exe` and `jean-linux_*`; `npm run build:dmg` makes the Mac's disk image. None of these come from `BRAND`, and none may change once in use. The native API is on for twelve calls only (`NATIVE`): for Sync's folder (D169), the computer's memory in Settings › Computer (D176), and the two programs the app runs, This computer's bridge, started, listed and ended through its input (D198), and the system's list of the computer's network addresses, read from what it writes (D260). `ui/host.js` takes the one-time key as Jean opens and carries every call, which only it and This computer make. On the Mac, a launcher inserts `libjeanframe.dylib` (D160), which turns on WebKit's internal setting that ignores `X-Frame-Options` and `frame-ancestors`, so sites that refuse frames show in the browser pane (window-wide, so the preview's frames get it too; accepted). That needs bundle mode, since the embedded build's resource reader crashes when an extra library loads; Windows and Linux stay single embedded files. Developer ID signing and notarization will need the `allow-dyld-environment-variables` entitlement.

## Deploying

- **A server reached over SSH** (D320, D321): `npm run deploy` (`scripts/deploy.js`) builds a commit from `git archive`, never the working tree, with `npm ci --ignore-scripts` and `npm run build:web`. Before the server, when npm lacks the render package's version that build names, it publishes it from the same build, `scripts/render.js` then `npm publish ./dist/render`, under the npm login on this computer, which asks for its one-time code; a failure leaves the server as it was. It then rsyncs all of `dist/web/` with `--checksum --delete` into `releases/<time in UTC>-<commit>/`, made first as hard links to the current release, so only what changed is written and an unchanged file keeps its time, and with it its ETag; `mv -T` swaps the `current` link, which the server serves, and the five latest releases stay. `DEPLOY_TO` (`host:/path`) names the server, which needs rsync and GNU `cp` and `mv`. `POLICY`, a JSON object as the gateway's `GATEWAY_CONFIG` is, becomes the site's `policy.json`, which `build:web` has `index.html` name before the hashes are taken, as an organisation does by hand (D344); jean.is's names its gateway, so every deploy of it passes the same.
- **A search engine in the browser's bar** (D353): `ADDRESS`, the address the site is served from, has `build:web` write `opensearch.xml`, OpenSearch's description (`openSearch()` in `scripts/web.js`), and `index.html` name it with `<link rel="search">`, so Firefox offers to add Jean to its search engines and Chrome lists it under site search, its shortcut the site's host. Its addresses, a search's and the icon's, are whole, since Chromium and Firefox refuse relative ones, which is why it is written for one address rather than kept in `app/`. A search opens `?q=<words>`; `ui/app.js` takes the words out of the address and sends them as a new task to the brain in use, as Enter would, through the first brain's dialog when there is none yet. A link anyone can write opens the same address and is sent the same way; what its words make Jean do still follows the rules (D20), so sending, sharing, deleting and anything outside Jean's own files wait for an approval. Safari adds no search engines, and the container image, which doesn't know its address, has none. jean.is's deploys pass `ADDRESS=https://jean.is/`.
- **What search engines and shared links read** (D355, `scripts/seo.js`): `ADDRESS` also has `build:web` fill `index.html`'s empty title with `BRAND.name` and the description's first sentence, and add its canonical address, Open Graph's card, whose picture is `screenshots/share.jpg` (the welcome screen at 1200 × 630, its drawer closed and drawn a quarter larger, which `npm run screenshots` takes and nothing precaches), X's `summary_large_image`, which reads Open Graph's, and JSON-LD: a `WebSite`, whose name Google shows beside a result, and a `WebApplication` in the catalogues' languages. Every other page but the privacy policy and the terms says `noindex`; `sitemap.xml` lists those three, and `robots.txt`, written only at a host's root, where crawlers look, lets them read everything and names it. Link previews run no script, so the head says it all before Jean starts; once it has, `ui/app.js` keeps that title in English and shows the name alone in any other language.
- **The privacy policy and the terms** (D356): `privacy.html` and `terms.html` are WAREHOUSE SAS's, for jean.is and its gateway, each with its English text (`#en`) then its French one (`#fr`), the legal notice at the end of the terms. They are documents: their only script is `index.html`'s first line, byte for byte, which takes the person's light or dark and look from `localStorage`, under a policy of `default-src 'none'` that allows it and one line of style by their hashes (`test/html.test.js`), so a jump to `#fr` clears the sticky bar; the rest is `ui/style.css`'s bar and prose. They aren't precached, as the check page isn't. The welcome links to them below its ideas (`ui/shell.js`), at `urls.privacy` and `urls.terms` (`privacy.html` and `terms.html`, which an organisation's policy replaces with its own, or hides with `''`), the address ending with Jean's language (`#fr`, or `#ja`, which leaves the page at its English). With `ADDRESS`, `build:web` gives each its canonical address without `.html` and lists it in `sitemap.xml` (`LISTED` in `scripts/seo.js`), since every server here answers a page at its address without `.html` too: `scripts/serve.js` (`pageOf()`), the container's nginx (`try_files $uri $uri.html $uri/`) and jean.is's Caddy (`try_files {path} {path}.html`), a file or folder of that name, as `LICENSE`, staying itself.
- **A container image** (D232, `deploy/docker/`, MIT): a multi-stage Dockerfile builds with `npm ci --omit=dev --ignore-scripts` and `npm run build`, and copies only `shippedFiles()` into nginx's unprivileged slim image (user 101, port 8080, Jean's files read-only). `index.html` gets `<meta name="app-policy">` and an empty `policy.json` beside it, which the organisation's own replaces as a mounted file; empty, Jean is the open version, and no 404 shows in the console. Every file is sent with `no-cache`, `nosniff` and `frame-ancestors 'self'`, and `CONTENT_SECURITY_POLICY` adds the organisation's own policy, which can only tighten. The gateway is a second target of the same file, off unless asked for, at an address of its own.

## jean-cli

`cli/` is Jean outside the browser, on Node 22 or later, published as `jean-cli` (D241), for the editors that speak ACP (Zed, JetBrains, Neovim, Emacs). `main.js` reads the command, and the terminal's language (`LC_ALL`, `LC_MESSAGES`, `LANG`, then the system's) picks `cli/locales/`'s.

- **`jean-cli acp`** (`acp.js`): ACP on its input and output through `rpc.js`, JSON-RPC a message a line, requests answered side by side so `session/cancel` is heard during a prompt; anything printed goes to the error stream. `session/new` makes a conversation (`createConversation`) in the folder `--folder` names, which must hold Sync's `mirror.json`, in the project whose `folder` is the editor's folder's name, else the home one; its ULID is the session's. `session/load` reads one back and tells it again as updates, a call's later records as `tool_call_update`. `session/prompt` keeps the files the prompt shares (a file the editor names, its contents, a picture) as the project's (`addFile`, the pages that fit decided then), then the prompt or the notes since and the request, and runs `runTurn`: its updates go out as they are, but for brain entries (`brain-…`), notes and an answer's `<suggestions>`, cut as it streams with `splitSuggestions`, and a diff's or a location's path goes out in full. A question is `session/request_permission`; "always" and "never" set the rule of a kind not kept to a folder, as in the browser. `max_steps` ends as `max_turn_requests`, a stop as `cancelled`, and a brain's error is worded as the browser words it. `settings.json` at the top of the folder, which `carried()` leaves out, is this computer's: `device` (who writes), `rules`, and `always` by folder.
- **Tools** (`tools.js`): `list`, `find_in_files`, `open` and `change` on the editor's folder with `caps/folders/work.js`, whose `SPECS` and `USE` are what the capability tells the brain too. Listing and searching read the disk (`nodeFS`, writing in place there); opening and changing a text go through the editor when it offers `fs` (`fs/read_text_file`, `fs/write_text_file`), so its unsaved changes count. A change is checked against what was read (`lastRead`) and asked with its diff unless always allowed in that folder. `bash`, when the editor offers `terminal`, runs `bash -c` there (`terminal/create`, `wait_for_exit` within two minutes, else `kill`, then `output` and `release`), its terminal shown on the call while it runs and after; JavaScript and Python never run there, only in the sandbox. `read`, `recall`, `remember` and `skill` work on the project's and the person's files, `read` and `recall` as the browser's own (`readTool`, `recallTool`) and `skill` with `skillSteps`; the editor's MCP servers (`connect()`: a program, spoken to with `rpc.js`, or an address, through `mcpClient`) give deferred `<server>_<tool>` tools, with `find_tools` and `<connections>`.
- **The brain** (`brain.js`): `--brain <provider>[:<name>]`, with `--address` for a server of the user's, else the first provider whose key is in the environment (`<PROVIDER>_API_KEY`, `HF_TOKEN`, `AI_GATEWAY_API_KEY`), those with a brain of their own first, else Claude Code once `claude auth status` says it is signed in: `bridge()` on a free port of 127.0.0.1, with a key made for it, as a `claudecode` brain. `--brain copilot` and `--brain chatgpt:<name>` are the other plans' brains the same way (D262), ChatGPT's with the sign-in Jean's bridge keeps on this computer. It is chosen at the first prompt. Keys come from the environment only, never from a file.
- **`jean-cli gateway`**: `gateway/gateway.js` behind `gateway/serve.js`'s listener, `--origin` added to `GATEWAY_CONFIG`'s origins, on `--port` (8787) and `--host` (127.0.0.1); it answers Private Network Access for the origins it serves, so Jean's own address reaches one on this computer.
- **The package** (`npm run cli`, `scripts/cli.js`): every module `cli/main.js` reaches, statically or through the `import()`s it lists, copied as written and where they are (Jean's own under `app/`) into `dist/cli/` with `cli/locales/`, `app/brand.js`, `LICENSE`, `cli/README.md` and a `package.json` (`bin: jean-cli`; `@preact/signals-core` and `marked`, the two runtime dependencies those modules import). `cli/locales/` holds the approvals' names and the brains' errors copied from each catalogue, the rest translated, outside `app/` so the web never ships them (D243).

## Voice

- **Speech to text** (D56, D61, D110, D205): the browser's on-device recognition where it works, never its cloud recognition, otherwise a worker: Whistle (Cactus Compute, Apache-2.0, ~18 MB) in English, German, French, Spanish, Italian and Dutch, Whisper base (~80 MB) through Transformers.js in the other languages. Measured on 24 test recordings per language, Whistle made as few errors as Whisper base or fewer in those six and more in Polish (35% against 28%), was 3 to 10 times faster, and gave no words for silence where Whisper invented some. Clips over 30 s are cut at their quietest moment. A session that ends in an error or no words moves to the model for the visit; the browser's own download gets 15 s, its stop 2 s.
- **Text to speech** (D109, D114): `speechSynthesis` with local voices only, each answer in its own language, by the voice `rankVoices()` in `ui/language.js` puts first: the user's pick, then their variety, natural voices before compact ones, novelty voices last; `ui/language.js` guesses the language offline, and with no voice for it, Jean says so. Natural voices (Kokoro) are a possible later option.
- **Live conversation** (D93): an AudioWorklet feeds 16 kHz audio to Silero voice detection (~2 MB) in dictation's worker → Whistle or Whisper → the brain, streamed → the system's voices, sentence by sentence. A turn starts after 250 ms of speech and ends after 800 ms of silence; speaking over Jean for half a second interrupts it. `caps/live/turns.js` holds the turn-taking, tested under `node --test`.
- **Real-time speech models** from providers (OpenAI Realtime over WebRTC, Gemini Live) could come later; `wss:` is already in `connect-src`.
