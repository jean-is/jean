# Decisions

Each entry is a decision as it stands: what was chosen, why, and what was rejected, so it isn't proposed again. Numbers are stable, because code and docs cite them. When a later decision amended an earlier one, both live in one entry under all their numbers, so searching for any `Dnnn` lands on the current rule; git history keeps the original wording. D124 and D151 were never used.

A new decision takes the next number after the highest one here (D173), checked again just before writing, since several sessions may add numbers at once. It goes into the section it belongs to; if it changes an existing entry, rewrite that entry to the new state and add the number to its heading. A budget is raised only by the owner, in a change of its own.

## Product

- **D1 · Reboot from scratch** rather than refactor DEVS. *Why:* no users or years of fixes to protect; cutting 95% is harder than writing ~5k clean lines. *Rejected:* pruning DEVS ([background.md](background.md)).
- **D2 · First user: a non-technical knowledge worker; one job: files in, things out.** *Why:* a sharp job beats an architecture ("swarm") as a pitch. *Rejected:* developers first; generic chat; a separate mode for code.
- **D5 · Progressive discovery, like a game.** Jean starts as one box; a capability's code loads when it is discovered, so the simple first screen and the small first load are one decision. *Rejected:* a feature-complete UI from day one.
- **D6 · Discovery is triggered by events, reflexes and the brain's `offer()`, never by keywords,** so it works in every language. *Rejected:* regex or keyword intent rules.
- **D7 · One agent loop plus helpers.** *Why:* 2026's winners are single-loop agents; delegation is one tool (D98). *Rejected:* DEVS's decomposer, teams and methodology templates.
- **D27 · Data is bound to the origin: the domain is settled before launch.** *Why:* changing it means moving everyone's data. *Rejected:* launching on a temporary domain.
- **D38 · D50 · Jean is its own project, in its own repository.** It moved out of DEVS with its history (`git subtree split`): no devs.new redirect, no import from DEVS, nothing read, imported or copied from outside the repository. *Rejected:* Jean as DEVS's successor; a DEVS subfolder.
- **D3 · D39 · D139 · Open core: MIT, with the enterprise integrations in `ee/` under the Elastic License 2.0 and a key.** Reputation first, money second. Everything a person or a team uses is MIT; `ee/` holds only what an organisation's IT, security or compliance team asks for ([enterprise.md](enterprise.md#open-and-enterprise)), never the person's own security, a standard Jean speaks or anything already open, and nothing moves from open to `ee/`. Keys are ES256 JWS from CODENAME SAS, read from policy and checked offline with Web Crypto inside `ee/`; a subscription key unlocks every version released before its end date; a trial key lasts 30 days, bound to the deployment's addresses; `localhost` needs none; small organisations, non-profits and schools get free ones. A policy that asks for `ee/` features without a valid key stops Jean with a message for IT. `ee/GRANT.md`: if no key can be bought for twelve consecutive months, every version published until then is MIT. `ee/` loads with `import()` from one module, only when policy holds a key. *Why:* small players get the whole product, big ones adopt it bottom-up and pay when their IT needs the integrations; Elastic-2.0 is short, on the SPDX list and known to legal teams; Ed25519 would need browsers above D40's floor. *Rejected:* BUSL on everything; AGPL with a commercial licence; FCL (not on the SPDX list); PolyForm Small Business; a custom licence; online key checks; keys that stop a running version; locked features shown in the open version.
- **D45 · Collaboration relay (not built): hosted by the maintainer on a subdomain of Jean's domain,** running only once someone turns collaboration on, forwarding end-to-end-encrypted traffic it can't read, self-hostable, and replaced or switched off by policy. *Rejected:* no public relay; a relay that can read content.

## Stack and budgets

- **D9 · D43 · D51 · D52 · D74 · D183 · D185 · D196 · No build step, and nothing generated or third-party is committed.** Plain ES modules and an import map, JSDoc checked by `tsc --noEmit`; Jean's own code ships as written. `npm run dev`, `start`, `build` and `check` copy the three upfront libraries (only the lit-html files Jean imports) and the on-demand runtimes (`optionalDependencies`: pdf.js, Transformers.js with onnxruntime-web, QuickJS with feross's `buffer`, Pyodide, just-bash, `@silurus/ooxml`, Temml, ECharts, abcjs) from Jean's own `node_modules` into `vendor/`, rewriting bare specifiers where import maps don't reach (workers), patching what Trusted Types and the CSP refuse (each patch found exactly as often as expected, or the copy stops), and write `capabilities.json` and `manifest.webmanifest`. The committed `index.html` preloads and `sw.js`'s `VERSION` line are stamped, and `npm run manifest -- --check` checks them. A runtime is listed under the capabilities that use it, never in the shell, and nothing comes from a CDN (Transformers.js gets `wasmPaths`). Deploying is `npm ci && npm run build`, then copying the folder. *Why:* view-source is the source; third-party code in history is noise in every diff; `package-lock.json` makes the copies reproducible. *Rejected:* a Vite or TypeScript build; committing `vendor/` or the generated files; runtimes from a CDN; `transformers.min.js` (bundles its own ORT). Known cost: `npm install` also fetches Transformers.js's Node backends (~300 MB, never shipped).
- **D10 · Custom elements with `@preact/signals-core`, `lit-html` and `marked`'s lexer, the only libraries loaded upfront.** *Why:* standard elements upgrade when their module loads, which *is* progressive discovery, and all of it is CSP-safe. *Rejected:* Preact with htm; VanJS; Alpine (needs `eval`); htmx (needs a server).
- **D66 · QuickJS and Playwright.** `quickjs-emscripten-core` with only the release-sync variant (~600 KB with its wasm), loaded on demand; `@playwright/test` as a dev dependency, run by `npm run e2e` in Chromium and WebKit against the fake brain, apart from `npm run check`. *Rejected:* the `quickjs-emscripten` package with every variant; browsers inside `npm run check`.
- **D37 · Development uses a deterministic fake brain** (`test/fixtures/fake-brain.js`). *Rejected:* testing only against real providers.
- **D62 · Mechanisms live in `core/`, product policy outside it.** `core/decide.js` packs Kev's input, `core/deferred.js` finds tools, `core/search.js` ranks text; which reflex questions are asked (`caps/reflexes/questions.js`) and how Auto picks a brain (`ui/auto.js`) are policy, in pure modules tested under `node --test`, and `scripts/reflexes.js` imports the same questions, so what is measured is what runs.
- **D75 · Shared types live in `core/types.d.ts`,** which never ships and which `lines.core` doesn't count. *Rejected:* a JSDoc-only `types.js` counted as code.
- **D96 · D148 · A module that only one capability, or one part of the UI, uses lives with it.** Extraction is `caps/files/extract.js`, pictures from a provider `caps/computer/picture.js`, the backup zip `caps/backup/archive.js`, the language guesser `ui/language.js`, the page policy `ui/csp.js`; `core/zip.js` stays because several share it. All stay tested under `node --test`. *Why:* the core is the engine you read in an afternoon. *Rejected:* raising `lines.core`.
- **D76 · D94 · D148 · The first load holds what the first screen draws, and one catalogue.** The dialogs (`ui/dialogs.js`), the Anthropic adapter (imported by `core/llm.js` when first needed), the loop and the adapters (with the first message), Auto, and what a message needs on its way (`ui/send.js`: the prompt, what the brain reads of the files, the run and its approvals, cache warming, loaded as the user starts typing) all load when first needed, and stay in the shell's precache for offline use. `useLocale()` fetches only the chosen language's catalogue; the budget counts the largest. *Rejected:* preloading after the first paint; a lexer-only `marked` (its published file can't be tree-shaken).
- **D97 · A language's catalogue comes in parts.** `locales/<lang>.json` holds what the first screen and the conversation show; `locales/dialogs/<lang>.json` what only dialogs show, loaded by `ui/dialogs.js`, which every module that shows a dialog imports; a capability whose strings would weigh on the first load brings its own part, `locales/<id>/<lang>.json`, cached with it (browser, ask, folders, sync, computer). `test/locales.test.js` checks that every string is used, and only where its part is loaded. *Rejected:* trimming sentences; one part per capability for all of them.
- **D86 · D129 · D161 · D171 · D175 · D179 · D186 · D189 · The app's line budget is 25,000, and a capability's code 50 KB.** The owner raised the lines from 10,000 to 15,000 (before 0.5), 20,000 (the looks), 22,000 (the Computer), 22,500 (Sync in the desktop app), 22,600 (formulas) and 25,000 (going back to a request, D188), and a capability's code from 40 KB to 44 KB (the Computer shown in Settings) and 50 KB (Node's own modules in the Computer), each in a change of its own. The core keeps 3,000 lines, the first load 100 KB and the CSS 12 KB. *Rejected each time:* raising it inside the change that needs it; thinning a shipped capability.

## Data

- **D11 · D12 · D40 · Data is plain files in OPFS behind `core/fs.js`, written by a storage worker with `createSyncAccessHandle`.** That sets the browser floor: Safari 16.4, Chrome 108, Firefox 111, except for capabilities that need more (D141, D157). *Why:* portable, readable, ready to sync, the user's own; universal beats newest. *Rejected:* Yjs as the data layer; IndexedDB records; `createWritable` on the main thread (Safari 26).
- **D18 · D19 · D82 · D182 · Projects are self-contained folders, called "Project" in the UI.** `projects/<ulid>-<slug>/project.md` (`format`, `name`, `colour`, `createdAt`, `by`; `default` for the home project; `cloud: false` to keep it on this device) beside its own conversations, files, instructions, memory, skills and routines. A project with a name and a way of being is what other products call an agent (D102). The header shows the project the user is in and opens on the others; the address carries it; its colour tints the light (D78). The home project's name is never translated: the UI calls it by its assistant's. Its dialog shows who the project is first, its light as picked, large, beside its name and the colours; then its assistant, once names are found; then where it is kept, a switch for this device and its folder; Save and Delete at its foot, apart and always in view. What a project is, it says only when making one. *Rejected:* "Space", "Agent", "Room" or "Folder"; remembering the last project in settings; tinting the interface's accents; one column of fields with Delete under Save, out of view on a short screen.
- **D30 · Organisation policy is opt-in,** through `<meta name="app-policy" content="policy.json">`. *Rejected:* always fetching `policy.json` (a 404 for everyone else).
- **D33 · D53 · Every third-party address is a default that settings or policy replace.** Providers' endpoints (`PROVIDERS`), OpenRouter's sign-in, Wikipedia, the model weights host and the package registries are identities of what the user picked or defaults in `DEFAULT_URLS` (`core/settings.js`), resolved when read, never written into `settings.json`. *Why:* "no hard-coded third-party URL" is about services Jean depends on; organisations mirror them. *Rejected:* hard-coding huggingface.co in the workers.
- **D173 · Until the public launch, nothing is kept for earlier versions.** No alias for a renamed tool, no migration of settings or files, no reader for an older shape: a change of shape changes the code and its tests, and the owner's own data follows or starts again. Every file keeps its `format` field, for the lazy upgrades that begin after launch (D11). *Why:* there are no users yet, and each shim cost code, tests and docs for data only the owner had. *Rejected:* keeping the tools a conversation started earlier was given (D46 holds for conversations started from now on).
- **D59 · D137 · The address holds the place: `#/c/<ulid>`, `#/p/<ulid>/c/<ulid>`, and Settings over either, `…/settings/<section>`.** Opening Settings adds one history entry, so Back closes it; another section takes the same entry; closed where it opened, it goes back. The unsent draft is kept per conversation in `sessionStorage`. Other dialogs stay out of the address. *Rejected:* path routing (host rewrites); `#/settings` on its own (loses the conversation underneath); `?settings=` (reaches the server); an entry per section.
- **D177 · Settings › Your data breaks the storage down when asked.** "What takes up space", under Storage, measures once opened and lists each kind that holds something, largest first and everything else last, with its size and a bar of its share; the total shown becomes their sum. *Why:* a total alone doesn't say what to keep or clear. *Rejected:* Chromium's `usageDetails` (Chromium only, and by storage API rather than by what Jean keeps); a stacked bar with a colour a kind (no palette holds across fifteen themes and forced colours); measuring whenever the section opens (it reads every file's size).

## Security

- **D28 · Trusted Types is enforced, with one extra policy, `app-urls`,** that allows only same-origin script URLs (the workers). *Rejected:* dropping `require-trusted-types-for`.
- **D29 · Inline code is allowed by hash,** each guarded by `test/html.test.js`: the import map, the first-paint line (D85, D111) and the update's view-transition opt-in (D138). *Rejected:* `'unsafe-inline'`; a bundler.
- **D35 · Markdown images in a brain's answer are never loaded;** only their alt text shows. *Why:* an image address is the classic way for injected instructions to leak data.
- **D13 · D14 · D65 · D80 · Untrusted code runs in one sandbox: a classic worker started from a blob by `sandbox.html`, framed with `sandbox="allow-scripts"` only.** Its CSP is `default-src 'none'; script-src 'sha256-<relay>' blob: 'wasm-unsafe-eval' 'unsafe-eval'; worker-src blob:; connect-src 'none'`. The parent sends every file in (QuickJS, Pyodide and just-bash, as `capabilities.json` lists them); Pyodide's `fetch` serves only those, under an address that never resolves. `'unsafe-eval'` is for Pyodide's start-up, harmless in an opaque origin with no network. QuickJS gets 64 MB and 20 s of computing time (waiting on Jean or the user doesn't count); a watchdog in the parent stops a run that goes quiet. Requests go through Jean (D162). *Why:* code reaches only what Jean hands it, the same in every host. *Rejected:* running code in a sandboxed frame's document (WebRTC, navigation, a frozen tab); a module worker (refused from `blob:` in an opaque origin); `srcdoc` (inherits `index.html`'s policy); serving the runtimes to the sandbox over the network; a second document for Python (until D162).
- **D126 · D143 · D158 · D183 · A web page shows in `preview.html`, an opaque frame with `sandbox="allow-scripts"`, and five switches say what it may do; a Word, Excel or PowerPoint file is drawn in one as Office draws it.** Settings › Approvals › Web pages: Run its code (on), Go full screen (on), Save files (on), Load things from the internet (off), Send and receive over the internet (off; then a list of sites, `*` until one is named, each added with Enter); `pages` in policy sets and locks them. `preview.html`'s relay writes a doctype, the policy `ui/csp.js` makes as a `<meta>`, then the page. The frame delegates `clipboard-write *` and, when on, `fullscreen *` (`*` because WebKit doesn't match an opaque origin to `'src'`). Saving goes through Jean: the relay watches `createObjectURL` and `download` links, and Jean saves the file after a click of the user's. Pictures and PDFs (drawn by pdf.js) show in Jean's own document from what Jean keeps. **Office files** (D183), made by Jean, shared, kept by the Computer or in a folder the browser shows, and a CSV made a workbook by Jean's own writer, are drawn by `@silurus/ooxml` (MIT): parsers in WebAssembly, viewers that draw on a canvas with a text layer to select, a document's pages and a deck's slides scrolling, a workbook with its sheets' tabs, nothing fetched. They run in a frame of the same kind, in a page `caps/files/office.js` makes: the viewer's modules as `data:` addresses under an import map (`npm run vendor` names their relative imports for it and starts their workers as classic scripts, which an opaque origin can start from a blob), its parser and the file as data. A page whose scripts are data, a folder's or an Office file's, may also start `blob:` workers, show `blob:` pictures and run WebAssembly. With Run its code off, such a file shows its text. *Why:* the pages Jean makes are charts and small tools that need their scripts; their scripts have WebRTC, which no policy closes, a risk accepted since they have no fetch, none of Jean's storage and no way out of the frame. People judge a deck or a workbook by how it looks, and browsers have no Office of their own: drawing it on the device is the closest to native that keeps the file there, and a canvas puts nothing of the file in a document as markup. *Rejected:* `srcdoc` or blob frames (they take `index.html`'s policy); the browser's PDF viewer (`blob:` in `frame-src`); `allow-downloads` (WebKit takes a download for a navigation); the policy as text in Settings; a document per combination of switches; `http:` from the internet; this computer inside `*`. For Office files: Microsoft's or Google's online viewers (the file would have to be uploaded at a public address); LibreOffice in WebAssembly (about 100 MB, and its threads need cross-origin isolation); docx-preview, pptx-renderer and reamkit together (three libraries building markup from the file; reamkit's HTML was 36 MB for 10,000 rows); the viewer in `index.html` (it sets `innerHTML`, which Trusted Types refuses, style attributes and `data:` workers); slides and sheets as their text.
- **Another site's page** is the one frame with both `allow-scripts` and `allow-same-origin` (D140, under Browser).

## Brains

- **D15 · D42 · The brain ladder: on this device → one click → keys and local servers.** On the device, Gemma 4 E2B (q4f16, ~3.1 GB for text, its image and audio encoders when first needed), offered only where it runs (WebGPU with `shader-f16`, enough memory and storage); one click is the OpenRouter sign-in; then the user's key or a local server. *Why:* no account needed where the device allows it, and the on-device brain must read documents, call tools and answer in ~30 languages. *Rejected:* browsers' built-in models (too experimental); Qwen3-0.6B (too weak for multi-step work; Kev covers the small slot).
- **D32 · Anthropic defaults:** `claude-opus-5-5`, adaptive thinking with summarized display, server-side refusal fallbacks, eager tool-input streaming; OpenAI gets `max_completion_tokens`. *Rejected:* the SDKs; `budget_tokens`.
- **D31 · Tool calls run at the end of a model step,** not mid-stream, so a mid-stream refusal fallback never leaves earlier calls run.
- **D36 · Brain entries store the provider and model as data;** their labels render in the current language.
- **D54 · Anthropic's thinking blocks are kept on the step's brain entry and replayed as they were** to the model that wrote them; a stale signature retries once without them. *Why:* dropping them is an edit, which costs the cache. *Rejected:* stripping thinking at each turn.
- **D58 · The device's brain reuses its KV cache by text prefix:** its worker keeps the text and tokens it read and only reads what follows. *Rejected:* cropping the cache at a token-level prefix.
- **D70 · Auto.** `ui/auto.js` turns Intuition's demand into a tier (fast, smart, best) and steps up when the user seems unhappy, never down within a conversation. Personal content stays on the device or a local server when there is one, and "Never send to the cloud" allows only those; a picture goes to a brain that can see (D105); without Intuition, the smart tier. Tier ids (`TIERS`, which policy replaces) are used only when the provider's live model list has them. The brain entry records `auto: { level, reason }`, shown in plain words. *Rejected:* unchecked tier ids; stepping down mid-conversation (the cache and the tool format would change).
- **D136 · More services take a key:** Google Gemini, Vertex AI, Mistral AI, Vercel AI Gateway, Hugging Face, Groq, Cerebras, Together AI, Fireworks AI and xAI, each a first-party Chat Completions API that answers browsers, with the steps to get a key. *Rejected:* GitHub Copilot's and Claude Code's tokens (their terms); GitHub Models (no CORS); DeepSeek (data rules many security reviews refuse); Vertex AI sign-in with Google (an OAuth client per deployment).
- **D194 · A brain is used in every project, or only in those ticked,** as a connection is (D191): `projects` on its entry, ticked under it in Settings › Brains once there are projects. The room's project decides which brains Auto, the picker, Double-check, pictures, routines and Since last time choose from; one chosen in another project gives way here to the first of this one's, and one kept elsewhere is listed but can't be chosen. *Why:* a key a client or an employer pays for is for their work only. *Rejected:* a brain chosen per project (one choice, and Auto per message, stay simpler); the key in the project's folder (secrets stay in `.secrets/`, out of backups and syncs).
- **D112 · A brain writes each conversation's title beside the first answer,** in one short request outside the conversation (the provider's fast tier when it has one); after 20 s, an error, or with the device's brain, the title is the message's first words. *Rejected:* titling after the answer; titling inside the conversation; Intuition.

## Prompt, tools and context

- **D8 · Short, calm prompts, after pi:** about 200 tokens in sections, one line per tool. *Rejected:* DEVS's 2,000-token personas.
- **D46 · The prompt and the declared tools are frozen for a conversation; changes arrive as system notes.** A note is a record in the transcript (`_system_note`), rendered as a `system` message where the provider takes one there, otherwise as a tagged block in the next user turn, and never edited or deleted. *Why:* providers cache by prefix, the device's brain keeps its KV cache, and the transcript records what the brain was told, and when. *Rejected:* editing the prompt in place.
- **D81 · The context is frozen sections, each changed by a note that gives it whole:** `project`, `instructions`, `memory`, `skills`, `connections`, `folder` and `page`, each fingerprinted (FNV-1a). Instructions are always read: the organisation's (locked), the person's, the project's. *Rejected:* line-by-line diffs; reading the files into the prompt at every request.
- **D47 · D63 · D64 · D104 · Deferred tools.** Only the tools unlocked when a conversation starts are declared, with `find_tools` and `offer` (the `discovery` capability, always loaded) in every conversation. A later tool is found with `find_tools` (BM25 over names and descriptions) and called from a script, or declared from the next request on, recorded as `_meta.declare` so replay rebuilds the list. A deferred tool the brain calls by its exact name runs under the rules without being declared; a missing argument gets its signature back. Every tool can be called; only `declared` ones are shown; `hidden` ones (`file`, `decide`, `image`, `helper`, …) are for scripts or other tools; `tools` is read at each step, so a capability turned on mid-turn is callable at once. *Why:* a small prompt for small brains, and a stable cache however many connections there are. *Rejected:* declaring everything upfront; changing the list without a record; insisting on `find_tools` first.
- **D48 · Codemode: scripts call Jean's tools.** A `javascript` script gets `tools.<name>()`, `file()`, `csv()`, `fs`, `fetch` through Jean, `searchTools()`, `models.decide()` and `models.image()`. Every nested call goes through the rules, shows nested under its call, and stays out of the brain's context. Declared tools stay callable directly. *Rejected:* codemode only (small brains call tools more reliably than they write code); a second sandbox.
- **D49 · Anthropic prompt caching, with warming.** One breakpoint at the end of the system prompt plus automatic caching. When the user starts typing after about 5 minutes without a request, and the prefix is big enough to cache, the same prefix goes out with `max_tokens: 0` and the real request's thinking and effort. *Rejected:* a periodic keep-alive; the 1-hour TTL everywhere.
- **D55 · Shared files are linked, not copied, and what the brain reads of them is decided once,** when the message is sent: pages up to 25% of the brain's context, recorded as `_meta.pages`; `read` reaches the rest. Tokens are estimated as UTF-8 bytes / 3. *Rejected:* deciding again at each request; a tokenizer per provider.
- **D24 · No vector database:** a whole document when it fits, otherwise agentic BM25 search; embeddings only if the test set proves them needed.
- **D57 · "What Jean read" lists every file in the brain's context for an answer, and that turn's `read` calls,** from the records, so it is true even when a small brain cites nothing.
- **D71 · D90 · Every source is numbered once, and recorded.** A shared file's number is on its link (`_meta.source`); tools call `ctx.cite()`; the brain's own search arrives as `cite` events; numbers continue through the conversation and are recorded as `_meta.sources`. `[n]` becomes a chip only for a known source, and a "Sources" list follows the answer. *Rejected:* numbering when rendering; each provider's citation format as it comes.
- **D23 · D91 · D145 · Web search is the brain's own, or Wikipedia, with no Jean proxy.** `web_search` is `native`: Anthropic's and OpenRouter's own search take its place; every other brain gets Wikipedia in the user's language (`urls.wikipedia`). It is offered only after five conversations, so the first ones show what Jean does alone. *Rejected:* a search proxy (DEVS's `proxy.devs.new`); OpenRouter's web plugin (it searches on every request).

## Intuition

- **D16 · D41 · D67 · Reflexes are Kev-0.6B through Transformers.js, asked in the Decisions API's shape;** the UI calls them Intuition. All of a state's questions go into one forward pass, with Kev's delimiter ids from its `config.json` (the model card's sample escapes them, which flattens every score). A score is read as its most likely level; a yes, or an offer, needs 0.6; a message waits 2.5 s at most. About 345 MB, q4f16 on WebGPU or q4 on WebAssembly, downloaded with consent. *Rejected:* Laya (a second runtime); the brain for every decision; hosted Jev by default.
- **D68 · D84 · Kev is measured in all 33 languages, and needs fine-tuning before launch.** `test/reflexes/<lang>.json` holds 44 labelled examples per language, machine-translated; `npm run reflexes` writes [test/reflexes/results.md](../test/reflexes/results.md): 67% overall, tables reliable, "personal", "unhappy" and "lasting" near chance (Kev mostly says no), the low-resource languages lowest. A fine-tuned "Jean reflexes" checkpoint is needed.
- **D69 · Follow-ups come from three places:** the brain's hidden `<suggestions>` block, "Shorter" for an answer over 220 words, and "As a table" or "Draft an email" when a reflex says so. *Rejected:* "Simpler" and "Translate"; one choice over the whole catalogue.
- **D72 · Offers: what the user is doing now beats what is merely due.** An offer comes from an event (a long paste, a spreadsheet, a count of conversations) or a reflex at 0.6; one shows at a time, and a contextual one replaces an ambient one; Backup is never offered in a private window; the brain's `offer` waits inside the answer. "Turn on everything" never downloads weights without consent.
- **D100 · Double-check asks the brain that answered, not Intuition,** in one request outside the conversation: each cited claim (12 at most), with the passages of its sources, is supported, contradicted or missing, shown under the answer with a way to correct it. Offered after three cited answers. *Rejected:* Kev (unmeasured, too small); a second provider; the verdicts inside the conversation.

## Capabilities

- **D79 · Memory.** Once on, `remember` and `recall` are declared like any tool, with one rule. `memory.md` has one line per entry, with when, by whom and from which conversation in a hidden comment; the person's at the root, a project's in its folder. The brain reads the newest lines within about 1,000 tokens, the same for every brain; a toast offers Undo. Offered by Intuition's "lasting" question, the brain or its trophy. *Rejected:* a tool handed out by a reflex (it changes the declared list); a budget per brain; one JSON file.
- **D22 · D83 · D115 · Skills are Agent Skills (`SKILL.md`), and the UI calls them skills.** `skills/<name>/SKILL.md`, global or in a project; `<skills>` lists each name and description; `skill` reads the steps and `save_skill` writes them. The third request of a kind (its first words compared with the openings of earlier conversations by `alike()`) offers to save one. *Rejected:* DEVS's marketplace YAML; a Kev "same kind of task" question.
- **D116 · D121 · Skills from elsewhere come from Agent Skills discovery indexes,** from policy (`skills.sources`, and `skills.only` to keep to them) and the user's list (by default, the indexes that answer browsers). They are compared with requests on the device, never sent to a search service, and a skill comes in only by the user's hand after they read its steps, once its download matches its digest and holds only instructions (`SKILL.md` and text, from `.tar.gz` or `.zip`, 2 MB at most). The brain can point to one with `suggest_skill`, deferred. *Rejected:* a search service; skills that run scripts; adding what the brain finds.
- **D122 · Routines are requests Jean sends itself on a schedule:** `routines/<ulid>.md`, every day, working day, week or month at a local time. With no server, one runs while Jean is open, once it is free and the user isn't reading, one tab at a time; times missed while it was closed make one run at the next visit. ## Desktop

- **D155 · D160 · D169 · D176 · A desktop app, with Neutralino.** `npm run build:desktop` embeds the files a deploy serves in Neutralino's binary, which serves them on 127.0.0.1:24601 (fixed, since the origin holds the data) to a window of the system's own web view: `Jean.app` (bundle id `cx.jean.desktop`), `jean-win_x64.exe` and `jean-linux_*`; `npm run build:dmg` makes the Mac's disk image. None of these come from `BRAND`, and none may change once in use. The native API is on for nine calls only, none of which starts a program (`NATIVE` in `scripts/desktop.js`), for Sync's folder (D157) and the computer's memory in Settings › Computer (D176); `ui/host.js` takes the one-time key as Jean opens and is the only module that talks to the host. On the Mac, a launcher inserts `libjeanframe.dylib`, which turns on WebKit's internal setting that ignores `X-Frame-Options` and `frame-ancestors`, so sites that refuse frames show in the browser pane (window-wide, so the preview's frames get it too; accepted). That needs bundle mode, since the embedded build's resource reader crashes when an extra library loads; Windows and Linux stay single embedded files. Developer ID signing and notarization will need the `allow-dyld-environment-variables` entitlement. *Why:* the system's web view stays lean, and the window serves exactly what a deploy copies. *Rejected:* Electron; Tauri; Neutralino's random port; its client library; a native bridge beyond what Sync and Settings › Computer ask.
