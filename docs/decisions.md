# Decisions

Made on 2026-10-01 unless stated otherwise. Each entry gives the decision, why, and what was rejected. To change one, add a new entry that supersedes it; don't edit history.

| # | Decision | Why | Rejected |
|---|---|---|---|
| D1 | **Reboot from scratch** rather than refactor DEVS | No users or years of fixes to protect; cutting 95% is harder than writing ~5k clean lines | Incremental pruning of DEVS |
| D2 | **First user: a non-technical knowledge worker**; one job: files in, things out | A sharp job beats an architecture ("swarm") as a pitch | Developers first; generic chat |
| D3 | **Open source, reputation first;** money secondary | The goal is craft and reach; plain files keep the Obsidian-style door open | Designing a paid relay now |
| D4 | **Working name Jean, held in the `BRAND` variable,** display only | The name may change; data must not depend on it | Name in identifiers or storage |
| D5 | **"Incremental" means game-like progressive discovery** | Teaches itself; the simple first screen and the small first load are one decision | Feature-complete UI from day one |
| D6 | **Discovery triggers: events, reflexes, `offer()` — never keywords** | Must work in every language | Regex/keyword intent rules |
| D7 | **One agent loop plus helpers;** no orchestrator or methodologies | 2026 winners are single-loop agents; delegation is one tool | DEVS's decomposer/teams/synthesis and 8D/DMAIC templates |
| D8 | **pi-style prompts** (~150 tokens, sections) | Small on-device brains, calm instructions, cache-friendly | DEVS's 2k-token persona prompts |
| D9 | **No build step:** ES modules, import map, JSDoc + `tsc --noEmit` | View-source is the source; deploying is copying; no toolchain rot | Vite/TypeScript build; React; htmx |
| D10 | **Custom elements + `@preact/signals-core` + `lit-html` + `marked` (lexer)** | Standard elements upgrade when their module loads, which *is* progressive discovery; CSP-safe | Preact + htm; VanJS; Alpine (needs `eval`); htmx (needs a server) |
| D11 | **Data as plain files in OPFS** behind `core/fs.js` | Portable, readable, sync-friendly, user-owned | Yjs as the whole data layer; IndexedDB records |
| D12 | **Writes via a storage worker using `createSyncAccessHandle`** | Works from Safari 16.4; `createWritable` needs Safari 26 | Main-thread `createWritable` only |
| D13 | **Keep QuickJS** for JavaScript | Code can only reach what Jean hands it; hard memory and time limits; same sandbox in every host | Running JavaScript in a sandboxed iframe (can still navigate itself, WebRTC not covered by CSP, can freeze the tab) |
| D14 | **Pyodide with no network,** enforced by a CSP `<meta>` in `sandbox.html` | Static hosting can't set headers; untrusted code only in a worker that inherits the strict CSP | Pyodide in a plain worker (its `js` bridge can call `fetch`) |
| D15 | **Brain ladder:** on-device Gemma 4 E2B → one-click cloud → keys/local servers | Works out of the box; universal; multilingual | Browser built-in models (too experimental); Apple Foundation Models / native shells (not lean) |
| D16 | **Reflexes through a Decisions API (Jev shape);** local Kev or Laya, chosen by evaluation | Cheap, private, multilingual decisions without paying LLM prices | The brain for every decision; hosted Jev/Clef as default (need a server or account) |
| D17 | **ACP `session/update` as the event and transcript format** | Standard, small, semantic (kind, locations, plan, permissions map onto rules) | A custom format; AG-UI (built for a UI fronting a server agent) |
| D18 | **Projects are self-contained folders;** an agent is a project with an identity | One mechanism for contexts and agents; folder operations give backup, share and sync | Separate "agents" and "spaces" concepts; `spaceId` on every record |
| D19 | **UI word "Project"** | Already taught by Claude and ChatGPT; translates everywhere | Space (collides with ChatGPT Space), Agent (jargon), Room (French "pièce" ambiguity), Folder (confusing) |
| D20 | **Rules: Do it / Ask me first / Never** | Clear, maps onto ACP permission options, lockable by policy | Free-form permissions |
| D21 | **MCP for connections** | Open standard; replaces DEVS's 30k lines of connectors | Proprietary connector code; an app catalogue |
| D22 | **`SKILL.md` for routines** | Portable across Claude, Codex and others | DEVS marketplace YAML |
| D23 | **Web search via the brain's own search, Wikipedia, or a configured endpoint;** no Jean proxy by default | DEVS's `proxy.devs.new` was a server in disguise | Running a search proxy |
| D24 | **No vector database:** whole document if it fits, else agentic BM25 search with reflex re-ranking | The brain writes queries in the document's language; fewer moving parts | Embeddings-first RAG |
| D25 | **i18n built in everywhere,** with instant switching, ~30 languages | Jean is for every region; signals make switching free | English-first with translations later |
| D26 | **Dictation and read-aloud from day one;** live conversation discovered | Accessibility first | Voice entirely gated |
| D27 | **Data bound to the origin:** settle the domain before launch | A domain change means migrating everyone's data | Launching on a temporary domain |

## Added while building 0.1 (2026-10-02)

| # | Decision | Why | Rejected |
|---|---|---|---|
| D28 | **Trusted Types on, with one extra policy, `app-urls`,** that only allows same-origin script URLs (the storage worker, the service worker) | Without it, Trusted Types blocks `new Worker()` and service-worker registration; with it, no other script URL can ever be created | Dropping `require-trusted-types-for` |
| D29 | **The inline import map is allowed by its SHA-256 hash in the CSP,** guarded by `test/html.test.js` | Browsers don't support external import maps; a hash keeps `'unsafe-inline'` out | `'unsafe-inline'`; a bundler |
| D30 | **Organisation policy is opt-in** via `<meta name="app-policy" content="policy.json">` | No 404 noise for everyone else; organisations already edit `index.html` and send headers | Always fetching `policy.json` |
| D31 | **Tool calls are emitted at the end of each model step,** not mid-stream | After an Anthropic mid-stream refusal fallback, earlier tool calls must not run | Streaming tool calls as they complete |
| D32 | **Anthropic defaults:** `claude-opus-5-5`, adaptive thinking with summarized display, server-side refusal fallbacks (`fallbacks: "default"`), eager tool-input streaming; OpenAI gets `max_completion_tokens` | Current API guidance; summaries feed the activity view | SDKs; `budget_tokens` (rejected by current models) |
| D33 | **Provider endpoints in `PROVIDERS` and the OpenRouter OAuth URLs are provider identities,** not hidden dependencies: every base URL can be overridden in settings or policy | The "no hard-coded third-party URL" rule targets services Jean depends on, not the provider a user explicitly picks | Configuring every provider by hand |
| D34 | **Display face: Instrument Serif (OFL), regular and italic Latin subsets** (15 KB each); Arabic headings use the system font | Warm, editorial, memorable; within the 30 KB budget | Variable fonts with many axes (too heavy) |
| D35 | **Markdown images from model output are never loaded,** only their alt text is shown | An image URL is a classic way for injected instructions to leak data | Rendering images |
| D36 | **Brain entries store provider and model as data;** labels are rendered in the current language | Switching language relabels history, as planned for the activity view | Storing only the rendered title |
| D37 | **Development uses a deterministic fake brain** (`test/fixtures/fake-brain.js`) | End-to-end checks without keys, downloads or network | Testing only against real providers |

## Answers to the open questions, and pi 1.0 (2026-10-02)

| # | Decision | Why | Rejected |
|---|---|---|---|
| D38 | **Jean is its own project.** It sits in the DEVS repository only to draw on DEVS's history. There's no devs.new redirect, no migration or import from DEVS, and no plan to archive DEVS. Nothing in Jean reads, imports or copies files from outside its own folder. | Jean is a new product, not a DEVS release; a folder that needs nothing around it moves to its own repository unchanged | Treating Jean as DEVS's successor (redirects, data import); reusing files from the DEVS tree |
| D39 | **License: MIT,** in Jean's own `LICENSE` file | Same as DEVS and the ecosystem Jean builds on; maximum reuse | Copyleft licences |
| D40 | **Minimum browsers: Safari 16.4, Chrome 108, Firefox 111** (sync access handles, D12). Confirmed. | It's the floor set by sync access handles, and nothing else in Jean needs newer; universal beats newest | Raising the floor to Safari 26 for `createWritable` or WebGPU |
| D41 | **Reflexes: Kev-0.6B** through Transformers.js (supersedes "Kev or Laya" in D16). The multilingual test set stays: it measures Kev in each launch language and decides whether a fine-tuned "Jean reflexes" checkpoint is needed. | Shares the brain's runtime (no extra dependency), small (~340 MB), and the better fit | Laya multilingual through laya-ts plus onnxruntime-web (a second runtime) |
| D42 | **On-device brain: Gemma 4 E2B, quantised (q4f16),** confirming D15. The text-only download is about 3.1 GB; the image and audio encoders download the first time they're needed. The rung is offered only to devices that can run it (WebGPU with `shader-f16`, enough memory and free storage); other devices get the one-click cloud rung. | The on-device brain is Jean's first impression for everyone who skips an account. It has to read documents, call tools and answer in about 30 languages, and handle scans as images. Kev already covers the small, runs-everywhere slot. | Qwen3-0.6B (~0.5 GB, runs almost anywhere, but too weak for multi-step tool use and document answers in most launch languages, and text only) |
| D43 | **Pyodide is never committed and never taken from outside Jean's folder.** Jean pins its own `pyodide` npm package, and `npm run dev`, `npm start` and `npm run build` copy its files into `vendor/pyodide/`, which is gitignored. The Python packages the data toolkit needs follow the same rule. This amends D9: deploying means `npm ci && npm run build`, then copying the folder. Jean's own source still ships exactly as written. | Pyodide is ~14 MB of third-party binaries per version; committing it bloats history, and borrowing DEVS's copy breaks D38 | Committing Pyodide; serving it from DEVS's tree; loading it from a CDN at runtime |
| D44 | **Translations are machine-made and get no per-language human review.** Launch with the 33-locale candidate list. Anyone can fix a string with a PR, like any other bug. The reflex test set gets no native-speaker review either. | Review doesn't scale to 33 languages; about 150 short strings is a size machine translation handles well | A reviewer per language as a launch gate |
| D45 | **Collaboration relay: hosted by the maintainer on a subdomain of Jean's domain** (e.g. `relay.jean.cx`). It only runs when the user turns collaboration on. It is self-hostable, and its address is a default setting that policy can replace or switch off. It forwards end-to-end-encrypted traffic, so it can't read what passes through. | Someone has to run the default for "invite someone" to work out of the box; encryption keeps "no Jean server sees your data" true | No public relay (collaboration only for those who self-host); a relay that can read content |
| D46 | **A frozen prompt per conversation, with mid-conversation system notes.** The system prompt and the declared tools are fixed when a conversation starts. Later changes (language, rules, instructions, memory, project, newly unlocked tools, the date) are appended to the transcript as system notes where they happen. Adapters render them as `role: "system"` messages where the provider accepts them, and as a tagged block in the next user turn elsewhere. (Adopted by pi 1.0.) | Providers cache by prefix, so editing the prompt re-bills the whole conversation, and on-device it throws away the KV cache. The transcript also records exactly what the brain was told, and when. | Editing prompt sections in place, which [prompts/system.md](../prompts/system.md) wrongly said kept caches warm |
| D47 | **Deferred tools.** Only the tools unlocked when a conversation starts are declared. Tools that arrive later (a capability discovered mid-conversation, every connection's tools) are found with `find_tools(query)` and called through codemode (before codemode is loaded, they're declared from the next request on). A provider's native deferral (Anthropic's `defer_loading`) may replace this as an optimisation. (Adopted by pi 1.0.) | The prompt stays small for small brains and stable for caches, however many connections there are | Declaring every tool upfront; editing the tool list mid-conversation |
| D48 | **Codemode: `run` scripts can call Jean's tools and non-LLM models.** Inside QuickJS a script gets `tools.<name>()` (Jean's tools and connection tools, deferred ones included), `searchTools()`, `models.decide()` (Kev, or Jev when connected) and `models.image()` (image models from the connected provider). Every nested call passes the same rules and shows in the activity view as a child of the `run` call. Declared tools stay callable directly. (Adopted by pi 1.0.) | One script replaces many round trips and many tool schemas; QuickJS already limits code to what Jean grants it | Codemode as the only way to call tools (small brains call tools more reliably than they write code); a second sandbox |
| D49 | **Anthropic prompt caching, with warming.** One explicit breakpoint at the end of the system prompt, plus automatic caching for the conversation tail. When the user starts typing and the cache has probably expired (no request for about 5 minutes) and the prefix is big enough to cache, Jean sends the same prefix with `max_tokens: 0`, unstreamed. Thinking and effort match the real request, so the cache it writes is the one the reply reads. (Adopted by pi 1.0.) | First-token latency is what users feel; a warm-up costs one cache write, paid only when a message is on its way | A periodic keep-alive (pays while nobody is there); the 1-hour TTL everywhere (double write price) |

## Standalone repository (2026-10-02)

| # | Decision | Why | Rejected |
|---|---|---|---|
| D50 | **Jean has its own repository** (`~/repos/codename/jean`), moved out of the DEVS repository with its history (`git subtree split`). This supersedes D38's "sits in the DEVS repository"; the rest of D38 stands. | A separate project needs its own history, issues and releases; the move cost nothing because the folder was already self-contained | Keeping Jean as a DEVS subfolder |
| D51 | **`vendor/` is never committed.** The three upfront libraries follow D43: `npm run dev`, `npm start`, `npm run build` and `npm run check` copy them from Jean's own `node_modules` (only the lit-html files Jean imports). `package-lock.json` pins their exact bytes, so the committed `index.html` preloads and `capabilities.json` hashes stay reproducible, and `npm run manifest -- --check` catches drift. | Third-party code in history is noise in every diff and review, and a second copy that can disagree with `package-lock.json` | Committing `vendor/` (the 0.1 layout) |

## Added while building 0.2 (2026-10-02)

| # | Decision | Why | Rejected |
|---|---|---|---|
| D52 | **On-demand runtimes are `optionalDependencies`, copied into their own `vendor/` folders.** `pdfjs-dist` (legacy build, character maps and standard fonts) goes to `vendor/pdfjs/`; `@huggingface/transformers` and `onnxruntime-web` (its WebGPU bundle and one `asyncify` wasm) go to `vendor/transformers/`, with bare specifiers rewritten to local files because import maps don't reach into workers. The manifest lists those folders under the capabilities that use them (Files; the on-device brain and dictation), never in the shell. Nothing is ever fetched from a CDN (transformers.js defaults to jsDelivr; Jean sets `wasmPaths`). Extends D43 and D51. | Upfront dependencies stay at three (`dependencies` is what the budget counts); a capability's code and runtime are cached together when it unlocks; the shell never precaches 30 MB of wasm | Loading the runtimes from a CDN; listing them in `dependencies`; `transformers.min.js`, which bundles its own ORT and duplicates it. Known cost: `npm install` also fetches `onnxruntime-node` and `sharp` (transformers.js's Node backends), about 300 MB that Jean never ships |
| D53 | **Model weights come from a configurable host,** `settings.urls.modelWeights`, which policy can replace (`urls.modelWeights`, as sketched in [enterprise.md](enterprise.md)). The default, Hugging Face, lives in `DEFAULT_URLS` in `core/settings.js` and is a provider identity, like a brain's URL (D33). Defaults are resolved, never written into `settings.json`, so changing one later reaches everyone. | Organisations mirror weights internally; "no hard-coded third-party URL" holds because every address is overridable | Hard-coding huggingface.co in the workers |
| D54 | **Anthropic thinking blocks are kept in the transcript** (on the step's brain entry, `_meta.raw`, only when there is thinking) and replayed verbatim to the model that made them. Other models get the text and tool calls. If the API rejects a stale signature, the request is retried once without the earlier reasoning. This supersedes 0.1's "raw blocks are never persisted". | Current models bind thinking blocks to the conversation; dropping them is an edit, which costs the cache from that point on (D46, D49) | Stripping thinking at every turn boundary |
| D55 | **Shared files are linked, not copied, into the conversation** (ACP `resource_link` chunks), and the pages that go into the brain's context are decided once, when the message is sent: everything up to 25% of the brain's context (32k tokens on the device, else the model's listed context), recorded on the link as `_meta.pages`. The rest is reached with the `read` tool. Tokens are estimated as UTF-8 bytes / 3, generous for Latin scripts and about right for CJK. | The message the brain read never changes afterwards, so the cache stays valid even if the brain or its budget changes later | Re-deciding inclusion per request; a tokenizer per provider |
| D56 | **Dictation is private by default:** the browser's on-device recognition (`processLocally`) where it exists, otherwise Whisper base (8-bit, about 80 MB) on WebAssembly in a worker, downloaded once after a confirmation. Never the cloud recognition some browsers use by default. The language is the interface language. | Accessibility without sending audio anywhere; base runs on every device, including those without WebGPU | Whisper small (about 250 MB, better for Arabic: a setting later if testers ask); the browser's default cloud recognition |
| D57 | **"What Jean read" lists every file in the brain's context for that answer** (shared in this message or earlier, with the pages that fit) plus that turn's `read` calls, from the records. | It must be true even when a small brain cites nothing; a file shared earlier is still read | Only the files of the current message; the brain's own citations |
| D58 | **On-device KV cache reuse by text prefix.** The worker keeps the exact text and tokens it has read; when the next prompt starts with that text, it tokenizes only the rest and passes the cache to `generate`. Otherwise it drops the cache and reads everything. | Re-tokenizing a reply can produce different tokens; comparing text keeps the reuse exact. With the frozen prompt, a follow-up question normally continues the previous text. | Cropping the cache to a token-level common prefix (tensors may live on the GPU) |
| D59 | **The address holds the open conversation** (`#/c/<ulid>`; `#/` is a new one). Reloading, going back or forward, or reopening the tab shows the same content. The unsent draft is kept per conversation in `sessionStorage` (this tab only). Dialogs and scroll position are not part of the address. An unknown id opens a new conversation. | The minimum to come back to the same place; a hash works on any static host and never reaches a server | Path routing (needs host rewrites); putting dialogs or drafts in the address |
| D60 | **Japanese ships in 0.2** (`locales/ja.json`, machine-translated like the others, D44), ahead of the other launch locales in 0.3, so every UI change can be checked in a CJK locale as AGENTS.md asks. Arabic and Japanese headings use the system font, because the display face is Latin only. | The testing rule needs a real CJK interface, not just CJK content | Waiting for the 0.3 batch |
| D61 | **Dictation falls back when the browser's own recognition fails.** Some Chromium browsers (Arc, reported on 2026-10-02) say on-device recognition is available, then deliver nothing. A session that ends with an error or no words switches dictation to Whisper for the rest of the visit and tells the user. The recogniser gets a full language tag from the user's languages (`fr` → `fr-FR`). Amends D56. | Dictation must not fail silently | Trusting `available()` alone |
