# Product

## Who and what

- **One sentence:** everyone's AI, in a browser tab. It starts as one box, takes anything in and gives anything back, with the AI you choose, and keeps what it holds on your device. Nothing to install, free and open source (D2 · D395).
- **Who:** everyone, non-technical people first, in three places:
  - **at home:** a person with a question, a letter, a budget, a trip, a song to write;
  - **in a family:** a profile for each child, set by a parent (D228, D389);
  - **at work:** a knowledge worker, often on a managed laptop, and the IT team that deploys Jean like a web page ([enterprise.md](enterprise.md)).
- **Design for the weakest device:** a managed Windows laptop running Edge or Chrome, a weak graphics chip and IT policies; a family's shared computer; a phone.
- **What it does:** people ask in words, aloud, or with a file, a folder, a picture or another assistant's export, and get back what they asked for, made: an answer with its sources, a Word document, a spreadsheet, a deck, a chart, a score that plays, a picture, a page that works, a map, a routine. Numbers are worked out by code Jean runs, not guessed. Files in, files out is the job people search for most, so it leads the examples, never the identity.
- **What sets it apart,** in this order:
  1. **Simple.** One box. The rest is offered when a moment calls for it, and the first load stays small ([Progressive discovery](#progressive-discovery)).
  2. **Universal.** Anything in, anything out, with any brain: one on the device, a free one, a plan already paid for, or a company's gateway. In 33 languages, in any recent browser, a phone's included.
  3. **Confidential.** What Jean keeps is encrypted on the device, and there is no Jean server. On a computer with 12 GB of memory and a recent graphics chip, the answers can be written there too, offline (D319, D371).
  4. **Ready for a family.** A profile per child, set by a parent: topics by age, an under-13 lock and a danger notice (D389, D390). Learning's skills help a child learn rather than do the work (D394). The tutor is promised only once `npm run tutor` shows that the brains offered to a child rarely give the answer.
  5. **Open.** MIT, open standards (MCP, `SKILL.md`, ACP, the OpenAI-compatible and Anthropic APIs), plain files readable without Jean, apps, and a static folder anyone can host.
  6. **Shareable.** A task, or anything Jean made, goes out as a link sealed in the browser, which the host can't read, with a password and an end date if wanted, and its answers' certificates (D361); or as a web page that opens anywhere (D305).
- **Behind those six:** honest (each answer says where it was done, with a certificate, D252, D274), careful (Do it, Ask me first or Never, and a sandbox for code), multilingual (right to left included, voice on the device), accessible (WCAG AA, with dictation and read-aloud always there).
- **The browser is the security model.** The category's biggest problem is agents with shell access on your laptop. Jean stays inside the most battle-tested sandbox there is.
- **Open source and reputation come first.** Revenue is secondary. Everything a person or a team uses is MIT. Organisations pay only for the enterprise integrations their IT, security or compliance teams ask for, in `ee/` (open core, D139).

## Progressive discovery

Jean is learned the way *A Dark Room* is played: the first screen holds a single box ("What can I do for you?"; once something is asked, a line under it says "Jean is AI and can make mistakes", D273), and capabilities show up when a situation calls for them.

**How it works:**

- **Three triggers, never keywords or rules,** so it works in every language:
  1. Events that carry no language: a file dropped, a long paste, a download finishing.
  2. Reflex questions answered by a local multilingual decision model (see [architecture.md](architecture.md#reflexes)).
  3. The model's own `offer(capability)` tool, as a backstop.
- **Offers are short.** Jean introduces a capability in one sentence. If the user accepts, that capability's code loads and its tools join the conversation. Once discovered, it stays visible until the user turns it off. "No thanks" is for good (kept in `offers`): nothing offers it again, above the box or in an answer, where the brain's `offer` hears it was turned down and shows no card, and its trophy still turns it on (D219); stopping the answer, or walking into another project, while its card waits isn't a no. The brain's `offer` waits inside the answer, which goes on once the capability is turned on or down; its description of each capability, a few words, goes with every request, those policy denies left out. "Turn on everything" never downloads weights without consent.
- **One offer at a time,** above the box, and above the ideas where they are above it too (a phone). One about what the user is doing now (a paste, a file, a reflex, a request of a kind, a server refused, coming back) takes the place of the one shown, unless a download is under way; one merely due (a count reached), like Backup after three conversations, waits until nothing is shown, then the next due in turn (Backup, Intuition, Search), so an offer left unanswered hides none for good. Conversations are counted in every project, since Backup, Search and Intuition are about all of them (D281), and nothing of a capability shows before it is found.
- **"What Jean can do"**, Settings' Capabilities section, is a case of trophies (D127, D316). Each capability is a row, lit once found. Each undiscovered one is a silhouette that says how it is found ("Share a spreadsheet"), so the case doubles as a list of things to try. A count and a bar show how much of it is found. Curious users can open a row and turn it on early, and power users can unlock everything at once.
  - **Turned off** (D433): a row found, open, turns its capability off, and on again. Off, it is still found but dark, Off at its end where On was, and nothing of it shows or loads: no offer, no tool, no section, no button, and what would find it (a file dropped for Files) does nothing, until its row turns it on, at once, as found. Jean then opens afresh where it was, once no answer is being written, since a capability's code can't be unloaded; so do other tabs that had it. Things Jean made doesn't turn off, being always there, nor do a lock and the brain on this device, which are removed where they are set (Your data, Brains); and nothing turns off in a private window, which opening afresh would empty. Asked, Jean says which are off and where they come back.
- **Asked what it can do, or where something is,** Jean reads its own guide, which says where each capability stands for this person: found, still to find and how, turned down, or not in this browser, never one the organisation denies, and names each menu and button as the screen does, in its language, with the shortcuts this keyboard has, what the organisation or a parent locked, and the services that can be connected here (D423). It answers with two or three things that fit, one to try now, rather than the whole list.
- **Discovery and code loading are one decision.** Each capability is a module loaded on demand, so the simple first screen and the small first load are the same thing.
- **Capabilities are granted with consent, never present by default.** This is the same idea as the QuickJS sandbox.
- **Enterprise policy can unlock or deny capabilities in advance.** A denied capability is never offered and never downloaded.

**Always available, never gated:** the box, read-aloud, dictation (for accessibility), the language switch, light or dark, the activity view, and "unlock everything" in settings. Things Jean made, questions (`ask`) and noting the user's name (`you`) are capabilities that are always there, and formulas (`math`) load with the first one in an answer, drawn as they are printed, a LaTeX document laid out with them (D185), and layouts (`layouts`) with the first answer, for its comparisons, steps, notes, timelines, key figures and checklists to tick (D291): options side by side, each with its picture when a source gave one (D35), the best of each row lit and the pick framed, steps in rings, notes in their colour, and on a wide screen a table of three columns or more takes the room it needs beside the text (D215); and the receipt (`receipt`) with the first message, for About this answer (D252); and pages (`interactive`), with the first message too, so that a tool or an explanation to play with (a bill splitter, a calculator, a quiz) can run right in the answer as it is written, a diagram in Mermaid is drawn and a map shows places and routes, once the user allows maps (D291), and a page can hold a map beside its form, the two in step, in the room's colours and the user's language, with no internet unless Settings allow it, charting with ECharts, its buttons able to send the next message (D289). The language, the theme and light or dark are also in the user's menu, at the foot of the drawer (D150, D153).

**Later:** a bigger brain offered when a task outgrows the current one; "Make this a standing instruction?" when a remembered preference keeps coming back; replies to a shared task, and requests between people's Jeans ([enterprise.md](enterprise.md), D226); the same tasks on a phone, project by project, and the phone as a remote of Jean at work (D227).

## Projects

A project is a self-contained folder with its own files, conversations, instructions, memory, skills, rules and preferred brain. **A project that has been given a name and persona is what other products call an agent.**

| Level | Lifetime | Has its own |
|---|---|---|
| Profile (D228) | Permanent | A whole Jean: settings and keys, a lock, the person's instructions and memory, its projects |
| Jean (the house) | Permanent | Global instructions and memory about the person |
| Project ("Bakery · with Margot") | Permanent | Files, memory, conversations, rules, brain; optionally a name, persona and colour |
| Helper | One task | A temporary sub-session, shown nested in the activity view |

- **Inheritance.** Global instructions and memory apply in every project; each project adds its own on top.
- **Isolation.** A project cannot see another project's memory or files unless the user allows it (default rule: Ask me first). When a lasting fact is detected, a second reflex question decides whether it belongs to the person in general or to this project.
- **Privacy by project.** A "Health" project can be pinned to the on-device brain, which is more reliable than any classifier. Rules can also be set per project, e.g. "Client X: never use the cloud".
- **Small context.** Memory per project stays small, so it fits the on-device brain's context.
- **Easy to move.** Backing up, exporting, sharing, syncing or deleting a project is one folder operation. Collaboration later becomes "invite someone to this project".
- **Meetings** (D224). Asked to hold a meeting, Jean has the assistants of the other projects, or of those named, speak on the topic in rounds, each from its own project's instructions, memory and latest tasks, hearing what the others said; then it says what was decided, what each project will do and what needs the user. The user allows each meeting first, or always for those projects, and a routine holds a regular one. A project kept on this device doesn't hear a brain in the cloud.
- **Its place and its dialog** (D18). The header shows the project the user is in and opens on the others; the address carries it, and its colour tints the light (D78). The home project's name is never translated: the UI calls it by its assistant's. Its dialog shows who the project is first, its light as picked, large, beside its name and the colours; then its assistant, once names are found; then where it is kept, a switch for this device and its folder; Save and Delete at its foot, apart and always in view. What a project is, it says only when making one.
- **Hidden default.** There is always a default project, invisible until the Projects capability is discovered.

## Profiles

A profile is a whole Jean on the device: a personal one and a work one, or one per child (D228). Nothing crosses between them.

- **Unseen until a second.** The person's menu has "Add a profile" at its top; once there are two, it lists them first, the one open marked, a locked one with a lock. Choosing another opens it afresh, its lock first if it has one, and the lock screen lists the others too. Settings › Profiles names this one, opens or removes others, and adds one.
- **An address opens its profile,** whichever was open last in that tab.
- **A child's profile** (D389), set by a parent:
  - The parent locks their own profile first, so the child can't open it, then ticks "For a child", picks the year of birth, reads what they decide and see, and confirms with their password or passkey. Jean asks then whether it may notify them on this device.
  - Under 13, the profile opens only with the parent's password or passkey; from the school year the child turns 13 (4e in France), on its own, or with the child's own lock.
  - Settings › Set by a parent shows the year of birth, each topic's choice (Explain for their age, Talk with us first, Later), Vikidia or Wikipedia, and what is turned off. "Change, with a parent's password or passkey" opens it, and while it is open Brains and Approvals can be changed too, then Done keeps them. Start for free is never offered there, and pictures are checked at the strictest. Whatever it locks says "Set by a parent".
  - Each message the child sends comes with Learn it's steps, as if they had named it, so the brain helps them learn rather than do their work (D394); a parent's and grown-ups' profiles are as they were.
  - The child sees, until they say they read it, that if they write about a danger their parent is told that a concern came up and when, never their words, and not when the danger is at home.
- **The family page** (D424): jean.is/family and /fr/famille tell parents what a child's profile does and what it can't, with the tutor's measurement and never its promise; its button opens Add a profile with For a child ticked.
- **What a parent sees** in their own profile: in Settings › Profiles, each child's time today and over seven days; above the box until "Seen", and as a notification, a concern that came up in a child's profile, its kind and when, with "What you can do"; never what was written (D390).
- **Honest limits:** a parent's settings decide how Jean answers, not what the device allows, which its own parental controls do; a child who opens the browser's developer tools, or clears the site's data, can get round them, as they can open another AI. Intuition reads a danger right a bit more than half the time across languages, so the brain's own reading backs it up.

## Instructions and memory

One section of Settings, **About you** ("What Jean knows about you"), in two parts (D134):

1. **Your instructions** (`instructions.md`). Written by the user, authoritative, always included. They come in three layers: organisation policy (locked), then global, then project.
2. **What Jean noticed** (`memory.md`). Curated by Jean. Every entry links to the conversation it came from and can be edited or deleted.

Once they are on, Settings' Skills lists the skills, each saying where it came from, Jean's own ready-made skills as tiles to read and add, each opening on what it does and that it can be deleted, its steps a click away (D261), everyday ones (a hard document in plain words, a formal letter, a budget, a comparison with a recommendation, calendar events, a quiz, D208; learning, below; who's who in what the user shares, drawn as a map and kept as a spreadsheet, D223) and methods for work (below), both lists by their names in the user's language, as Connections lists services, the sources of skills from elsewhere, by default folders of Anthropic's skills for knowledge work on GitHub, and what they offer (D121, D196, D207), and Routines the routines, with when each runs next (D122).

**Skills that draw** (D196). A skill can say which kinds of block it writes, and while one of the room's skills says so, those blocks are drawn in the answer instead of shown as code: Charts (ECharts) draws bars, lines, pies, heatmaps and more, in the theme's colours with numbers in the user's language; Music scores (ABC notation) draws the score and plays it on real instruments, MuseScore's (D338), each note lit as it sounds; Slides (Marp's Markdown) shows a deck a slide at a time, in the room's look, to page through with buttons or the arrow keys, present full screen and print one slide under another (D200). Each is drawn as the answer writes it. Copy takes both the block's text and its picture, so it pastes as code in an editor and as a picture in a document, and copying the answer brings the pictures along in its formatting. All three are in Jean's own directory, tiles in Settings › Skills. None needs adding by hand: asked for sheet music, a chart, a deck or anything else one of Jean's own does, the assistant reads the one that fits, which comes into the user's skills as it does, finding Skills if it wasn't, and a toast says so (D401, D406). Deleting the skill turns its blocks back into code. A file opens drawn the same way, beside the conversation or in the browser, while its skill is there: a tune the assistant saved as `.abc`, a deck as Marp's Markdown, a chart or a tune in a Markdown file; a diagram or a map always, as `.mmd`, `.geojson` or in Markdown (D432). A shared task brought in with Continue in Jean adds the ones its answers draw, and the toast says which, so that someone who never found charts sees the chart they were sent (D378). The directory's PowerPoint skill draws nothing in answers: it makes a deck as a `.pptx` on the computer, with its charts and tables PowerPoint's own, shown beside the conversation slide by slide (D201).

**Methods** (D225). Six ready-made skills hold the methods people at work recognise, one for each kind of work: Project plan (the critical path, ranges as PERT gives them, phases with a sign-off, or short cycles with a board), Goals and strategy (OKR, Hoshin Kanri, or a plan from analysis to control), Problem solving (8D, A3, DMAIC, PDCA, a root cause analysis for an incident that is over, or 5 Whys alone for a small problem), Improve a process (Kaizen, the bottleneck first as the Theory of Constraints has it, or a redesign), What could go wrong (FMEA or a pre-mortem) and Design something new, with the people it is for (the double diamond with design thinking's practices, or DMADV). Each picks the method the situation calls for, keeps to the one the room's instructions name, and asks with `ask_user`, recommending one, when it isn't clear. Their practices are rewritten from DEVS's 38 methodologies, as ideas and never files (D38): facts and numbers before causes or plans, nothing blamed on a person, at least three options weighed in a comparison with the pick starred, actions with an owner, a date and a measure, a check before answering, charts where numbers say more (a Pareto, a Gantt, a risk heatmap), the document the method makes as Word or Excel, and a routine for the check-ins.

**Learning** (D394). Three ready-made skills help someone learn, often a child, and never do the work that is theirs. Learn it (Apprendre sa leçon) starts from what the child sent: their own answer is right or not yet, never corrected for them; a question to understand is answered; their work gets one rung of help at a time (a question, the rule, an example with other numbers, then a note for the teacher), never its answer; and a lesson is found at their level without marks, explained from their own book, made theirs (a summary written with the book closed, gap-fill pages whose answers are never in the page, cards over days) and counted known once they explain it in writing. Flash cards (Fiches) keep Leitner's five boxes, reviewed every 1, 2, 4, 8 and 16 days, in a CSV that Anki imports, as Quiz me's cards now are. Study plan turns each weekday's minutes, the term, the subjects and the tests into today's session, with a routine for it, and drops missed days rather than piling them up. All three keep to the same rules: no marks, percentages or streaks, praise for the strategy and the effort, and "too hard" always works. `npm run tutor` measures how often brains give the answer anyway ([architecture.md](architecture.md#skills-and-routines)).

**Memory that switches itself on:**

- **Detecting.** Before memory is on, a reflex question asks whether the message states a lasting fact, preference or correction, and offers memory when it does; the brain can offer it too (D79, D84).
- **Writing.** Once memory is on, the brain has a `remember(text, scope)` tool in every new conversation, with one rule: remember only what will still matter later. It writes one line in the user's language, about the person or about the current project, and a toast shows "Remembered: … · Undo".
- **Opting in.** The first time, it is an offer. Once accepted, memory runs automatically. It can be switched off in About you. Private conversations come later.
- **Reading back.**
  - The newest lines of `memory.md` that fit in about 1,000 tokens go into the prompt, the same for every brain.
  - Later: past that, Jean occasionally consolidates it, keeping the previous version for undo, and the reflex model selects the relevant lines.
  - `recall(query)` searches past conversations with the same engine as documents.
- **Transparency.** Memory is a local file. With a cloud brain it is sent as context, and About you says so plainly.

## Rules and approvals

Every kind of action has one of three settings: **Do it / Ask me first / Never**.

| Defaults | |
|---|---|
| Reading and writing Jean's own files | Do it |
| Changing files in the user's own folder (D152) | Ask me first, with the change shown; "Always allow" holds for that folder only |
| Sending, sharing, deleting, anything external | Ask me first |
| Making a film, which costs far more than a picture (D251) | Ask me first; "Always allow" holds for films only, until Settings › Brains asks first again |
| Starting a long task on a plan, once plans are found (D364) | Ask me first: the plan waits for Go ahead |
| Passwords, payments | Never (reserved for humans) |

- **Automatic review** (later): a reflex question checks consequential actions against the user's instructions.
- **Setting rules from approvals.** On an approval card, "Always allow" writes a "Do it" rule and "Never allow" writes a "Never" rule.
- **Overrides.** Projects can override rules, and organisation policy can lock them.
- **Rules for one kind of action or one service** (D295): under the rules, a line adds one: Ask me first or Never, for a kind of action or a connected service, and if the user likes only when the answer to their own question about it is yes ("Is it to a client?"). They only ever make Jean more careful; an organisation's come first, locked.

## What Jean is doing

A live, inspectable activity view built from standard ACP events:

- **The plan** (D364): for a task of three steps or more, its steps above the activity, each with its status, ticked off as they are done. The first waits at the top of the box for Go ahead, and the user's own words there change it. A confirmed plan carries the task on while it moves; a task that runs out of steps pauses there instead, with how far it got and what it cost so far, and Keep going.
- **Each action:** a plain-language label, the files it touched (clickable), its status, and, one click down, what it was given and what came back (D103).
- **Approval cards.**
- **Pause and stop,** and **Answer now** while a brain thinks at length with nothing written yet; on this computer, Jean does it itself when the thinking runs on (D414).
- **Steering** (D365): what the user writes in the box while Jean works is read before its next step, as in Cowork, the work going on; until then it waits under the answer, and can be taken back.

Jean's "computer" is the user's own browser, so the view can show everything: files read, code run, sources used, files made.

- **Decision inbox** (D99). During long tasks or work by helpers, approvals queue as cards under the answer being written, each saying which part it is for, answered in any order while the work goes on.
- **Questions** (D146). When Jean needs the user's choices before it can do a task well, it asks them all at once, at the top of the box, as part of it, one question at a time, small enough for a phone held sideways: a few answers to pick from, the one it recommends picked already and marked, and room for the user's own words, which can also be written in the box itself, where they answer the question on screen. Skip leaves a question unanswered, Back returns to the one before, and the last one sends the answers back. Helpers ask the same way, saying which part it is for, each set after the one before. Like the inbox, it is always there.
- **Since last time** (D101). On opening after time away, a read-only pass over the connected services produces a short brief. Jean cannot work while the tab is closed, and says so.
- **Routines** (D122). Requests Jean sends itself on a schedule, or once later ("remind me Thursday morning"), each in a conversation of its own that opens with the routine's name, under the same rules as any. They run while the tab is open, when they fall due: in the user's place when they aren't there, and otherwise out of sight, the routine's name lit in the task list, so nothing the user is doing is interrupted (D317); one that fell due while it was closed runs at the next visit, once. A routine's runs are one row in the task list, the latest, with a count that unfolds the earlier ones under it by date; Settings › Routines lists them too, opened from a run's first line. A run starts from the one before, as it went, so a daily summary can say what changed since; Jean reads the earlier ones when asked ("what did Monday's summary say?"). A routine answers with the brain the user's messages have, unless one is picked for it in Settings › Routines: Auto, or one of those the picker offers (D303). Each has a switch there, on when it is made: off, it runs only with Run now, and back on it makes up none of the times it fell due meanwhile (D430).
- **Flows** (D218). A flow is the steps of a task, drawn on a canvas: a text, a file, instructions for Jean or one of its tools, each taking the results of the steps wired to it. Jean draws one when asked, or from a task it just did; the user moves, wires and changes its steps, runs it, and schedules it as a routine. Running, its steps light up one by one, under the same rules as any task, and what its last steps say is the answer. A step can go through a list, an item at a time, and one that gives nothing stops what follows. On a new task, + in the box puts the main area in flow mode, on the room's flows; on a task, a button beside the terminal's and the browser's shows the task the same way beside it, each request, step and call with what it is doing, waiting for, or became, a card leading to its line in the conversation, and the flows it made or ran.
- **Explanations for Auto.** Auto mode explains its choices in collapsed "thinking" entries ("Chose the on-device brain: personal content").

## / and @ in the box

Typed at the start of a word, / and @ open a menu above the box that narrows as the user types on (D199):

- **/** names what Jean uses for the message: one of the project's skills or connections, or something Jean can do (Web search, Computer, Documents and spreadsheets…). Once Skills or Connections is found, it also finds what isn't there yet: a ready-made skill, read before it is added, and a service Jean knows, connected in a click.
- **@** points at what Jean reads: a file or folder of the conversation's folder, a document the project keeps, opened beside the conversation (D488), a file shared or made in the project, attached again, or one of the project's earlier tasks.

What is picked stays in the message as words ("/chart", "@Budget 2026"), and Jean is told what each one names.

Once Skills or Connections is found, + in the box has a row for each, which opens a menu beside it on hover or when pressed (D292): the project's skills, by name, or its connections. One picked goes in the message as / would put it, and the menu's last line adds another, in Settings. Once Web search is found, + also has a switch for it (D304). Once pages in answers are on, + also has Visual answers, a mode (D300): picked, it shows pressed at the foot of the box, and each message asks for maps, diagrams, timelines and checklists where they help, as the ready-made skill of that name does, until it is pressed again.

## Brains: picker and Auto

**The first brain** (D329). The first message, or the chip, while there is no brain, shows "One step before I answer" in the page, under the box, which keeps the request and the files it shares, where the ideas were (D366): Start for free, a free account on OpenRouter's site, then back to the request, answered; where this computer can run a private brain, a box beside it gets that one too, downloaded in the background while OpenRouter answers, Auto then having both. Two doors lead on: "I already use ChatGPT, Claude or Copilot", to the plans, keys and local servers of Settings › Brains, and "I'd rather choose", to what matters most (my words staying on this computer, starting right away, or the best answers), whose button says what each does, and where a device that can't run the private brain says so. A line says Jean has no tie to OpenRouter nor to any other service there.

A chip in the message box, beside its send button, reads **Auto ▾**, or the name of the brain picked by hand (its provider is in the picker). It opens a menu above it, each choice on one line, an icon and a name, and the one answering ticked:

- **Auto** (recommended)
- **On this device:** private, free, works offline
- **Fast / Smart / Best,** taken from the connected provider. Each shows the real model name and a plain cost ("about 1¢ per answer") on hover, using prices from the provider's catalogue (OpenRouter `/models`), or models.dev's, read only when a price is wanted and kept a week (D255); a plan's say "in your Claude plan", "in your Copilot plan" or "in your ChatGPT plan" instead (D235 · D262).
- **All brains**
- **Keep on this device,** an explicit switch, while a brain is in the cloud. While it is on, the picker offers no brain in the cloud, and one picked by hand gives way to Auto. In a project kept on this device, it is on and can't be turned off, and says why (D307)

Organisation policy can hide or lock any of these.

**At work** (D385), the organisation's policy names its own brains, behind its AI gateway, and its sign-in. The first visit goes to the organisation's sign-in page, which sends the person straight back when they are signed in already, and the first answer comes from the gateway, with no step before it. Settings › Brains says who is signed in, with Sign out. When the sign-in ends, a toast asks to sign in again, keeping what was typed.

The picker offers the brains of the project the user is in. A brain is used in every project, or only in those ticked under it in Settings › Brains, so a key a client pays for answers for that client only (D194).

**How Auto decides** (reflex questions, asked locally, per request):

| Question | Effect |
|---|---|
| How demanding is this? (chat → reading → multi-step → expert) | Use the cheapest brain that can do it |
| Does it involve personal, health, financial or confidential information? | Prefer the on-device brain when one is installed |
| Does it need the web or image input? | Only brains that support it |
| Is the user unhappy with the last answer? | Step up a level |
| Is the browser offline? | The on-device brain, when one is installed (D269) |

- **Stable choices.** Auto steps up when needed and never steps down within a conversation; a new conversation starts again from the bottom. This keeps the provider's cache warm and the tool-call format consistent.
- **Without Intuition,** Auto picks the Smart level (D70).
- **How much it thinks** (D414). Auto asks each brain to think as much as the request demands, more when the user seems unhappy, never less within a conversation. Once the user has asked for an answer now, Settings › Brains lets each brain keep its own: Auto, Quick, Balanced or Thorough.
- **Visible.** Every answer shows where it came from ("answered on this device"), with a one-tap "Ask a smarter brain".
- **Private · offline, shown** (D270). While the next message can only be answered by the brain in this browser tab, the box is sealed: its border and its chip's take the theme's accent, and a legend in its bottom row, beside its tools, says **Private · offline** (**Offline · still answering** while the browser is offline); a narrow screen shows its shield alone. The legend opens a card above the box that says what that means and why it is rare: everything stays on this device, written in this tab with no server and nothing to install; private, free and answering without the internet; "Turn off Wi-Fi and see"; the shield under each answer as the proof. The card opens by itself once, as the brain's download ends.
- **About this answer** (D252). Among an answer's buttons, one, a shield when the answer was done on this device, shows on hover or keyboard focus (a click or a tap keeps it) how long the answer took, what it cost (free on this device, about what the provider's prices say in the cloud, in your Claude, Copilot or ChatGPT plan when one of those answered, or not known), which brains answered and who made its pictures and films, each by name, one on this device too (D264), with the address each was given the conversation at, and apart from them the other addresses outside this device the page reached meanwhile, as the browser itself recorded them. It says first where the answer was done: on this device, in the cloud (the conversation was sent there), or sent outside this device when a brain here still reached addresses outside. *Kept private* is said only when all of these agree. Its certificate, folded under *Certificate* at the card's foot, saves as a file in standard forms that says how the answer was made and holds salted fingerprints of its words and files, never the words, sealed with a key the device never gives out, so it can go to whoever needs to see it; its proof adds the request and the answer, for those who may read them (D274). Settings › Approvals shows the device's seal, whose fingerprint whoever relies on its certificates can check, or agree on beforehand, and beside it who dates certificates, the public log, and the country of each brain in the cloud, which certificates name, each as the organisation set it where it did. ## Files and outputs

- **Dropped files are kept** in the project's library. Each file is stored as the original, an extracted text version and a metadata file; files are named by content hash, so duplicates are stored once. Conversations reference files rather than copying them.
- **Or left where they are** (D141, D149). A project or a conversation opened on a folder works on that folder's files in place, and each keeps its own: two projects, or two conversations, work in two different folders, and a new conversation starts on its project's. Nothing is copied, and a change Jean makes is in the folder as soon as the user has seen and allowed it.
- **Pictures and the screen.** A picture is shared like any file, and the box's + menu captures the screen, a window or a tab: one frame, shown as a thumbnail before it is sent. Sent, a picture shows itself in the request, where any other file is a chip, and opens whole. Brains that can see are shown it, and the pages of a scanned PDF too (D105 · D479).
- **Seen without leaving Jean** (D126). A file Jean made, or one the user shared, opens in a preview beside the conversation (over it on a phone), as what it is: a picture, a film or a sound (a MIDI file too, played by Jean's own synthesizer, D197), a PDF's pages, a Word document's pages, a workbook with its sheets' tabs (a CSV too, whether commas, semicolons or tabs split it, or an .xls that is only text, as exports often are) whose cells can be changed there, in the version on show, its totals worked out again, which Jean hears of (D229), a deck's slides, each as Office draws them (D183), a web page with its own look and, by default, its own scripts, without the internet, able to fill the screen and save a file it made (D143, D158; five switches in Approvals change what a page may do). A file being changed shows its new version as it comes, so the next request can be made while looking at it.
- **Outputs fit office life without any dependency** (D119): Word documents and Excel spreadsheets Jean writes, each change a new version (D164), their formulas written with symbols, since Office reads no LaTeX (D185); an answer copied as rich text, which pastes formatted into Word, Outlook and Google Docs; a table as CSV.

## Sources and citations

- **Numbered sources.** Every tool that brings in outside content returns numbered sources (file and page, URL and title, memory item, past conversation). The brain cites them as `[n]`, and the UI shows each as a chip: hovering a web page's chip shows its site's icon, its domain and the page's title (D210), and clicking opens the file or the URL.
- **Citations that say where** (D481). The brain cites a passage of a file by its exact words, `[n: "…"]`; hovering its chip shows them, and clicking opens the file there: a PDF at its page, the rest dimmed and the words outlined; a Word document or a deck with the words lit by its viewer; a text with them lit. Words the file doesn't hold open it at the top and say so. A picture's area (`[n: x,y,w,h]`, in percent) is drawn the same way, once brains are measured at it.
- **One format for all providers** (D90). Shared files, a connection's emails and documents, Wikipedia's pages and the brain's own search share one numbering per conversation. A web page's chip opens it in a new tab, or beside the conversation once the browser is on; an email's shows its title. Each answer lists its sources under "Sources".
- **Honest even with small brains.** Small on-device brains cite unreliably, so a "What Jean read" list is always built from the actual tool calls.
- **Double-check** (D100). Each sentence that cites a source (12 at most) is checked against that source's words by the brain that wrote the answer, in one short request outside the conversation; the reflex model was not up to it. The verdicts show under the answer: what matches, what the source doesn't say or contradicts, and a follow-up to correct it. A sentence whose quoted words its source doesn't hold is not in it, without asking (D481).

## Web search

There is no Jean server, so search comes from something the user or their organisation already has:

1. The connected cloud brain's own search, with its sources (Anthropic and OpenRouter, which search only when a question needs it; OpenAI and Gemini later), while Wikipedia is the one source on.
2. The sources built into Jean, each a switch in Settings › Web search (D271), for everyone else, the on-device brain included: Wikipedia, in the user's language, on from the start: free, callable from a browser, in 300+ languages (Wikidata later); Vikidia, the encyclopedia for 8 to 13 year olds, in fifteen languages, a click away; and an offline library, a Kiwix server on the user's computer, a school's hotspot or a company's network, which can also stand for Wikipedia (D254). With another one on, every brain searches what was chosen, its own search set aside. An organisation can choose them: Vikidia alone, for a school.
3. A search service connected like any other (D192): Exa, which needs no key and no sign-in, is among the services Jean knows, and an organisation can add its own. Settings › Web search lists the connections that search the web, found from what their own tools say, and offers those Jean knows, a click away (D271).

Once found, web search has a switch in + in the box (D304). Off, Jean searches nowhere in tasks started meanwhile, and a task under way is told not to; on again, it searches when a question needs it.

When no route exists, Jean says so and suggests connecting a cloud brain. A shared community proxy should only be considered if real demand appears; DEVS's `proxy.devs.new` is the warning.

## Browser

Once it is found (D140), pages open in a pane beside the conversation, or over it on a phone, so the user can look while they talk:

- **What it has:** back, forward and reload; an address field that takes an address, a site's name or words to look up (Wikipedia's search by default, set by the user or the organisation); a new tab; full screen; and a button in the header that opens and closes it, as ⌘⇧B does (D142). Escape closes it too, unless the page has the keyboard: a site's keys never reach Jean; while an answer is being written, Escape stops it first, leaving the page it reached (D315).
- **What opens there:** links from answers, their sources included, and pages Jean opens with `browse`. Jean asks first, since an address it picks could carry something away, and reads the page's words when the site allows it.
- **What Jean knows:** which page is open, by its address. It can't see the page itself, nor where it went once the user follows a link in it.
- **Sites that won't show.** Many sites refuse to be shown inside another page, and many accounts only work in their own site's tab. The browser can't tell, so a page from a site not seen working yet comes with "Page not showing?" and a new tab; a site Jean knows refuses, Vikidia's (D271), opens in a new tab at once. A site opened that way opens in a tab of its own from then on, and Jean recommends installing it as an app, which gives it its own window and a place on the desktop, with the steps for the browser in use. Where the browser can't install sites (Firefox on a computer), Jean suggests a bookmark. "Try here again" undoes it.
- **The conversation's folder** (D156). Its pages show there as a site's would, with their styles, pictures and scripts, and their links lead to its other pages. Typing the folder's name, or "Show" and its name when nothing is open, shows its `index.html`, or what it holds. Any other file shows as it does when opened beside the conversation: a picture, a film or a sound (a MIDI file too), a PDF's pages, a Word, Excel or PowerPoint file or a table as Office draws it (a workbook's cells change there, in the file itself, D229), Markdown laid out, and a file of a kind Jean doesn't know as its text, unless it isn't text (D190, D197). A page Jean makes or changes in the folder opens by itself (the first time, Jean offers the browser), and the page on show comes again whenever one of its files changes, in Jean's hands or the user's own editor.
- **Beside a file.** A file opened while a page shows doesn't cover it: the two share the side of the window, one above the other (side by side on a phone held sideways), and closing one gives the other its room. Dragging the line between them shares it differently, and dragging the side's edge makes it wider or narrower; the arrow keys do it too, a double click puts it back, and Jean remembers (D144).
- **Where it was** (D220). Reloading, going back to a task, or a link to it shows it with what was open beside it, in the same order: a file, the browser on the page it opened, the terminal, Flows. The keys stay where they were.

## Reply suggestions

- **Actions from a translated catalogue** (D69):
  - "Shorter" when the answer is over 220 words. That is a length, so it works in every language, with or without Intuition.

What draws it comes from the internet as it opens, Jean's own files, each checked; without it, the page still shows every request and answer as they were written. The files it made and was given are in the page too (D470): its pictures show either way, and each other file opens under its name as Jean's preview shows it, a PDF's pages, a Word document, a workbook or a deck as Office draws it, a web page working.
- **Tips.** An icon button's name, or what a title adds (a time's full date), shows above it as a cited source's does, once the pointer rests on it or the keyboard reaches it, never the browser's own tooltip (D233).
- **The first screen** (D366). Where it all fits a wide window, the box sits under the question until a task starts, then slides to the foot; on a phone, or where it doesn't fit, it stays at the foot. Before any task, in a browser's tab, a sentence says what Jean does ("Bring your files and questions. Get back answers, documents and charts, right in this tab.") and three facts what it is: nothing to install, kept on this device, free and open source; not in the desktop app or an installed one, where the first would be wrong. Where your files go · Privacy · Terms sit at the window's foot (D356, D381).
- **Ideas on the first screen** help non-technical users begin, under the box, or above it on a phone: first "Try a sample spreadsheet", which shares a year's sales of four products with a request to chart which grew the most, so files in and files out are tried in one click; then "Compose a tune" and "Make a quiz", which add Jean's own Music score and Quiz skills before their requests, so the tune is written as a score that plays and the quiz is asked on cards; and "Savings plan", which has the computer work a plan out with one script and draw it as a page that opens beside the conversation (D163). Their requests are short and plain, so that the brain on this device understands them too.
- **Suggestions double as discovery.** A "Chart this" button is how the computer gets discovered.

## Settings and the drawer

**Settings** (D113) is a menu beside the section open, in three groups, each list a rounded group of rows: General, Brains, Appearance, Keyboard shortcuts; About you, then Skills, Routines, Connections, Web search, Computer and Apps once found, then Capabilities; Approvals, Your data. The middle group goes from the person outwards: what Jean knows of them and has learned from them (About you, Skills, Routines, one module), then what it reaches and runs (their services, the web, a computer, others' code), the most used first, and as the case of trophies finds them, so a section found later mostly joins below the ones already known.

- **Brains** is one group, one choice of who answers: Auto, then each brain with where it runs and its version, a button opening the rest (its version to change, the projects it is used in, Remove); Keep on this device at its foot; Add a brain at its top, which shows the ways to add one, one open at a time, until Settings closes; before any brain, the ways are the page. The pictures this device makes come after it, their check's switches folded under What else is refused, which most never change (D331).
- **Capabilities** is a case of trophies made of Settings' own parts, so it reads as the sections around it: the wave and how many are found, over a bar of it, as Storage's, then a row per capability in the case's order, its icon lit and On at its end once found, a dashed silhouette until then with how to find it under its name, a dark one with Off once turned off; the row open, at first the next to find, says what it does and turns it on, downloads it or opens it, and once found turns it off.

**The drawer** (after Manus): New task, which brings the keyboard to the box, a row per place found (Skills, Routines, Connections), in Settings' order, the tasks under their heading, those the user pinned under Pinned above them, and the user at its foot, by name (D150), whose menu holds Settings, the language and the theme (as thumbnails; the menu stays open while they change), dark mode and what Jean can do. The UI calls a conversation a task.

- **A task's ⋮ menu** holds Pin (or Unpin), Rename, Mark as unread (or read), Save a copy (D305) and Delete, the only one in red. Its button takes no room until the pointer is on the task, so its title shows whole; Tab stops once per task, ↑ ↓, Home and End go from task to task, ← → along it to its ⋮ button. Renaming puts a box in the task's place, a double click too; Enter or leaving it names the task, Escape doesn't.
- **Unread:** an answer that comes while its task isn't on screen marks it unread, and opening it reads it; an unread task has a still light where a running one's pulses. Each is a `meta` record in the conversation (`title`, `pinned`, `unread`), the latest winning, and none moves a task among the others: its place is when something was last said or done in it. A pin and a name are kept when the user goes back to a request; a routine's runs are neither pinned nor renamed, as the next run takes the row and the routine's name.
- **Beside the conversation:** on a window at least 48rem wide the drawer stays open beside the conversation or is put away, as the user left it on that device (`app.sidebar`); until then, Mail and Human open it once the room has a task, and leave it put away while there is none (D369): a first visit has the welcome to itself rather than a column saying tasks will appear there, the drawer's button staying in the header for the user's menu at its foot, and the drawer comes in with the first request, as its question turns into the task's title. Opened or put away, it slides from the start edge, a view transition in which the conversation and the box move over as they will be (D234). It scrolls without a bar of its own, the user staying in view at its foot, and while more tasks lie above or below, they fade out at its top or above the user (D348); and the page stops at its edges, without the bounce that showed what lay beyond. Nothing in it can be selected, its header with it, as an app's own sidebar: a drag there selected task names.

## Keyboard shortcuts

As in the Claude apps (D118), Ctrl outside Apple's systems: ⌘, Settings; ⌘/ its keyboard shortcuts, with Shift too since many keyboards need it for "/"; ⌘⇧O a new task (ChatGPT's key), shown everywhere, since a browser tab keeps ⌘N for a new window, and ⌘N too where the page gets it (an installed Jean, Firefox); ⌘⇧D light or dark (D130); ⌘⇧E the next theme, in the gallery's order, its name shown; ⌘⇧L the next language, in the menu's order, the browser's first, its name shown in its own words, unless the organisation sets it; ⌘⇧S dictation, ⌘K search (D133), ⌘⇧B the browser (D142) and ⌘⇧H talking hands-free, once each is found; ⌘J the terminal (D166) and ⌘B the drawer (D234), as in code editors (a dialog over the room closes, and the drawer shows); ⌘S a copy of the open task, as a web page, and ⌘⌫ deleting it, as in Mail, after asking, from an empty box or no box at all and with no dialog over it (Ctrl+Delete elsewhere), both shown beside their actions in the open task's ⋮ menu (D313), as is ⌘⇧U, which shares it once sharing is found, opening the dialog that asks how before anything leaves (D377). Escape stops the answer being written, as Stop does and as Esc interrupts Claude Code, once nothing else takes it: a dialog or a menu, the box's / and @ menu, a pane with the keyboard, a field of its own (a request being edited, a task being renamed), and before the browser's pane closes, so a stopped answer leaves the page it reached on screen (D315).

- **How keys are read:** from `event.key`, or from where the key sits on another alphabet, never while an IME composes, and announced with `aria-keyshortcuts`. ⌘B is the page's, not Firefox's bookmarks, ⌘S not the browser's Save As, which would keep Jean's own page, and so are the ⌘⇧ keys a browser has a use for (⌘⇧D, ⌘⇧S, ⌘⇧H, ⌘⇧U) while its tab has the keyboard; nothing Jean lets the user type is bold.
- **Settings › Keyboard shortcuts** lists them, to read, in groups, the most used first, each under a name the user already knows: Tasks (New task, Search, then Save a copy and Delete, in their ⋮ menu's words, with Sharing between them), Your message (the box's own: Enter sends, Escape stops, Shift+Enter starts a line, ↑ and ↓ bring back earlier requests from an empty box, Enter on a request selected edits it (D312), then dictation and hands-free), then the rest under the section of Settings where each is set, General (the drawer, the browser, the terminal, Settings, its shortcuts, the next language, and Escape, which closes) and Appearance (light or dark, the next theme). A capability's shortcut comes once it is found, and the section isn't offered where the pointer is a finger.

## Voice

| Need | Default (private) | Option |
|---|---|---|
| Dictation (speech to text) | A model in the page: Whistle in English, German, French, Spanish, Italian and Dutch, Whisper base through Transformers.js in the other languages (D205) | Chrome's on-device recognition (`processLocally: true`) where available; cloud speech-to-text from the connected provider |
| Read-aloud (text to speech) | `speechSynthesis` with operating-system voices, using only voices where `localService` is true, in the answer's own language (D109), by the most natural voice there for it; when none speaks it, Jean says so (D114) | A natural voice on this device, Kyutai's Pocket TTS, in English, French, German, Spanish, Italian and Portuguese (D455); cloud text-to-speech |
| Live conversation | A chain: Silero voice detection → speech-to-text → brain (streamed) → speech, sentence by sentence, in read-aloud's voice (the natural voice where it is on); speaking over Jean interrupts it. Works with any brain. | Real-time speech models from the connected provider (OpenAI Realtime over WebRTC with the user's key, Gemini Live) |

Dictation and read-aloud are always there, for accessibility. Live conversation is discovered after three dictations (D93); once on, it starts from the box's button while the box is empty, and its state shows in the box (D123), where what the user says is written as they say it, and sent once they stop, the button ending live conversation all the while (D374). The natural voice is discovered after three answers read aloud in one of its languages (D455): about 108 MB for that language, once, then about 97 MB for each other one, offered when an answer in it is first read; Settings › General turns it off. The providers' speech services are an option for later.

## Languages

- **Coverage.** 33 locales at launch. They cover Arabic, Hebrew, Persian and Urdu (right-to-left), Chinese, Japanese and Korean, the major Indic and Southeast Asian languages, and Swahili, Hausa, Yoruba and Amharic. Translations are machine-made, with no per-language review (D44).
- **Instant switching.** The language changes immediately, with no reload, including in past conversations (activity labels are rendered from structured data).
- **Conversations.** Jean replies in the language of the user's last message, and otherwise in the UI language.

## In an editor

People at home in a code editor can have Jean there, through `npx jean-cli acp` in any editor that speaks ACP, such as Zed (D241). It is the same Jean: the projects, memory, skills and conversations of the folder Sync keeps, so a conversation started in the editor shows in the drawer after the next round. It works on the editor's folder where it is: each change shows as the editor's own diff, approved first, and each command runs in the editor's terminal once the user agrees. The brain is the one whose key the editor's environment holds, or the user's own Claude Code with their Claude plan; their Copilot or ChatGPT plan when named. `npx jean-cli gateway` runs the gateway for whoever serves Jean.

## Deliberately out of scope

- An always-on cloud computer, and working while the user is away
- Controlling the user's computer outside the browser
- A proprietary app catalogue (Jean uses MCP)
- Persona-heavy prompts, and assistants that work among themselves without the user
- Built-in browser models (`LanguageModel`), and native code beyond the window the desktop version opens and Sync's folder (D155, D169), for now
